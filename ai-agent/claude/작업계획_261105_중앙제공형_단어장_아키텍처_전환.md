## 1. 배경 및 전환 목적

### 1.1 기존 구조의 한계
* **사용자 의존적 콘텐츠**: 사용자가 직접 단어장을 생성하고 CSV를 가공해 업로드해야 학습이 가능하여 온보딩 허들이 높음.
* **데이터 중복 및 비표준화**: 서로 다른 사용자가 같은 영단어를 각자의 단어장에 중복 등록하며, 오타나 불완전한 예문이 정제되지 않음.
* **복잡한 CRUD 유지보수**: 대량 단어 파싱, CSV 인코딩(UTF-8/CP949) 예외 처리, 개별 편집/삭제 트랜잭션 등 비핵심 관리 비용 과다.

### 1.2 전환 목표
1. **표준 단어장 풀(Standard Vocabularies) 구축**: 서비스가 검증된 품질의 단어(예문, 품사, 발음기호, 난이도)를 중앙에서 일괄 제공.
2. **콘텐츠와 학습 상태의 완전 분리**: 단어 데이터는 읽기 전용(Immutable)으로 두고, 사용자는 단어장 구독 및 개인 학습 이력(`study_logs`, `bookmarks`)만 소유.
3. **학습 진입 단순화**: 회원가입/로그인 즉시 기본 단어장이 활성화되어 단 1회의 클릭으로 학습 세션에 진입.

## 2. 데이터베이스 스키마 재설계 (Alembic 마이그레이션)

### 2.1 ERD 개념도

```text
[시스템 표준 단어 풀]                   [사용자 개인 상태]
+----------------------+               +---------------------------+
| system_vocabularies  |               | users                     |
|----------------------|               |---------------------------|
| id (PK)              |               | id (PK), nickname, ...    |
| title, category      |               | active_vocabulary_id (FK) |
| level, total_words   |               +---------------------------+
+----------+-----------+                             │
           │ 1:N                                     │
           ▼                                         │
+----------------------+                             │
| system_words         |                             │
|----------------------|                             │
| id (PK)              |                             │
| vocabulary_id (FK)   |                             ▼
| word, meaning        |               +---------------------------+
| phonetic, part_of_sp | 1:N           | user_word_progress        |
| example_en, ko       +──────────────>|---------------------------|
| difficulty_level     |               | id (PK)                   |
+----------------------+               | user_id (FK)              |
                                       | word_id (FK)              |
                                       | review_count, wrong_count |
                                       | last_studied_at, mastery  |
                                       +---------------------------+
```

### 2.2 테이블 상세 명세

#### (1) `system_vocabularies` (표준 단어장 카탈로그)
* `id`: `INT AUTO_INCREMENT PRIMARY KEY`
* `title`: `VARCHAR(100) NOT NULL` (예: "초등 필수 800", "중고등 기본 1,000제")
* `category`: `VARCHAR(50) NOT NULL` (`ELEMENTARY`, `SECONDARY`, `CSAT`, `TOEIC`, `CONVERSATION`)
* `level`: `INT NOT NULL DEFAULT 1` (난이도 레벨 1~5)
* `description`: `VARCHAR(255)`
* `total_words`: `INT NOT NULL DEFAULT 0`
* `created_at`: `DATETIME DEFAULT CURRENT_TIMESTAMP`

#### (2) `system_words` (표준 단어 - 읽기 전용)
* `id`: `INT AUTO_INCREMENT PRIMARY KEY`
* `vocabulary_id`: `INT NOT NULL, FOREIGN KEY REFERENCES system_vocabularies(id) ON DELETE CASCADE`
* `word`: `VARCHAR(100) NOT NULL`
* `meaning`: `VARCHAR(255) NOT NULL`
* `phonetic`: `VARCHAR(100) NULL` (발음기호)
* `part_of_speech`: `VARCHAR(20) NULL` (품사: n, v, adj, adv 등)
* `example_sentence`: `TEXT NOT NULL` (빈칸 퀴즈 대상 문장)
* `example_translation`: `TEXT NOT NULL`
* `order_index`: `INT NOT NULL DEFAULT 0` (단어 노출 순서)
* **인덱스**: `INDEX idx_vocab_order (vocabulary_id, order_index)`

#### (3) `users` 테이블 수정
* `active_vocabulary_id`: `INT NULL, FOREIGN KEY REFERENCES system_vocabularies(id) ON DELETE SET NULL`
  * 사용자가 현재 대시보드/홈에서 집중 학습 중인 단어장 ID.

#### (4) `user_word_progress` (사용자별 단어 숙련도 요약 - #3 방식 B 전환 선행)
기존에 `study_logs`를 매번 full-scan하던 방식에서 단어별 요약 테이블을 신설하여 세션 출제 속도 최적화.
* `id`: `INT AUTO_INCREMENT PRIMARY KEY`
* `user_id`: `INT NOT NULL, FOREIGN KEY REFERENCES users(id) ON DELETE CASCADE`
* `word_id`: `INT NOT NULL, FOREIGN KEY REFERENCES system_words(id) ON DELETE CASCADE`
* `correct_count`: `INT DEFAULT 0`
* `wrong_count`: `INT DEFAULT 0`
* `is_memorized`: `BOOLEAN DEFAULT FALSE` (숙련 판정)
* `last_result`: `ENUM('CORRECT', 'WRONG') NULL`
* `last_studied_at`: `DATETIME NULL`
* **유니크 제약**: `UNIQUE KEY uq_user_word (user_id, word_id)`

## 3. 백엔드 서비스 및 API 변경 규격

### 3.1 레거시 API 제거 (Deprecation List)
다음 API는 라우터에서 제거하거나 410 Gone / 403 Forbidden 처리합니다.
* `POST /api/vocabularies` (개인 단어장 생성)
* `DELETE /api/vocabularies/{id}` (단어장 삭제)
* `POST /api/vocabularies/{id}/words` (개별 단어 추가)
* `POST /api/vocabularies/{id}/words/bulk` (CSV 일괄 업로드)
* `PUT /api/words/{id}`, `DELETE /api/words/{id}` (단어 수정/삭제)

### 3.2 신규 표준 API 명세

#### 1) 표준 단어장 카탈로그 조회
* **엔드포인트**: `GET /api/system-vocabularies`
* **인증**: 불필요 (비회원 미리보기 지원) 또는 세션 쿠키
* **응답 규격 (200 OK)**:
```json
[
  {
    "id": 1,
    "title": "초등 필수 영단어 800",
    "category": "ELEMENTARY",
    "level": 1,
    "description": "기초 파닉스를 마친 학습자를 위한 필수 어휘",
    "total_words": 800,
    "user_progress": {
      "studied_words": 800,
      "progress_rate": 100.0,
      "is_active": false
    }
  },
  {
    "id": 2,
    "title": "중고등 기본 1,000제",
    "category": "SECONDARY",
    "level": 2,
    "description": "교과서 및 모의고사 빈출 기본 어휘",
    "total_words": 1000,
    "user_progress": {
      "studied_words": 520,
      "progress_rate": 52.0,
      "is_active": true
    }
  }
]
```

#### 2) 활성 학습 단어장 변경
* **엔드포인트**: `POST /api/users/me/active-vocabulary`
* **요청 바디**:
```json
{
  "vocabulary_id": 2
}
```
* **동작**: 세션 유저의 `active_vocabulary_id`를 업데이트하고, 해당 단어장의 학습 진척도 요약을 반환.

#### 3) 오늘의 세션 문항 추출 (15문항 청크)
* **엔드포인트**: `GET /api/study/session/today`
* **파라미터**: `count` (기본값 15, 최대 30)
* **출제 알고리즘**:
  1. `user_word_progress` 기준 최근 오답 단어 (`last_result = 'WRONG'`) 우선 추출 (최대 30%).
  2. 한 번도 학습하지 않은 미학습 단어 순차 추출 (60%).
  3. 무작위 복습 단어 (10%).
* **응답 규격 (200 OK)**:
```json
{
  "session_id": "sess_20261105_001",
  "vocabulary_title": "중고등 기본 1,000제",
  "total_questions": 15,
  "items": [
    {
      "question_id": 1,
      "word_id": 105,
      "cloze_sentence": "The meeting was _________ until next Monday.",
      "korean_hint": "회의는 다음 주 월요일까지 연기되었다.",
      "part_of_speech": "v.",
      "options": ["postpone", "accelerate", "investigate", "establish"],
      "phonetic": "[pəʊstˈpəʊn]"
    }
  ]
]
```

## 4. 시드(Seed) 데이터 자동 파이프라인

### 4.1 시드 파일 저장소 구조
기존 업로드 방식을 대체하여 표준화된 JSON/CSV 데이터를 서버 레포지토리에 형상 관리합니다.

```text
src/backend/data/seeds/
├── system_vocabularies.json    # 단어장 메타 정보 (ID, 제목, 카테고리, 레벨)
└── words/
    ├── 01_elementary_800.json  # 초등 800 단어 및 문장
    ├── 02_secondary_1000.json  # 중고등 1,000제
    └── 03_csat_2000.json       # 수능 2,000제
```

### 4.2 자동 시딩 실행 메커니즘
* **서버 라이프사이클(`lifespan`) 연동**: FastAPI 애플리케이션 시작 시 `init_system_seeds()` 호출.
* **Idempotency(멱등성) 보장**:
  * `system_vocabularies` 및 `system_words`에 버전 해시 또는 고유 식별키를 두어, 이미 데이터가 적재되어 있다면 불필요한 DB 쓰기 작업을 건너뜀.
  * 신규 단어 추가 또는 오타 수정 시 시드 파일 수정 후 마이그레이션 커맨드로 업데이트 반영.

## 5. 단계별 실행 계획

```text
[1단계: DB 스키마 & 시드] ──> [2단계: 백엔드 API & 서비스] ──> [3단계: 프론트 클라이언트 연동] ──> [4단계: 레거시 제거]
 - Alembic 마이그레이션         - SystemVocab 서비스 구현        - api.js 엔드포인트 교체           - CSV 업로더 삭제
 - Seed Loader 스크립트        - 세션 출제 알고리즘 구현         - Explore 뷰 카탈로그 연동         - 단어 편집 UI 제거
```

### 1단계: 스키마 생성 및 시드 적재
1. Alembic 마이그레이션 스크립트 작성 (`create_system_vocabularies_and_words`).
2. 기존 1,000제 프리셋 데이터를 `02_secondary_1000.json` 표준 시드로 변환 및 DB 로드 검증.
3. 기존 사용자의 학습 로그가 유실되지 않도록 외래키 마이그레이션 맵핑.

### 2단계: 백엔드 서비스 계층 구현
1. `services/system_vocab.py`: 카탈로그 조회 및 진행률 계산.
2. `services/session_engine.py`: 오답 우선 15문항 큐 추출 로직.
3. `routers/system_vocabularies.py` 엔드포인트 구현 및 pytest 테스트 작성.

### 3단계: 프론트엔드 연동
1. `src/frontend/js/core/api.js`: 불필요한 단어 CRUD 메서드 삭제, 카탈로그 및 세션 API 추가.
2. `src/frontend/js/views/explore-view.js`: 표준 단어장 선택 및 활성화 UI 바인딩.
3. 대시보드 메인 CTA를 "현재 활성화된 단어장 즉시 학습"으로 연결.

### 4단계: 레거시 코드 정리
1. 프론트엔드의 CSV 드롭존, 벌크 텍스트 파서 모듈 완전 제거.
2. 미사용 백엔드 스키마(`WordBulkCreateRequest` 등) 정리 및 테스트 통과 확인.
