## 1. #9 플래시카드 전체 로딩

**원인**: 화면이 `limit=500`으로 한 번만 요청하고 서버가 준 `total`을 쓰지 않았다. 서버는 표제어 순서로 앞 500장만 주므로 그 뒤 단어는 순서대로 볼 때도, 섞을 때도 나오지 않았고, 끝에서는 "모든 카드를 봤습니다"가 떴다.

**변경**
- 백엔드: `GET /api/study/flashcards`에 `offset`(0 이상, 기본 0)을 추가했다. 표제어 순서에서 건너뛸 개수다. 무작위 순서는 요청마다 달라 이어 받을 수 없으므로 `shuffle=true`와 `offset`을 함께 쓰면 422다. 조용히 틀린 결과를 주는 것이 이번 결함과 같은 종류라서 오류로 막았다.
- 프론트엔드: `core/flashcard-load.js`(`loadAllCards`)가 첫 응답의 `total`만큼 `offset`을 늘려 가며 모두 받는다. 섞기는 전부 받은 뒤 `deck`에서 하므로 전체 범위에 적용된다. 최대 20쪽(10,000장)에서 멈추고, 그 경우 화면에 "전체 N장 중 M장만 불러왔습니다"를 보인다.
- 선택 근거: 서버 셔플 + 쪽 단위 로딩은 화면의 이동·되돌아가기·셔플 토글 상태 관리가 훨씬 복잡해진다. 1,000장 규모는 요청 2번으로 충분해서, 변경이 작고 기존 `deck` 로직을 그대로 쓰는 쪽을 택했다.

## 2. #10 소버그 묶음

1. **로그인 실패 문구**: "이메일 또는 비밀번호" → "닉네임 또는 비밀번호". 공식 문서(API 규격서 §3.1, UI/UX 설계서)에는 이미 "닉네임 또는 비밀번호"로 적혀 있어서 코드가 문서와 어긋나 있던 것이다. 문서는 고치지 않았다. `password.py` docstring과 테스트의 예시 문구도 맞췄다.
2. **다크 모드 색 누락**: 사용 중인 색 클래스를 `app.css`의 다크 규칙과 대조해 누락 8종을 보완했다.
   - `bg-green-50`: 이력의 "정답" 뱃지, 퀴즈 결과 정답 선지가 연한 배경에 연한 글씨였다.
   - `hover:text-zinc-900`: 고스트 버튼(닫기, 뒤로가기, 더보기)에 hover하거나 탭하면 어두운 배경에 어두운 글자가 되었다. 점검 때 놓쳤던 더 심각한 항목이다.
   - `text-red-600`, `border-red-200`, `hover:text-indigo-600/700`, `hover:bg-indigo-50/40`, `hover:border-indigo-300`.
3. **서버 문구 의존 분기**: 제출 오류 응답에 `X-Error-Code` 헤더(`QUIZ_EXPIRED`, `QUIZ_ALREADY_SUBMITTED`, `QUIZ_ANSWER_INVALID`, `QUIZ_WORD_MISSING`)를 더했다. `detail` 문구와 상태 코드는 그대로라 기존 호출과 호환된다. `ApiError.code`로 읽고, `quiz.js`는 정규식·`includes("삭제")` 대신 코드로 분기한다. 헤더를 택한 이유는 `detail`을 객체로 바꾸면 모든 화면의 오류 표시 코드와 기존 테스트가 깨지기 때문이다.

## 3. 재발 방지

- `tests/dark-theme.test.js`: 화면 코드(`js/**`, `index.html`)가 쓰는 모든 색 클래스에 다크 오버라이드가 있는지 검사한다. 수정 전 CSS로 돌리면 누락이 잡히는 것을 확인했다. 양쪽 테마에서 읽히는 색은 테스트 안 `THEME_NEUTRAL`에 사유와 함께 올린다.

## 5. 테스트 결과

- 백엔드 `pytest`: 298건 통과 (기존 295 + 신규 3).
- 프론트엔드 `node --test`: 207건 통과 (기존 197 + 신규 10).
- 전체 실행 중 `test_wordbook_api.py::test_list_is_ordered_by_most_recently_updated`가 한 번 실패했다. 단독 5회, 전체 재실행에서는 통과했다. 이번 변경과 무관한 기존 테스트다. 10ms `sleep`에 의존하고, 생성 시각은 DB 시계(`UTC_TIMESTAMP(3)`), 수정 시각은 앱 시계(`utcnow`)를 써서 두 시계의 미세한 차이로 순서가 뒤집힐 수 있는 것으로 추정한다 (재현해 확인하지는 못했다). 별도 이슈로 다룰 가치가 있다.

## 6. 미확인·후속

- **브라우저 실사용 확인은 하지 않았다.** 다크 모드 색 대비, 1,000장 단어장에서의 로딩 체감, 퀴즈 제출 오류 안내는 코드와 단위 테스트로만 검증했다. 직접 한 번 확인해 주면 좋다.
- **공식 문서 반영이 필요하다** (`docs/` 직접 수정 금지 규정에 따라 승인 후 버전 업 절차로 진행).
  - API 규격서 #18: `offset` 쿼리와 `shuffle=true` 조합 422.
  - API 규격서 오류 규약: 퀴즈 제출 오류의 `X-Error-Code` 헤더 값 4종.
