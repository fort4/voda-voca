## 1. 요구사항 명세 v2.3

> **REQ-159 | 관리자 계정 | M** — (2026-11-26 신설, 이슈 #30) ① 닉네임이 `admin`(영문 대소문자·앞뒤 공백 무시)인 계정이 관리자다. ② 서버는 시작할 때 계정이 없으면 초기 비밀번호 `admin1234` 로 만든다. 이미 있으면 건드리지 않아 바꾼 비밀번호가 유지된다. ③ `admin` 닉네임은 예약어다. 가입은 409(`NICKNAME_TAKEN`), 중복 확인은 사용 불가다. ④ 관리자 계정은 탈퇴할 수 없다(403). ⑤ 관리 API 는 비로그인 401, 일반 사용자 403 이며 서버가 요청마다 판정한다. 내 정보에 `is_admin` 을 싣는다. ⑥ 알려진 위험: 초기 비밀번호가 공개 저장소에 있어 바꾸기 전에는 누구나 관리자로 로그인할 수 있다(ADR-011).
>
> **REQ-164 | 비밀번호 변경 | M** — (2026-11-26 신설, 이슈 #30) ① 로그인한 **모든 사용자**가 계정 메뉴의 마이페이지에서 비밀번호를 바꾼다(`PUT /api/auth/me/password`). ② 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인을 받는다. 새 비밀번호 규칙은 가입(REQ-001)과 같고 현재 비밀번호와 달라야 한다(위반 422). ③ 현재 비밀번호가 틀리면 400(`CURRENT_PASSWORD_MISMATCH`). ④ 계정별 1분 5회를 넘으면 429 + `Retry-After`(성공하면 초기화). ⑤ 성공하면 지금 세션은 유지하고 본인의 다른 세션을 지운다. ⑥ 마이페이지에는 닉네임·역할·가입일(한국 날짜)을 보인다.

## 2. API 연동 규격서

- #1·#1b: `admin` 은 예약 닉네임.
- #4 `UserOut`: `is_admin: boolean` 추가(로그인·가입 응답도 같음, 하위 호환).
- #4b 탈퇴: 403 추가(관리자).
- #4c 신설 `PUT /api/auth/me/password` — 본문 `{"current_password", "new_password", "new_password_confirm"}`, 204, 실패 400(`X-Error-Code: CURRENT_PASSWORD_MISMATCH`)·401·422·429(`Retry-After`).

## 3. UI/UX 설계서

- 계정 메뉴 순서: **마이페이지** → 학습 설정 → 환경 설정 → 로그아웃 → 회원 탈퇴(관리자는 숨김). 역할 칩은 "학습자"/"관리자".
- 마이페이지(`#/mypage`): 계정 카드, 비밀번호 변경 카드(세 칸 모두 보기 토글, 확인란 일치 안내 `aria-live`, 제출 중 버튼 비활성, 성공 토스트 후 입력 비움). 관리자에게는 초기 비밀번호 변경 안내를 보인다. 하단 탭바는 보이되 활성 탭이 없다.

## 4. 결정 기록 — ADR-011 (신설)

- 결정: 관리자는 고정 닉네임 `admin`, 초기 비밀번호 `admin1234` 를 코드 상수로 둔다. 역할 컬럼·환경 변수는 두지 않는다.
- 이유: 채점 환경에서 설정 없이 로그인할 수 있어야 하고, 스키마 변경이 필요 없다 (사용자 결정 2026-11-26).
- 대안: `ADMIN_USERNAME`/`ADMIN_INITIAL_PASSWORD` 환경 변수 — 채택하지 않음.
- 대가: CLAUDE.md §5.3 의 예외. 배포 직후 바꾸지 않으면 누구나 관리자가 된다. 기존 DB 에 `admin` 계정이 이미 있으면 그 계정이 관리자가 된다.
