# 검토 — SRS(이슈 #25) 문서 개정 초안 (REQ-149)

`docs/` 는 승인 후 승격 대상이라 이 초안을 사용자가 승인하면 `개발방법론.md` 절차에 따라 v2.2 파일로 반영한다.

## 1. 요구사항 명세서 — REQ-149 신설
| ID | 요구사항 | 비고 |
| :--- | :--- | :--- |
| REQ-149 | 시스템은 단어별 복습 단계(0~5)와 다음 복습 시각을 사용자별로 기록하고, 복습 시각이 도래한 단어를 "오늘 복습"으로 집계·출제한다 | 이슈 #25 |
- 정답 +1단계, 오답 −2단계(최소 0). 간격 0/1/3/7/14/30일.
- 세션 출제(source=all)의 복습 슬롯은 기한이 지난 단어(오래 밀린 순)를 먼저 쓰고, 숙련 단어도 기한이 되면 복귀한다. 기한 전 단어는 풀이 모자랄 때만 채운다.
- 복습함에 "오늘 복습" 카드(개수 + 시작 버튼). 기한이 도래한 단어만으로 세션을 만든다.

## 2. Data 명세서
- `user_word_progress.interval_step TINYINT UNSIGNED NOT NULL DEFAULT 0`
- `user_word_progress.next_review_at DATETIME(3) NULL`, 인덱스 `idx_uwp_user_next_review (user_id, next_review_at)`
- `quiz_sessions.source` CHECK: `vocabulary | bookmarks | wrong | due`
- 마이그레이션: `f4c8b2d6a1e7`(컬럼·백필), `a7d3f1c9e5b2`(source `due`)

## 3. API 명세서
- `POST /api/study/sessions` (실제 경로는 명세 기준): `source` 에 `due` 추가. 기한 도래 단어가 없으면 409 `NO_WORDS_TO_STUDY`, 퀴즈에서 4개 미만이면 기존 `QuizSourceTooSmall` 응답.
- `GET /api/study/stats` 응답에 `due_review_count: int` 추가.

## 4. UI/UX 명세서
- 복습함 상단에 "오늘 복습" 카드(개수 문구, 0이면 "모두 마쳤어요" + 버튼 비활성).

## 5. 열린 사항
- `is_memorized` 를 단계로 흡수하지 않았다. 숙련 단어도 기한이 되면 출제되는 것으로 목적(망각 방지)은 달성하며, 통계의 "숙련" 수치 의미는 유지된다.
- 홈 화면에 오늘 복습 개수 노출은 이번 범위에서 제외 (후속 후보).

> **정정 (2026-11-19)**: 이 초안의 "REQ-149 신설"은 기존 REQ-149(환경 설정)와 번호가 겹쳐, 요구사항 명세 v2.2 에는 **REQ-150** 으로 반영했다. 나머지 내용(Data·API·UI/UX)은 v2.2 문서에 반영 완료.
