## 2. 요구사항 (신설)

**REQ-169 개인 단어장 소유와 접근 통제 (M)** — 단어장은 표준(소유자 없음)과 개인(소유자 있음)이다. ① 표준 단어장은 모두가 보며 아무도 고칠 수 없다. ② 개인 단어장은 소유자만 보고 학습한다. 목록·단어 목록·검색·학습 단어장 선택·북마크·통계에서 남의 것은 없는 것과 같다(404). ③ 기본 학습 단어장은 표준 단어장에서 고른다. ④ 탈퇴하면 개인 단어장과 단어, 학습 기록이 함께 지워진다.

**REQ-170 개인 단어장·단어 관리 (M)** — ① 로그인한 사용자는 단어장을 만든다(제목 100자 필수, 설명 255자 선택. 분류 기본 `PERSONAL`, 레벨 기본 1). ② 내 단어장만 제목·설명 수정과 삭제를 한다. ③ 단어를 추가·수정·삭제한다(표제어 100자·뜻 200자 필수, 예문·예문 뜻 500자 선택). 같은 단어장의 표제어는 대소문자·악센트를 무시하고 중복될 수 없다(409 `TERM_TAKEN`). ④ 표준 단어장 변경은 403 `SEED_READ_ONLY`, 남의 것은 404, 비로그인은 401.

**REQ-171 CSV 일괄 등록 (M)** — 내 단어장에 CSV 원문(`text/csv`)을 올린다. ① 열 이름은 `영단어,뜻`(필수), `예문`, `예문 뜻`(선택). 영문 `term,meaning,example,example_meaning` 도 된다. ② UTF-8(BOM 허용), 3,000행·1MB 이하. ③ 오류가 하나라도 있으면 파일 전체를 거부하고 행 번호를 알린다. ④ 중복 표제어는 건너뛰고 건수를 알린다.

## 4. ADR-017 요지: 표준 단어장 위에 개인 단어장을 둔다

- **배경**: 관리자 전용 등록은 VOCA-FR-001~003 을 일부만 만족했고, 코드의 초기 비밀번호가 VOCA-NFR-004 를 어겼다.
- **결정**: ① 테이블을 늘리지 않고 `system_vocabularies.owner_id` 로 구분한다. ② 조회는 모두 `visible_to(user_id)` 를 쓴다. ③ 관리자 역할을 없앤다.
- **대안**: 개인 단어 전용 테이블(학습·북마크·통계 코드가 두 벌이 된다), 관리자 유지(점수·보안 이점 없음) — 기각.
- **결과**: 새 조회를 만들 때 접근 조건을 빠뜨리면 남의 단어가 보인다(`test_vocabulary_ownership_api.py` 로 고정). 테이블 이름 `system_*` 은 개인 단어도 담게 되었다. 열 추가는 테이블 재작성을 피해 `ADD COLUMN ... REFERENCES` 로 했고, SQLAlchemy 가 이 외래키를 읽지 못해 `alembic check` 비교에서 이것만 제외하고 전용 테스트로 확인한다.

## 6. 남은 사항

- 과제 제공 CSV 원본(`영단어,뜻`, 2,000개)으로 확인 (파일 필요). 2026-11-26 에 받은 `ai-agent/claude/uploads/` 의 500행 파일 두 개는 `term,meaning` 형식의 기존 샘플로, 각 500단어 등록·재등록 시 500건 건너뜀을 확인했다.
- 로컬 개발 DB 에 `0005` 를 적용했다(2026-11-26, 백업 `ai-agent/backups/voca_dev_261126_pre0005.db`, 행 수 동일, 무결성·외래키 검사 통과). 관리자 단어장 1개가 `admin` 계정의 개인 단어장이 되었다.
- 이미 `admin` 계정이 만들어진 DB 에서는 그 계정이 일반 계정으로 남는다. 비밀번호가 `admin1234` 그대로면 누구나 로그인할 수 있으므로 바꾸거나 탈퇴시킨다.
- 사용자별 단어장 수 상한은 두지 않았다.
- 순위(#42)는 시작하지 않았다.
