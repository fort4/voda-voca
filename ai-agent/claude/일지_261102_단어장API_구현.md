## 3. 핵심 정책

### 3.1 소유권 격리와 404 일원화 (REQ-003)
- 모든 단건 조회·수정·삭제는 `get_owned_wordbook(db, user_id, wordbook_id)`를 거칩니다. 쿼리 조건은 `id = ? AND user_id = ?`입니다.
- 타인 소유 단어장과 존재하지 않는 ID는 **같은 404 본문**으로 응답합니다. 403을 쓰면 해당 ID가 존재한다는 사실이 드러나므로(ID 열거), 명세가 허용한 두 옵션 중 404를 택했습니다.
- 목록은 `WHERE user_id = ?`로 본인 단어장만 반환합니다.
- 테스트 `test_other_users_missing_and_foreign_ids_give_identical_404`가 두 응답의 동일성을 직접 비교합니다.
- 이후 단어·북마크 API도 같은 함수로 단어장 소유자를 확인합니다.

### 3.2 페이징 상한 (REQ-005, REQ-103)
- `size`: `Query(default=20, ge=1, le=100)`. 기본 20건, 최대 100건입니다.
- `page`: `ge=1`. 0, 음수, 101 이상은 422로 거부됩니다.
- 응답은 `items`, `total`, `page`, `size`를 포함합니다.
- 정렬 키는 `updated_at DESC, id DESC`입니다. 수정 시각이 같은 행의 순서도 고정됩니다.

### 3.3 이름 중복과 DB 기반 동시성 제어 (REQ-004, REQ-105)
- 애플리케이션에서 먼저 조회하지 않습니다. `uk_wordbooks_user_name(user_id, name)` UNIQUE 위반을 최종 기준으로 삼습니다.
- 동시에 같은 이름으로 생성해도 한쪽만 성공합니다. 실패한 쪽은 `IntegrityError`를 잡아 409로 바꿉니다.
- 위반이 다른 제약 때문이면 바꾸지 않고 그대로 전파합니다.
- 콜레이션 `utf8mb4_0900_ai_ci` 때문에 `Vocab`과 `vocab`은 같은 이름입니다. 테스트 `test_create_duplicate_name_is_409_case_insensitive`가 확인합니다.
- 다른 사용자끼리는 같은 이름을 쓸 수 있습니다.
- 이름 변경도 같은 경로로 409를 냅니다. 테스트 `test_patch_to_taken_name_is_409`가 확인합니다.

### 3.4 CASCADE 삭제 (REQ-007, REQ-104, REQ-106)
- 단어장 삭제는 `db.delete` 한 번과 커밋입니다. 하위 데이터는 DB의 `ON DELETE CASCADE`가 정리합니다.
- 삭제 범위는 단어, 북마크, 학습 이력입니다.
- 테스트 `test_delete_cascades_words_bookmarks_and_study_logs`가 단어, 북마크, 학습 이력을 직접 넣은 뒤 단어장을 지워 세 테이블이 모두 0건인지 확인합니다.

### 3.5 변경 없는 수정
- 값이 같으면 SQLAlchemy가 UPDATE를 보내지 않으므로 `updated_at`이 바뀌지 않습니다 (REQ-006).
- 테스트 `test_patch_without_changes_keeps_updated_at`이 확인합니다.
- 부분 수정은 요청에 포함된 필드만 바꿉니다. `name`은 null로 바꿀 수 없고, `description`은 null로 지울 수 있습니다.
