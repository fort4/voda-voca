## 2. TTS 음성 읽기 (`core/tts.js`)

### 2.1 설계
- 래퍼는 `createSpeaker({synth, UtteranceCtor, warn, defaults})`로 만듭니다. 기본 인스턴스는 `window.speechSynthesis`와 `SpeechSynthesisUtterance`를 씁니다. 테스트에서는 가짜 합성기를 주입합니다.
- 기본 설정은 `lang: 'en-US'`, `rate: 0.9`, `pitch: 1.0`입니다. 호출 시 옵션으로 덮어쓸 수 있습니다.
- **연속 클릭**: 발화를 시작하기 전에 `speechSynthesis.cancel()`을 부릅니다. 빠르게 여러 번 눌러도 이전 발화가 남지 않고 마지막 것만 읽힙니다.
- **예외 처리**
  - 빈 텍스트나 공백만 있는 텍스트는 아무것도 하지 않고 `false`를 돌려줍니다.
  - 브라우저가 Web Speech API를 지원하지 않으면 예외 없이 `false`를 돌려주고, 경고는 **한 번만** 콘솔에 남깁니다.
  - 합성기가 예외를 던지면 잡아서 경고를 남기고 `false`를 돌려줍니다.
  - 발화 오류(예: 오프라인이어서 음성이 없음)는 `onerror`에서 경고만 남기고 화면은 그대로 둡니다. 화면이 깨지지 않게 하려는 조치입니다.

### 2.2 화면 연결
| 화면 | 위치 | 읽는 텍스트 |
| :--- | :--- | :--- |
| 단어 목록 (`views/words.js`) | 각 행의 표제어 옆 (별 버튼 왼쪽) | 표제어 |
| 플래시카드 (`views/flashcards.js`) | 앞면 우상단 | 표제어 |
| 플래시카드 (`views/flashcards.js`) | 뒷면 우상단 (예문이 있을 때만) | 예문 |
| 퀴즈 (`views/quiz.js`) | 문제 카드 오른쪽 가운데 | 표제어 |

- 플래시카드 스피커는 카드를 뒤집는 포인터 동작과 겹치지 않도록, 스피커 래퍼에서 `pointerdown`과 `pointerup`의 전파를 막습니다. 스피커를 눌러도 카드가 뒤집히지 않습니다.
- 스피커 버튼은 최소 44×44px 터치 타깃이고 `aria-label`을 갖습니다.

## 3. 다크 모드 테마 (`core/theme.js`, `css/app.css`, `index.html`, `app.js`)

### 3.1 초기 판정 우선순위
1. `localStorage['voda.theme']`에 `light` 또는 `dark`가 있으면 그 값.
2. 없거나 잘못된 값이면 `matchMedia('(prefers-color-scheme: dark)')`를 따릅니다.
3. 둘 다 없으면 라이트입니다.

판정 함수 `resolveInitialTheme({stored, prefersDark})`는 순수 함수입니다. 관리자 `createThemeManager({storage, root, matchMedia})`는 생성 즉시 `<html>`에 `.dark` 클래스를 맞춥니다.

### 3.2 저장 정책
- 시스템 설정으로 정해진 초기 테마는 **저장하지 않습니다.** 사용자가 전환 버튼을 눌렀을 때만 `voda.theme`에 저장합니다. 그래야 OS 설정을 바꾸면 따라 바뀝니다.
- 저장소가 막혀 있어도(사생활 보호 모드 등) 전환은 동작합니다. 저장 실패는 무시합니다.

### 3.3 첫 화면 깜빡임 방지
- `index.html` `<head>`의 인라인 스크립트가 본문을 그리기 전에 `.dark` 클래스를 붙입니다. 같은 규칙을 씁니다. 다크 사용자가 밝은 화면을 잠깐 보는 현상을 막기 위해서입니다.

### 3.4 전환 버튼
- 헤더 우측, 프로필 칩 왼쪽에 둡니다. 아이콘은 라이트에서 달 모양(`moon`), 다크에서 해 모양(`sun`)입니다.
- `aria-pressed`와 `aria-label`로 현재 상태를 알려 줍니다.

### 3.5 다크 토큰 (`html.dark`)
- 토큰 변수: 배경 zinc-950, 표면 zinc-900, 보더 zinc-800, 본문 zinc-50, 보조 글자 zinc-400, 포인트 indigo-400(어두운 배경에서 대비를 확보하려고 밝게 잡았습니다).
- 뷰가 쓰는 Tailwind 유틸리티(`bg-white`, `text-zinc-700`, `border-zinc-200`, `ring-*`, `bg-indigo-50`, `bg-emerald-50`, `bg-red-50` 등)를 같은 톤으로 덮어씁니다. 플립 카드 뒷면, 헤더, 탭바, SweetAlert2 대화창도 포함합니다.
- Tailwind Play CDN의 `dark:` 변형은 OS 설정을 따르므로 쓰지 않았습니다. 대신 `html.dark` 선택자를 씁니다. 그래서 사용자가 고른 테마가 항상 우선합니다.

## 4. 키보드 단축키

### 4.1 전역 가드 (`core/shortcuts.js`)
- 단축키는 **입력 칸(`input`, `textarea`, `select`, 편집 가능 요소)**에서는 동작하지 않습니다.
- **열려 있는 SweetAlert2 모달**이 있으면 동작하지 않습니다.
- Enter와 Space는 포커스가 **버튼**에 있을 때 브라우저의 클릭 동작에 맡깁니다. 그래서 같은 키가 두 번 실행되지 않습니다.

### 4.2 퀴즈 (`views/quiz.js`)
| 키 | 동작 |
| :--- | :--- |
| `1` `2` `3` `4` | 해당 보기를 즉시 선택 (아직 답하지 않은 문항에서만) |
| `Enter` / `Space` | 해설이 열린 뒤 [다음 문항] 실행, 마지막 문항이면 [최종 결과 보기] 실행 |

- 시간이 지났거나 제출 중이면 아무 키에도 반응하지 않습니다.
- 리스너는 퀴즈 세션이 시작될 때 등록하고, 뷰를 떠날 때 정리합니다.

### 4.3 플래시카드 (`views/flashcards.js`)
| 키 | 동작 |
| :--- | :--- |
| `Space` | 카드 앞·뒤 뒤집기 (버튼 포커스 상태는 제외) |
| `←` / `→` | 이전 / 다음 카드 |
| `S` | 셔플 켜기·끄기 (마지막 카드를 보는 중이 아닐 때) |

- `Ctrl`, `Meta`, `Alt`를 함께 누른 `S`는 무시합니다. 브라우저 단축키를 가로채지 않기 위해서입니다.
- 리스너는 뷰를 떠날 때 제거합니다.

## 6. 설계 판단
| 항목 | 판단 | 이유 |
| :--- | :--- | :--- |
| 발화 전 `cancel()` | 항상 호출 | 연속 클릭에서 발화가 쌓이는 현상을 막음 |
| 오류는 경고만 | `console.warn`, 화면 변화 없음 | 음성이 없는 환경에서 학습 흐름을 막지 않음 |
| 시스템 테마는 저장 안 함 | 사용자 선택만 저장 | OS 설정을 바꾸면 자동으로 따라가게 함 |
| 다크 모드는 `html.dark` 덮어쓰기 | `dark:` 변형 대신 선택자 | Play CDN의 `dark:`는 OS 설정을 따르므로 사용자 선택과 충돌 |
| Enter·Space는 버튼에 맡김 | 버튼 포커스일 때 전역 처리 생략 | 같은 키로 두 번 실행되는 것을 막음 |
| S 키는 Ctrl·Meta·Alt와 함께면 무시 | 수정 키 조합 가드 | 브라우저의 기본 단축키를 가로채지 않음 |

## 7. 브라우저 확인 체크리스트
1. **TTS**: 단어 목록에서 스피커를 누르면 표제어가 영어로 읽히는지 확인합니다. 빠르게 연속으로 누르면 마지막 것만 읽히는지 봅니다.
2. **TTS 미지원**: 음성 합성을 지원하지 않는 브라우저나 음성 없는 환경에서 화면이 깨지지 않고 콘솔에 경고 한 번만 남는지 확인합니다.
3. **플래시카드 스피커**: 앞면 스피커는 표제어를, 뒷면 스피커는 예문을 읽는지 확인합니다. 스피커를 눌러도 카드가 뒤집히지 않아야 합니다.
4. **다크 모드 기본값**: OS를 다크로 두고 처음 접속하면 어두운 화면인지 확인합니다. 첫 화면에 밝은 화면이 깜빡이지 않는지도 봅니다.
5. **전환**: 헤더의 달·해 버튼으로 전환하면 즉시 바뀌는지 확인합니다. 새로고침 후에도 유지되는지 봅니다. OS 설정을 바꿔도 사용자가 한 번 고른 뒤에는 따라가지 않는지 확인합니다.
6. **다크 시인성**: 플립 카드 앞·뒷면, 퀴즈 보기(정답 초록, 오답 빨강), 해설 카드, 입력 칸, SweetAlert2 대화창의 글자가 잘 보이는지 확인합니다.
7. **퀴즈 단축키**: 미선택 상태에서 `1`~`4`로 보기를 고르면 바로 판정되는지 봅니다. 판정 뒤 같은 키는 무시되어야 합니다. `Enter`와 `Space`로 해설 다음 문항, 마지막 문항에서는 최종 결과가 실행되는지 확인합니다.
8. **퀴즈 가드**: 입력 칸이나 모달이 열린 상태에서 숫자 키를 눌러도 보기가 선택되지 않는지 확인합니다.
9. **플래시카드 단축키**: `←` `→`로 이동, `Space`로 뒤집기, `S`로 셔플이 켜지고 꺼지는지 확인합니다. 보던 카드가 셔플 후에도 그대로인지 봅니다.
10. **포커스 중복**: 보기 버튼에 포커스가 있을 때 `Enter`를 누르면 한 번만 선택되는지 확인합니다.
11. **콘솔**: 오류가 없어야 합니다 (음성 경고 한 번은 허용).
