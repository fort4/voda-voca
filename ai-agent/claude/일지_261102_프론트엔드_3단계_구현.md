## 2. 플래시카드 (`views/flashcards.js`, `core/deck.js`, `core/gesture.js`)

- **출처**: `#/study/flashcards?wordbook_id=N`(단어장) 또는 `?bookmarked=1`(북마크). 출처가 없으면 안내를 띄웁니다.
- **데이터**: `GET /api/study/flashcards`를 `limit=500`으로 한 번 받고, 셔플은 클라이언트에서 합니다. 셔플을 켜거나 끌 때마다 서버를 다시 부르지 않습니다.
- **덱 상태 (`createDeck`)**: 현재 위치, 앞·뒤 상태, 셔플 순서를 가집니다. 경계에서는 `next`, `prev`가 `false`를 돌려주고 멈춥니다.
  - 카드를 옮기면 뒤집기 상태는 앞면으로 돌아갑니다.
  - 셔플을 켜거나 끄면 **지금 보고 있던 카드는 그대로** 보입니다 (`setShuffle`).
- **3D 뒤집기**: 카드 하나에 앞면과 뒷면을 겹치고, 뒷면은 `rotateY(180deg)`로 미리 돌려 둡니다. 뒤집기는 `is-flipped` 클래스만 토글하므로 애니메이션이 끊기지 않습니다. 동작 줄이기 설정에서는 애니메이션을 끕니다 (기존 CSS 규칙).
- **제스처 (`classifyGesture`)**:
  - 8px 미만 이동은 탭으로 보고 뒤집습니다.
  - 가로 48px 이상이고 세로보다 크면 좌우 넘김입니다. 왼쪽으로 밀면 다음, 오른쪽으로 밀면 이전입니다.
  - 세로 이동이 더 크면 스크롤로 보고 무시합니다.
- **키보드**: `←` 이전, `→` 다음, `Space`·`Enter` 뒤집기. 입력 칸과 버튼에 포커스가 있으면 무시합니다.
- **마지막 카드**: 다음을 누르면 "모든 카드를 봤습니다"와 다시 보기, 목록으로 버튼을 보입니다.

## 3. 4지선다 퀴즈 (`views/quiz.js`, `core/quiz-state.js`, `core/timer.js`, `core/result-cache.js`)

### 3.1 출제 전 가드 (결정 4)
- 출제 화면을 열면 원천 단어 수를 먼저 셉니다. 단어장은 `GET /wordbooks/{id}/words?size=1`, 북마크는 `GET /bookmarks?size=1`의 `total`을 씁니다.
- 4개 미만이면 **시작 버튼을 막고** 안내를 보입니다. 서버의 400을 기다리지 않습니다.
- 문항 수는 5, 10, 20 중에서 고릅니다. 원천 단어가 적으면 "N문항으로 출제합니다"로 실제 수를 안내합니다.

### 3.2 세션 타이머 (결정 2)
- 출제 응답의 `expires_at`(30분)을 기준으로 **로컬 카운트다운**을 합니다.
- **시계 보정**: 응답의 `Date` 헤더로 서버와 기기 시각의 차이를 구합니다 (`computeClockOffset`). 기기 시계가 틀려도 남은 시간이 맞습니다. 헤더가 없으면 보정 없이 계산합니다.
- 잔여 시간 = `expires_at − (기기 시각 + 보정값)`이고 0 아래로 내려가지 않습니다 (`remainingMs`).
- 표시는 `mm:ss`이고 초는 올림합니다 (`formatClock`). 5분 이하는 빨간색으로 강조합니다 (`isWarning`).
- **만료**: 0이 되면 선택과 제출을 막고 "시간이 지났습니다" 안내를 띄웁니다. 제출 요청은 보내지 않습니다.
- 서버 검증이 최종입니다. 로컬 타이머가 조금 늦게 끝나도, 제출 요청에서 서버가 400으로 거절하면 같은 만료 안내를 보입니다.

### 3.3 답안과 제출 (결정 1: 일괄 채점)
- 문항을 고르면 `createQuizState`에만 저장합니다. **정답 인덱스는 제출 전까지 화면에 없습니다.**
- 진행률 바와 "N / M 답함, K문항 남음"을 보여 줍니다.
- 마지막 문항에서만 "제출하기"가 나오고, 모든 문항에 답해야 활성화됩니다. 아직 답하지 않은 문항 수를 안내합니다.
- 제출 전에 확인 창을 띄웁니다 ("제출하면 답을 고칠 수 없습니다").
- 제출 본문은 문항 번호 순으로 정렬한 `{answers: [{question_id, choice_index}]}`입니다.
- 제출 오류:
  - 400 + 만료 → 만료 안내
  - 409 + "삭제" → 단어 삭제로 제출 불가, 퀴즈를 다시 시작하라는 안내
  - 409 그 밖 → 이미 제출된 퀴즈 안내
- 제출 중에는 타이머를 멈추고 화면을 잠급니다. 실패하면 타이머를 다시 켭니다.

### 3.4 결과 화면과 캐싱 (결정 3)
- 제출 응답의 `wrong_items`와 로컬 답안으로 **문항별 결과**를 만듭니다 (`deriveQuizItems`).
  - 틀린 문항은 표제어와 고른 뜻이 같은 문항을 찾아 정답 뜻의 선지 번호를 구합니다. 같은 표제어가 두 번 나와도 고른 뜻으로 올바르게 짝을 짓습니다 (테스트로 확인).
  - 맞힌 문항은 고른 선지가 정답입니다.
- 결과를 `sessionStorage['voda.quizResult.<session_id>']`에 저장한 뒤, 주소를 `#/study/quiz?session=<id>`로 바꿉니다.
- 결과 화면 구성:
  - 정답 개수, 정답률 (`N / M`, `정답률 P%`), 100%면 축하 문구
  - **오답 노트**: 틀린 단어의 표제어, 내 답, 정답 뜻, "북마크에 추가" 버튼 (`PUT /bookmarks/{word_id}`)
  - **전체 문항**: 선지마다 정답은 초록, 내 틀린 답은 빨강으로 표시
  - 다시 풀기(같은 출처로 새 퀴즈), 학습 이력 보기
- **복구**: 새로고침해도 주소에 세션 ID가 있으므로 캐시에서 결과를 다시 그립니다. 캐시가 없으면 "이 탭에서는 결과를 다시 볼 수 없습니다"를 보입니다.
- **로그아웃 시** `voda.quizResult.*` 키를 모두 지웁니다.

### 3.5 진행 중 새로고침
- 진행 중인 답안은 서버에 없고 메모리에만 있습니다. 새로고침하면 사라집니다. 이 한계는 API 규격 §6에 따른 확정 사항입니다.

## 4. 북마크 모아보기 (`views/bookmarks.js`)
- `GET /api/bookmarks`를 최신순 20건씩 받습니다. "더 보기"로 이어 받습니다.
- 각 행에 표제어, 뜻, 단어장 이름(칩), 북마크 시각(KST)을 보여 줍니다. 행을 누르면 그 단어장으로 갑니다.
- **별 해제 즉시 제거**: 별을 끄면 행이 바로 사라지고(낙관적 갱신), 서버 요청이 실패하면 목록을 다시 받아 되돌립니다. 2단계의 북마크 큐를 씁니다.
- 상단 액션:
  - "플래시카드": `#/study/flashcards?bookmarked=1`로 이동. 북마크가 없으면 비활성.
  - "퀴즈": `#/study/quiz?bookmarks=1`로 이동. **4개 미만이면 비활성**이고, "북마크가 4개 이상이면 퀴즈를 할 수 있습니다" 안내를 보입니다.

## 5. 학습 이력 (`views/history.js`, `lib/study-stats.js`)
- `GET /api/study/logs?limit=50`으로 받습니다.
- 상단 요약: 정답률, 정답 수와 오답 수. 집계는 받은 **최근 50건 기준**이라고 밝힙니다.
- 타임라인: 한국 날짜(YYYY-MM-DD)별로 묶고, 각 항목에 시각(HH:mm)과 정답·오답 태그를 붙입니다. 날짜가 바뀌는 기준은 한국 시각입니다 (UTC 자정 직전 기록이 다음 날로 묶이는지 테스트로 확인).
- 기록이 없으면 안내와 단어장 이동 버튼을 보입니다.

## 6. 네비게이션 (`app.js`, `index.html`)
- 하단 탭바: 단어장, 북마크, 이력 세 개입니다. 로그인하지 않은 상태에서는 숨깁니다.
- 현재 경로에 맞는 탭에 `aria-current="page"`를 붙이고 색을 강조합니다.
- 상단바 로그인 상태, 로그아웃, 세션 만료 흐름은 1단계와 같습니다.
- 라우트 4개를 `user` 접근으로 등록했습니다: `/study/flashcards`, `/study/quiz`, `/bookmarks`, `/history`.
- 단어 목록 화면 상단에 "플래시카드"와 "퀴즈" 버튼을 두고 해당 단어장으로 진입하게 했습니다.

### 7.3 테스트 중 발견·수정한 사항
- **테스트 설계 오류**: 셔플 결정성 테스트가 같은 덱을 두 번 걸어, 두 번째 순회는 마지막 카드만 보았습니다. 호출마다 새 덱을 만들도록 고쳤습니다. 제품 코드의 문제는 아니었습니다.
- **키보드 리스너 중복 등록**: 플래시카드 화면이 `keydown` 리스너를 두 번 등록하고 있었습니다. 한 번만 남기고 화면을 떠날 때 제거하도록 정리했습니다.
- **퀴즈 뷰의 잘못된 import**: 존재하지 않는 모듈(`quiz-time.js`)을 가져오고 있었습니다. `apiResponse`로 바꾸고, 타이머 기준 시각을 응답 직후의 `Date.now()`로 넘기도록 고쳤습니다.
- **정리 함수 누적**: 타이머 정리 함수가 배열에 반복해서 쌓였습니다. 화면당 하나의 정리 함수로 바꿨습니다.
- **이력 화면의 함수 섀도잉**: 구조 분해한 `navigate` 매개변수를 같은 이름의 내부 함수가 가리고 있었습니다. 매개변수를 그대로 쓰도록 고쳤습니다.
- **북마크 리스너 중복 분기**: 해제 처리 분기가 두 개였습니다. 하나로 합쳤습니다.

## 8. 알려진 한계와 후속 과제
- **브라우저 미검증**: 화면 동작은 아직 실제 브라우저에서 확인하지 않았습니다. 수동 체크리스트를 따라 확인해야 합니다.
- **진행 중 퀴즈 복구 불가**: 새로고침하면 진행 중이던 퀴즈는 사라집니다 (서버에 조회 API가 없고 API 규격 §6이 정한 한계).
- **결과 복구는 같은 탭 한정**: `sessionStorage`이므로 다른 탭이나 기기에서는 결과를 볼 수 없습니다 (확정 결정 3의 한계).
- **오답 노트의 북마크**: 북마크 버튼은 "추가"만 합니다. 다시 누르면 해제하지 않습니다. 해제는 북마크 화면에서 합니다.
- **학습 이력 집계 범위**: 요약 정답률은 받은 최근 50건 기준입니다. 전체 기간 통계는 없습니다.
- **플래시카드 500장 상한**: API 한도에 맞춰 한 번에 500장까지 받습니다. 그보다 많은 단어장은 일부만 학습됩니다.
