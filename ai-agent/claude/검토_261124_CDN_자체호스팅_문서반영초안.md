# 검토 — 외부 CDN 자체 호스팅(vendor/)의 문서 반영 초안

`docs/` 와 `CLAUDE.md` 는 승인 후에만 수정한다. 승인되면 아래대로 반영하고 각 문서의 변경 이력 행을 추가한다.
(구현·테스트는 완료: 프론트엔드 `node --test tests/` 473건 통과. 커밋 전)

## 변경 요약
- Tailwind(Play 스크립트 3.4.17), SweetAlert2 11.10.5, Lucide 0.460.0, Pretendard Variable 1.3.9(동적 서브셋 woff2 92조각), Paperlogy Bold 를 CDN 에서 받지 않고 `src/frontend/vendor/` 에서 같은 출처로 제공한다.
- 서버 코드는 바뀌지 않는다. 기존 `StaticFiles` 마운트가 `vendor/` 도 서빙한다. 빌드 파이프라인은 여전히 없다(ADR-007 결정 1 유지).
- **효과**: 오프라인·CDN 장애에서도 화면이 같다(A4 해소). 버전이 파일로 고정된다. 앱 이미지에 모든 화면 자원이 들어가므로 "다른 컴퓨터에서 동일 환경" 목표에 가까워진다.
- **남는 한계**: Tailwind Play 스크립트는 브라우저에서 스타일을 계산하므로 공식적으로 운영 비권장이다(파일 약 400KB). 운영 성능이 문제가 되면 standalone CLI 로 정적 CSS 를 생성하는 방안을 별도 결정으로 다룬다.
- 회귀 방지: `tests/self-hosted.test.js` 가 앱 소스의 외부 http(s) URL, vendor 파일 존재, Pretendard 92조각 완전성, `vendor/README.md` 기재를 검사한다.

## 열린 점
1. **브라우저 렌더링 미검증**: 서버가 DB 없이는 뜨지 않아 실제 화면(폰트·아이콘 표시, Tailwind 동작)은 확인하지 못했다. 컨테이너화 단계에서 DB 와 함께 띄워 확인한다.
2. **Paperlogy 라이선스**: 폰트 파일이 저장소에 들어갔으므로 재배포 허용 여부 확인이 더 중요해졌다(후속 과제 ⑦). 확인 전에는 `vendor/README.md` 에 "확인 필요"로 남긴다.
3. **캐시 헤더**: CDN 은 긴 캐시를 줬지만 `StaticFiles` 기본 응답은 `Cache-Control` 없이 ETag/Last-Modified 만 두는 것으로 알고 있다(미확인). 그러면 재방문마다 재검증 요청이 나가므로, 필요하면 버전 고정 파일(`vendor/`)에만 긴 캐시를 주는 방안을 컨테이너화 때 함께 본다.
4. **저장소 용량**: `vendor/` 4.1MB(Pretendard 3.1MB). 서체 갱신 시 이력이 누적되므로 버전 업은 드물게 한다.
5. **문서 파일명**: 이전 개정(ADR-006 결정 7·8)처럼 파일명을 유지하고 변경 이력 행으로 처리하는 안을 기본으로 했다. `docs/old/` 이동 절차(CLAUDE.md §3)로 하길 원하시면 알려 달라.
