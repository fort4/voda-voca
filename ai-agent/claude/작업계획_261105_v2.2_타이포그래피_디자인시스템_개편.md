## 2. 요구사항 (제안)

범위: **시각 체계의 정리.** 기능·API·DB·라우팅 변경 없음.

- **DS-1 폰트**: 한글 본문 서체 1종 + 영단어 표시용 서체 1종을 지정한다. 폰트 폴백 체인을 명시한다. 로딩 중 레이아웃 흔들림 최소화(`font-display: swap`).
- **DS-2 타입 스케일**: 용도 기반 토큰(`--fs-display / title / heading / body / caption / micro`)과 line-height·weight·letter-spacing 규칙을 정의한다. 임의값(`text-[15px]` 등)은 토큰으로 대체한다.
- **DS-3 컴포넌트**: 버튼(primary/secondary/ghost/danger × md/lg), 카드(flat/raised/interactive), 칩/태그를 CSS 클래스(`.btn`, `.card`, `.chip`)로 일원화한다. `dom.js button()` 헬퍼는 시그니처를 유지하고 내부 클래스만 교체한다.
- **DS-4 시각적 위계**: 화면당 주(主) 행동 1개 원칙, 제목·본문·보조 정보의 크기·색 대비 3단계, 학습 세션에서는 영단어를 최상위로 강조한다.
- **DS-5 반응형 여백**: 간격 토큰(4px 배수) 정의, `sm`(≥640px) 이상에서 컨테이너 여백·카드 패딩·핵심 글자 크기를 한 단계 키운다. 모바일(360~430px)이 기준이며 데스크톱은 보정만 한다.
- **DS-6 비기능**: 터치 타깃 44px, 입력 16px, 본문 대비 WCAG AA(4.5:1), 다크 모드 동등 지원, `prefers-reduced-motion` 유지.

## 3. 결정이 필요한 사항 (승인 시 함께 답변 요청)

1. **폰트 선택과 로딩 방식**
   - A안 (추천): **Pretendard Variable**(한글+라틴 통합, 한국 서비스 표준) — jsDelivr dynamic-subset CSS로 CDN 로드. 영단어 표시도 Pretendard 800으로 통일. 가장 단순하고 빌드 불필요.
   - B안: 본문 Pretendard + 영단어 전용 Inter/Plus Jakarta Sans 추가. 영단어 개성은 좋지만 요청 1개·FOUT 증가.
   - C안: 셀프호스팅(`src/frontend/fonts/`). 외부 의존 없지만 용량·라이선스 파일 관리 필요.
2. **Tailwind 설정 방식**: Play CDN `tailwind.config`로 `fontFamily`/`fontSize`를 확장(추천) vs. CSS 변수만 사용하고 Tailwind는 레이아웃 유틸 전용으로 제한.
3. **브랜드 컬러(Indigo) 유지 여부**: 이번 범위는 유지(추천). 변경하면 다크 오버라이드·차트·테스트 전체에 파급됨.
4. **UIUX 설계서 반영 시점**: 구현 후 v2.2 개정본 초안을 `ai-agent/claude/`에 작성(`docs/` 직접 수정 금지, 승인 후 승격).

## 4. 단계별 구현 계획 (TDD, 단계마다 독립 커밋 후보)

공통: 각 단계는 (1) 실패하는 검사 테스트 작성 → (2) 구현 → (3) 영향 범위 테스트 → (4) 시각 확인 순서. 커밋은 사전 승인 후.

### 단계 0 — 기준선 확보
- `pytest -q` 전체, `node --test tests/` 전체를 현재 상태로 실행해 통과 건수를 기록한다(회귀 비교 기준).
- 주요 화면(로그인, 홈, 탐색, 세션 퀴즈/플래시카드, 결과, 통계, 복습함) 라이트/다크 × 375px/768px 스크린샷을 `ai-agent/claude/`에 보관한다(Before).

### 단계 1 — 디자인 토큰 정립 (`app.css`)
- Red: `design-tokens.test.js` 신설 — `:root`에 타입/간격/반경 토큰이 정의되어 있는지, `text-[NNpx]` 임의값이 JS에 남아 있지 않은지 검사.
- Green: `:root`에 `--font-sans`, `--font-display`, `--fs-*`, `--lh-*`, `--space-*`, `--radius-*` 추가. 기존 변수는 유지(하위 호환).
- 영향: CSS 추가만, 시각 변화 없음.

### 단계 2 — 폰트 도입
- `index.html`에 폰트 `<link>`(preconnect 포함) 추가, `body`에 `font-family: var(--font-sans)`. 영단어(`.session-term`, 플래시카드 앞면)에 `--font-display`.
- 검증: `font-display: swap` 확인, 오프라인/CDN 실패 시 시스템 폰트 폴백 확인, 한글 줄바꿈(`word-break: keep-all`) 적용.
- 테스트: `index.html`에 폰트 링크·폴백 체인이 있는지 검사하는 정적 테스트.

### 단계 3 — 타입 스케일 적용
- 뷰 JS의 `text-xs/sm/base/lg…`와 임의값을 의미 클래스(`.t-title`, `.t-body`, `.t-caption` 등)로 점진 치환. **화면 단위로 나눠** 진행: 세션 → 홈 → 탐색 → 통계/복습 → 인증 화면.
- 치환 후 `dark-theme.test.js` 통과 확인(색 클래스를 건드릴 때 다크 규칙 동반).

### 단계 4 — 버튼·카드·칩 컴포넌트 일원화
- Red: 인라인 `bg-indigo-600` 버튼이 `dom.js` 외 파일에 남아 있지 않다는 검사 테스트(현재 `app.js` 2건, `explore-view.js` 1건이 걸림).
- Green: `.btn`(+variant/size), `.card`(+variant), `.chip` 정의. `button()` 내부 교체, `.surface/.session-card/.stat-cell/.count-choice` 반경·패딩을 카드 토큰으로 통합.
- 다크: 변수 기반으로 작성해 오버라이드 추가량을 최소화. `dark-theme.test.js`가 새 클래스도 검사하도록 확장.

### 단계 5 — 시각적 위계·반응형 여백
- 화면별 주 행동 버튼 1개 강조, 보조 정보 `--muted` 일원화, 세션 화면 영단어/뜻/선지 위계 재조정.
- `sm:` 브레이크포인트에서 컨테이너·카드 패딩·`--fs-display` 확대. 하단 탭바·피드백 시트와의 겹침(safe-area, `pb-24`/`has-sheet` 17rem) 재검증.

### 단계 6 — 검증 및 문서
- 전체 `pytest -q`, 전체 `node --test tests/` 실행해 단계 0 기준선과 비교. 백엔드는 변경 없으므로 회귀 확인 용도.
- 시각 확인: 단계 0과 같은 매트릭스로 After 스크린샷, 대비 비율 점검.
- 일지(`일지_YYMMDD_…`) 작성, UIUX 설계서 v2.2 개정 초안(`ai-agent/claude/`) 작성. `docs/` 승격은 별도 승인.
