# 작업계획 - 앱 컨테이너화 (개발용 + 배포용 이미지)

- 작성일: 2026-11-24
- 상태: **초안 (사용자 승인 대기)**. 승인 전에는 파일 생성·docker 명령을 실행하지 않는다.
- 관련: Architecture Design v1.0 A2(앱 미컨테이너화), A4(CDN 의존), CLAUDE.md §4 원칙 7

## 1. 목표

1. 하나의 Dockerfile 로 **개발용(dev)** 과 **배포용(prod)** 이미지를 모두 만든다 (멀티스테이지).
2. 개발: 호스트에 Python 없이 컨테이너 안에서 서버 실행(`--reload`), pytest, alembic 을 수행한다.
3. 배포: 다른 PC/서버에서 `docker compose up` 으로 DB + 앱을 재현 가능하게 실행한다.

## 2. 현재 상태 (조사 결과)

| 항목 | 현황 | 컨테이너화 영향 |
| :--- | :--- | :--- |
| DB | `docker/docker-compose.yml` 의 mysql:8.0 만 컨테이너 | 앱 서비스 추가 |
| 앱 | 호스트 `.venv` 의 uvicorn, Python 3.12 | 베이스 이미지 `python:3.12-slim` |
| 프론트 | FastAPI `StaticFiles` 가 같은 출처로 서빙 | 앱 컨테이너 하나로 충분 |
| 설정 | `core/config.py` 가 루트 `.env` 읽기, 환경 변수가 우선 | 컨테이너는 `.env` 없이 환경 변수 주입 |
| 시드 | lifespan 에서 `init_system_seeds()` 적재 | 마이그레이션이 먼저 끝나야 함 |
| 마이그레이션 | `src/backend/alembic.ini` | 별도 일회성 서비스로 실행 |
| 의존성 | `requirements.txt`(런타임), `requirements-dev.txt` | prod 는 런타임만, dev 는 dev 포함 |
| 외부 자원 | ~~Tailwind CDN, jsdelivr 폰트·SweetAlert2~~ → `src/frontend/vendor/` 로 자체 호스팅 완료(2026-11-24, 커밋 전) | 이미지에 모두 포함됨 |

## 3. 설계

### 3.1 파일 구성 (신규)

```text
docker/
├── Dockerfile              # 멀티스테이지: base → dev → prod
├── docker-compose.yml      # (수정) mysql + migrate + app (prod 기준)
└── docker-compose.dev.yml  # (신규) dev 덮어쓰기: 소스 마운트, --reload, tools
.dockerignore               # (신규, 루트) .venv .env .git ai-agent docs 등 제외
```

### 3.2 Dockerfile 스테이지

- `base`: python:3.12-slim, 환경 변수(`PYTHONUNBUFFERED`, `PYTHONDONTWRITEBYTECODE`, `TZ`), `requirements.txt` 설치.
  의존성 파일만 먼저 복사해 설치하여 소스 변경 시 의존성 레이어 캐시를 재사용한다.
- `dev`: base + `requirements-dev.txt`. 소스는 복사하지 않고 볼륨 마운트. `CMD uvicorn --reload`.
- `prod`: base + `src/` 복사. 비root 사용자(`app`) 실행. `CMD uvicorn --proxy-headers --host 0.0.0.0`.

### 3.3 compose 서비스

- `mysql`: 기존 유지. 컨테이너 내부 통신은 3306, 호스트 노출 포트는 `.env` 의 `MYSQL_PORT`.
- `migrate`: prod 이미지로 `alembic upgrade head` 실행 후 종료(`restart: "no"`). mysql healthy 후 시작.
- `app`: `depends_on: migrate (service_completed_successfully)`. `MYSQL_HOST=mysql` 주입. `/health` 로 healthcheck.
- dev 덮어쓰기: `app` 을 dev 타깃으로 바꾸고 `./src:/app/src` 마운트, `--reload`.
  테스트·alembic 은 `docker compose run --rm app pytest ...` 형태로 실행.

### 3.4 핵심 함정과 대응

| 함정 | 대응 |
| :--- | :--- |
| 컨테이너 안의 `127.0.0.1` 은 자기 자신 | `MYSQL_HOST=mysql`(서비스 이름) 주입 |
| 앱이 DB 보다 먼저 떠서 실패 | healthcheck + `depends_on` 조건 |
| 시드 적재가 테이블 생성 전에 실행 | `migrate` 완료 후 `app` 시작 |
| `.env` 가 이미지에 포함되어 비밀번호 유출 | `.dockerignore` 로 제외, compose `env_file` 로 주입 |
| 테스트가 개발 DB 를 지울 가능성 | 구현 전 `conftest.py` 가 어떤 DB 를 정리하는지 확인, 필요하면 테스트 전용 DB 분리 |
| 여러 앱이 동시에 마이그레이션 | 마이그레이션은 `migrate` 서비스 1회만 |

- **A4 CDN 의존**: 해소됨(vendor/ 자체 호스팅). 남은 것은 Tailwind Play 스크립트의 운영 비권장 문제(정적 CSS 생성은 지침과 충돌, 별도 결정). 문서 초안: `검토_261124_CDN_자체호스팅_문서반영초안.md`.

- **HTTPS**: 인터넷에 노출한다면 4단계가 필수, 사내/LAN 이면 HTTP + `COOKIE_SECURE=false` 로 생략 가능.

## 7. 0단계 확인 결과 (2026-11-24)

| 항목 | 결과 |
| :--- | :--- |

| 테스트 DB | **개발 DB 와 같은 DB**(`voda_voca`)를 쓴다. 격리는 DB 분리가 아니라 이름 규칙이다: 계정 닉네임 `tvoda-%`, 단어장 slug `tvoda-` 로 시작하는 행만 테스트 전후에 지운다. 컨테이너에서 pytest 를 돌려도 같은 DB 이므로 현재와 동작이 같다. 개발 DB 와 완전히 분리하려면 테스트 전용 DB(`voda_voca_test`)가 필요하다(선택, 별도 결정) |

### 이 결과가 계획에 미치는 영향
- 3단계(dev 컨테이너): 테스트를 컨테이너에서 돌려도 지금과 동일하게 `voda_voca` 를 쓰므로 추가 조치 없이 진행 가능. 테스트 전용 DB 분리는 선택 과제로 둔다.
- 2단계: 기존 `voda-voca-mysql` 컨테이너와 이름·포트·볼륨이 겹치므로, compose 를 수정해 다시 띄울 때 **기존 볼륨(개발 데이터)을 유지**해야 한다. `docker compose down -v` 금지.
- 개발 DB 에 학습 기록이 있을 수 있으므로, 2단계 전에 덤프 백업을 권한다 (`ai-agent/backups/`, 커밋 금지 경로).

## 11. 4단계 결과 (2026-11-25)

- **결정(사용자)**: HTTPS 불필요(`COOKIE_SECURE=false` 유지, 사내망·LAN 전용), `Cache-Control` 포함, 전달 방식은 **① git clone 후 빌드**. 그래서 계획의 "리버스 프록시(Caddy)"는 하지 않았다.
- **Cache-Control**: `main.py` 의 `FrontendStaticFiles` 가 `vendor/` 응답에만 `public, max-age=31536000, immutable` 을 붙인다(200·304 모두). `app.js`·`app.css`·`index.html` 은 그대로(ETag 재검증). 이유: vendor 는 경로에 버전이 있어 바뀌면 경로가 바뀐다. 테스트 3건(Red 2건 확인 후 Green).
- **필수 변수 검사**: 앱·migrate 의 `MYSQL_DATABASE/USER/PASSWORD` 를 `${VAR:?.env 파일에 ... (cp .env.example .env)}` 로 바꿔, `.env` 없이 실행하면 빈 비밀번호로 조용히 뜨는 대신 안내 메시지와 함께 중단된다. 테스트 6건(Red 6건 → Green). **`mysql` 서비스 정의는 바꾸지 않아** 기존 DB 컨테이너는 재생성되지 않는다.

- **열린 점**
  1. **DB 포트 노출**: `mysql` 이 `MYSQL_PORT` 를 모든 인터페이스(0.0.0.0)에 연다. LAN 배포에서는 같은 망의 누구든 DB 에 접속을 시도할 수 있다. 앱 컨테이너는 내부 네트워크(`mysql:3306`)로 접속하므로 호스트에 열 필요가 없다. 개발 편의(호스트 pytest·uvicorn)를 위해 열어 둔 것이라, `127.0.0.1:${MYSQL_PORT}:3306` 로 좁히는 안을 제안한다. 단 `mysql` 정의가 바뀌어 **DB 컨테이너가 한 번 재생성**된다(볼륨은 유지). → 사용자 결정 대기.
  2. 이미지 `voda-voca:prod` 태그는 시뮬레이션 빌드로 다시 만들어졌다(내용은 동일 소스).
  3. 브라우저에서의 실제 렌더링(폰트·아이콘·스타일)은 여전히 사용자 눈 확인이 필요하다.
