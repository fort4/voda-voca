### 1.2 보이스 선택 (신규 핵심)

- `speechSynthesis.getVoices()` 는 브라우저에 따라 **처음에 빈 배열**을 주고 이후 `voiceschanged` 로 채워집니다(Chrome). Safari 는 동기적으로 주는 경우가 많고, Firefox 는 OS 음성에 의존합니다.
- 선택 규칙(순수 함수 `pickVoice(voices, preferred)`로 분리해 단위 테스트):
  1. 선호 언어 순서 `["en-US", "en-GB"]` 의 정확 일치(`voice.lang` 의 `_`/`-` 표기 차이 정규화: Android 는 `en_US`)
  2. 같은 순서에서 `localService === true` 우선(오프라인에서도 재생)
  3. 없으면 `en-*` 아무 보이스, 그것도 없으면 `null`(→ `utterance.lang` 만 지정하고 브라우저 기본에 맡김)
- 초기화: 생성 시점에 한 번 읽고, `voiceschanged` 리스너(`addEventListener` 우선, 없으면 `onvoiceschanged`)로 캐시 갱신. 보이스 준비를 **기다리며 재생을 막지 않습니다**(빈 목록이어도 `lang` 으로 재생).

### 1.3 "AudioContext 잠김" 전제 바로잡기

`speechSynthesis` 는 `AudioContext` 를 쓰지 않습니다. 자동재생 제한은 다른 형태로 나타납니다.

- 사용자 제스처 밖에서 `speak()` 를 부르면 일부 브라우저가 `onerror` 의 `error: "not-allowed"` 로 거부합니다. → **자동 재생은 하지 않고 탭/클릭 핸들러 안에서만 호출**하는 것을 원칙으로 합니다. 이 원칙은 코드 리뷰와 테스트(`호출은 핸들러에서만`)로 고정합니다.
- `AudioContext` 잠금은 이미 `core/sound.js`(정답 효과음)가 따로 다룹니다. TTS와 섞지 않습니다.
- `cancel()` 이 진행 중 발화를 끊을 때 브라우저가 `onerror` 에 `interrupted`/`canceled` 를 보내는 것으로 알려져 있습니다. **현재 코드는 이를 모두 `warn` 으로 남기므로** 연타 때 콘솔 경고가 쌓일 가능성이 있습니다(실제 브라우저에서 확인 필요). 새 코드는 `interrupted`·`canceled` 는 정상 종료로 보고 조용히 처리하고, `not-allowed`·`synthesis-failed` 등만 경고합니다.

### 1.4 알려진 브라우저 변수 (구현에서 방어, 단위 테스트로 증명 불가한 부분은 수동 점검)

| 변수 | 대응 |
| :--- | :--- |
| Chrome: `cancel()` 직후 `speak()` 가 드물게 무시됨 | 현재 방식(취소 후 즉시 발화) 유지하되, 수동 점검 항목에 포함. 문제가 재현되면 그때 `setTimeout 0` 지연을 도입 |
| Chrome: 긴 발화가 약 15초 후 멈춤 | 예문 최대 500자(DB `String(500)`). 일반 예문은 짧아 이번에는 분할하지 않고 위험으로만 기록 |
| `paused` 상태가 남아 이후 재생이 안 됨 | `speak` 전에 `synth.resume?.()` 호출 여부는 수동 점검 후 결정 |
| Firefox/일부 Linux: 영어 보이스 없음 | `pickVoice` → `null`, 재생 실패 시 사용자에게 한 번만 안내 토스트(아래 §3 결정 3) |

## 2. 설계

### 2.1 `core/tts.js` API (하위 호환 추가형)

```
createSpeaker(deps) → {
  isSupported(), speak(text, overrides), cancel(),        // 기존: 그대로 동작
  speakWord(text, key?), speakSentence(text, key?),        // 신규: 단어/문장 프리셋
  stop(),                                                  // 신규: cancel 의 의미 있는 이름(별칭)
  getVoice(),                                              // 신규: 현재 선택된 보이스(테스트·진단용)
  subscribe(listener) → unsubscribe,                       // 신규: {status:"idle"|"speaking", key} 변경 통지
}
```

- 프리셋: 단어 `rate 0.9`(REQ-125 유지), 문장 `rate 0.85`(제안, 결정 4). 둘 다 `pitch 1.0`.
- `key`: 어떤 버튼이 재생 중인지 구분하는 식별자(예: `"word:123"`, `"example:123"`). 같은 화면에 버튼이 여러 개여도 해당 버튼만 Playing 표시.
- 상태 전이: `speak` 성공 → `onstart` 에서 `speaking`, `onend`/`onerror` 에서 `idle`. `cancel` 후 새 발화가 이어질 때 `idle` 이 깜박이지 않게, 새 발화의 `onstart` 가 오기 전까지는 `key` 만 즉시 `speaking(pending)` 으로 둡니다(옵티미스틱) — 연타 시 깜박임 방지.
- 전역 편의 함수: `speakWord`, `speakSentence`, `stopSpeaking`, `subscribeSpeaking` 를 `speaker` 위임으로 export. 기존 `speak(text)` 유지.
- 파일 크기: 현재 70줄 → 약 170줄 예상(500줄 한도 내, 분리 불필요). `pickVoice` 는 같은 파일의 export 순수 함수.

### 2.2 UI

- **공용 버튼 컴포넌트** `views/components/speak-button.js`: `speakButton({ text, kind: "word"|"sentence", key, label, size })`. 내부에서 `subscribe` 로 `is-playing` 토글, `aria-pressed`, 아이콘(`volume-2` ↔ 재생 중 파동). 화면이 사라지면 구독 해제(메모리 누수 방지) — 호출 측이 반환된 `dispose` 를 쓰거나, 컴포넌트가 `isConnected` 를 확인해 자동 해제.
- **터치 타깃**: `.btn` 계열에 `.btn-icon`(44×44 정사각, 아이콘 전용) 변형을 더해 기존 손으로 쓴 `h-11 w-11 …` 아이콘 버튼과 36px 해설 시트 버튼을 통일합니다. `.btn-icon` 은 `var()` 토큰만 쓰므로 기존 `dark-theme.test.js` 검사(`componentsWithoutDarkSupport`)에 걸리게 `.btn-` 접두를 사용합니다.
- **Playing 표시 CSS**: `.speak-btn.is-playing` — 강조색(`--accent`) + 아이콘 맥동(`@keyframes`, `prefers-reduced-motion` 에서는 애니메이션 없이 색만). 색은 토큰만 사용.
- **배치**

| 화면 | 버튼 | 비고 |
| :--- | :--- | :--- |
| 세션 헤더 | 표제어(기존 위치 유지) | 컴포넌트로 교체, Playing 표시 추가 |
| 플래시카드 뒷면 | 예문 | 뒤집힌 뒤에만 보임. 카드 탭(뒤집기)과 겹치지 않게 `stopPropagation` |
| 피드백 시트 | 표제어(기존), **예문(신규)** | 36px → 44px |
| 단어 바텀시트 | 행마다 표제어, 예문이 있으면 예문 | 행 전체 탭 영역과 구분 |

- **정지 시점**(`stop()`): 다음 문항으로 이동, 피드백 시트 닫힘, 세션 종료·중단, 단어 시트 닫힘(`close()`), 탭 이동(라우트 변경), `visibilitychange: hidden`/`pagehide`. 이를 한 곳에서 걸 수 있게 `app.js` 라우터 훅에 `stop` 한 줄을 둡니다(세부는 구현 때 확인).

## 3. 결정이 필요한 사항 (승인 시 함께 답변)

1. **보이스 선택 UI**: 이번에는 UI 없이 자동 선택(`en-US` 우선, 없으면 `en-GB`, 그다음 `en-*`) — **추천**. 설정에서 억양 선택 토글(`localStorage`)은 후속.
2. **버튼 위치**: 헤더 🔊 유지 + 해설 시트·플래시카드 뒷면에 예문 버튼 추가 — **추천**. 대안은 표제어 바로 옆(`.session-term` 옆)으로 이동하는 것인데 화면 위계가 바뀌므로 별도 과제로 미룸.
3. **재생 실패 안내**: 영어 보이스가 없거나 `not-allowed` 일 때 세션당 한 번 토스트("이 기기에서는 발음을 재생할 수 없어요") — **추천**. 조용히 무시하는 현 방식은 사용자가 원인을 모릅니다.
4. **예문 속도**: 단어 0.9 / 문장 0.85 — **제안**(REQ-125 의 0.9 는 표제어 기준으로 유지).
5. **문서**: REQ-125 를 확장(예문·재생 상태·보이스 선택)하려면 요구사항 명세 v2.2 개정이 필요합니다. 구현 후 `ai-agent/claude/` 에 v2.2 초안을 쓰고, 승인 시 승격 — **추천**. UI/UX 설계서(v2.2 승격본)는 §3.6·§12 에 재생 상태 컴포넌트를 추가해 v2.3 이 아니라 같은 v2.2 의 **개정 2차**로 다룰지 함께 결정해 주세요.

## 5. Node 환경 Web Speech 목(Mock) 설계

외부 라이브러리 없이 `tests/helpers/fake-speech.js` 로 둡니다(기존 `tts.test.js` 의 `fakeSynth` 를 일반화).

- `FakeUtterance`: `text, lang, rate, pitch, voice` 와 `onstart/onend/onerror` 슬롯.
- `FakeSynth`: `speak(u)` 는 대기열에 넣기만 하고 **자동으로 끝내지 않음**. 테스트가 `synth.start()` / `synth.finish()` / `synth.fail("not-allowed")` 로 이벤트를 **결정적으로** 발생시킴. `cancel()` 은 진행 중 발화에 `onerror({error:"interrupted"})` 를 보내 실제 브라우저 동작을 흉내 냄.
- 보이스: `setVoices([...])` 후 `emitVoicesChanged()` 로 `voiceschanged` 를 수동 발화. 초기 빈 배열 → 이후 채움 시나리오를 재현.
- 주입 지점은 기존과 같은 `createSpeaker({ synth, UtteranceCtor, warn })` 하나이므로 `globalThis` 를 오염시키지 않습니다. 타이머를 쓰지 않아 가짜 시계가 필요 없습니다.
- 한계: 실제 오디오 출력, 브라우저별 `cancel` 타이밍·15초 끊김은 목으로 증명할 수 없으므로 §4 단계 6 수동 점검으로 보완.
