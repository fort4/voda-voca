1. 떠 있던 `voca` 컨테이너(이미지 `voca-app`)는 소스가 이미지에 복사된 운영형이라 코드를 고쳐도 반영되지 않는다. `docker update` 는 자원 설정만 바꾼다. 개발할 때는 dev compose(소스 마운트, `--reload`)를 쓴다.
2. 프로젝트 루트(`/home/ade/dev/voda-voca`)에서 실행해야 compose 상대 경로가 맞는다.
3. `.env` 가 MySQL 시절 형식이라 `SECRET_KEY` 가 없었다. 사용자가 한 줄을 덧붙였다(`MYSQL_*` 는 그대로 둠).
4. **dev 이미지는 시작할 때 마이그레이션을 하지 않는다**(운영 이미지의 `docker-entrypoint.sh` 에만 있음). 빈 볼륨(`voda-voca-data`)에서는 `no such table` 로 시작 실패. 아래 명령을 한 번 실행했다(볼륨에 남아 있어 반복 불필요).
   ```bash
   dc=(docker compose --project-directory . -f docker/docker-compose.yml -f docker/docker-compose.dev.yml)
   "${dc[@]}" run --rm app alembic -c src/backend/alembic.ini upgrade head
   "${dc[@]}" restart app
   ```
   개선 후보: dev 에서도 시작 때 마이그레이션 적용. `test_container_files.py` 가 Dockerfile·compose 를 고정 검사하므로 별도 작업으로 다룬다.
5. 현재 `voda-voca-app`(dev 모드)이 8080 에서 떠 있다. 기존 `voca` 컨테이너와 `voda-voca-mysql` 은 중지 상태다(MySQL 정리는 결정 대기 항목).
