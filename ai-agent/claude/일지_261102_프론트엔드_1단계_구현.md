## 2. 기술 구조 (No-build ES 모듈)

- **빌드 없음**: `index.html`이 `<script type="module" src="js/app.js">`를 로드합니다. 번들러 없이 브라우저가 ES 모듈 경로를 직접 해석합니다 (CLAUDE.md §1).
- **외부 의존성은 CDN 한정**: Tailwind Play CDN, SweetAlert2 11.10.5, Lucide 0.263.1을 씁니다. npm 패키지는 설치하지 않습니다.
- **`package.json`은 테스트 진입점만 둠**: `"type": "module"`과 `"test": "node --test tests/"` 스크립트만 있으며 `dependencies`는 없습니다.
- **모듈 분할**
  - `core/`: 화면과 무관한 공통 기능 (API 클라이언트, 라우터, 상태, DOM 헬퍼, 토스트, 포맷, 검증, 폼)
  - `views/`: 화면 단위 (`login`, `signup`, `wordbooks`)
  - `app.js`: 부트스트랩, 라우트 정의, 상단바, 세션 만료 처리

## 3. 핵심 설계 결정

### 3.1 textContent 기반 DOM 렌더러 (XSS 방지)
- 모든 텍스트는 `document.createTextNode`로 넣습니다. `innerHTML`은 쓰지 않습니다 (`core/dom.js`의 `h()`).
- 서버 응답 값(단어장 이름, 설명, 닉네임)도 같은 경로를 탑니다.
- 모달 폼은 HTML 문자열이 아니라 DOM 요소를 SweetAlert2의 `html`에 넘깁니다. 수정 모달에 기존 값을 채울 때 문자열 이스케이프가 필요 없습니다.
- 수동 검증 항목 13번에서 `<img onerror>` 입력이 텍스트로만 보이는지 확인합니다.

### 3.2 해시 라우팅과 인증 가드
- 경로는 `#/login`, `#/wordbooks` 형태입니다. 서버는 해시를 보지 않으므로 SPA 새로고침에도 같은 화면이 유지됩니다.
- 라우트마다 `access`를 둡니다. `user`는 로그인 필요, `guest`는 로그인 상태면 단어장으로 보냄, `any`는 제한 없음입니다.
- 미로그인 상태로 보호 화면에 들어가면 `#/login?next=<원래 경로>`로 보냅니다.
- `next`는 `safeNext()`로 검사합니다. 같은 앱의 경로만 허용하고, `https://…`, `//…`, `javascript:` 등은 기본 경로로 바꿉니다 (열린 리다이렉트 방지). 단위 테스트 5건으로 확인합니다.
- 화면을 떠날 때 이전 화면의 정리 함수를 호출합니다. 429 카운트다운 타이머와 목록 요청 취소가 여기에 해당합니다.

### 3.3 공통 API 클라이언트 (`core/api.js`)
- 모든 요청에 `credentials: 'include'`를 붙입니다. 세션 쿠키는 JS에서 읽지 않습니다.
- **401**: 세션 만료 콜백을 부릅니다. 로그인 요청 자체의 401은 `skipAuthRedirect`로 제외합니다.
- **429**: `Retry-After`를 정수 초로 바꿔 `error.retryAfter`에 담습니다. 화면이 카운트다운을 담당합니다.
- **422**: `loc`의 마지막 문자열 요소를 필드 이름으로 씁니다. 모델 수준 오류(`loc`가 `["body"]`)는 필드가 `null`입니다.
- **시간 초과와 네트워크 오류**: 둘 다 `status 0`으로 바꿉니다. 시간 초과는 15초 기본값을 쓰며, 안내 문구가 다릅니다.
- **취소**: 호출자가 취소한 경우는 `AbortError`를 그대로 던집니다. 오류 화면으로 바꾸지 않습니다. 목록 화면을 떠날 때 이 경로를 씁니다.

### 3.4 429 카운트다운 (로그인)
- 429를 받으면 제출 버튼을 비활성화하고 `Retry-After` 초부터 1초마다 줄입니다. 문구는 `formatRetry()`가 만듭니다.
- 0이 되면 버튼을 다시 켜고 안내를 지웁니다.
- 카운트다운 중 입력을 고쳐도 서버는 비밀번호와 무관하게 차단하므로, 클라이언트 쪽에서 우회 제출을 허용하지 않습니다.
- 화면을 떠나면 `setInterval`을 정리합니다.

### 3.5 검증 규칙의 서버 정합
- `core/validate.js`의 제한값은 서버 스키마와 같습니다. 이메일 255자, 비밀번호 8자 이상과 **72바이트 이하**, 닉네임 50자, 단어장 이름 50자, 설명 200자.
- 72바이트 검사는 `TextEncoder`로 바이트를 셉니다. 한글 한 글자는 3바이트이므로 24자가 한계입니다. 25자 입력을 단위 테스트로 막는지 확인합니다.
- 서버 422는 `mapFieldErrors()`로 입력 칸별 오류에 붙입니다. 알려지지 않은 필드는 상단 배너(`_form`)로 보냅니다.
