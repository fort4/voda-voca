# 검토 — 앱 컨테이너화(Dockerfile·compose·개발용 override)의 `docs/` 반영 초안

`docs/` 는 승인 후에만 수정한다. 승인되면 아래대로 반영하고 각 문서의 변경 이력 행을 추가한다.
(구현·테스트는 완료. 컨테이너화 전체 경과는 `작업계획_261124_앱_컨테이너화.md` §7~§11.
기준선: 백엔드 pytest 587건, 프론트엔드 node 473건, 합계 1,060건 통과, `alembic check` 이상 없음)

## 변경 요약
- **앱을 컨테이너로 실행**한다. `docker/Dockerfile`(base → dev / prod 멀티스테이지, `python:3.12-slim`, 비root `app` uid 1000, prod 에 `/health` 헬스체크)과 compose 서비스 `migrate`·`app` 을 추가했다. 기동 순서는 `mysql`(healthy) → `migrate`(`alembic upgrade head` 1회 후 종료) → `app`(시작 시 시드 멱등 적재).
- **개발용 컨테이너**: `docker/docker-compose.dev.yml` 이 dev 이미지로 `./src` 를 마운트해 `--reload` 로 실행하고, 컨테이너 안에서 pytest·`alembic check` 를 돌린다. 저장소 전체와 `.env` 는 마운트하지 않는다.
- **설정 주입**: `.env` 를 통째로 넘기지 않고 앱에 필요한 변수만 `environment` 로 둔다. 루트 비밀번호는 앱에 전달하지 않고, 컨테이너 안에서는 DB 를 `mysql:3306` 으로 찾는다. 필수 3개(`MYSQL_DATABASE/USER/PASSWORD`)가 비면 안내 메시지와 함께 중단한다.
- **다른 PC 배포**: Docker 와 Git 만 있으면 `git clone` → `.env` 작성 → `up -d --build` 한 번으로 실행된다(HTTP 전용, 사내망·LAN). 빈 DB 에서 마이그레이션 12개가 처음부터 적용되고 시드가 적재됨을 시뮬레이션으로 확인했다(2026-11-25).
- **보안·정적 서빙**: `mysql` 호스트 포트는 `127.0.0.1` 에만 연다. `vendor/` 응답에 1년 캐시 헤더, woff2 MIME(`font/woff2`) 직접 등록.
- 효과: A2(앱 미컨테이너화) 해소, "다른 컴퓨터에서 동일 환경" 재현 가능.
- 남는 한계: **HTTPS 미지원**(LAN 전용 가정), 이미지에 DB 데이터가 들어 있지 않음(백업·복원 절차 필요), Tailwind Play 스크립트(ADR-007 결정 5 의 잔여).

### 2. `Decision_Records_v1.0_261119.md`
**결정 목록 표**에 행 추가: `ADR-009 | 앱 컨테이너화: 멀티스테이지 이미지, 최소 환경 주입, 개발용 override | Accepted | 2026-11-25 | REQ-116, 117, 152, 112`

**ADR-007 에 결정 6 추가** (정적 서빙, 2026-11-25): `vendor/ 응답에만 Cache-Control: public, max-age=31536000, immutable 을 붙이고(버전이 경로에 있어 안전), app.js·app.css 는 ETag 재검증을 유지한다. woff2 MIME(font/woff2)은 OS mime.types 가 없는 컨테이너에서도 같도록 앱이 직접 등록한다.`

**새 ADR-009 본문 (초안)**
- **상태**: Accepted (2026-11-25, 사용자 확정). **관련 요구사항**: REQ-116, 117, 152, 112
- **배경**: 앱이 호스트 `.venv` 에서만 실행되어 다른 PC 에서 환경을 재현할 수 없었다(Architecture A2). 사용자는 개발 환경까지 컨테이너로 옮기고, HTTPS 없이 사내망의 다른 PC 에서 실행하길 원했다.
- **결정**
  1. 하나의 `docker/Dockerfile` 에 `base`(공통 의존성) → `dev`(테스트 도구, 소스 마운트) / `prod`(소스 복사, 헬스체크) 를 둔다. `python:3.12-slim`, 비root `app`(uid 1000).
  2. 마이그레이션은 앱 시작과 분리한다: `migrate` 서비스가 `alembic upgrade head` 를 1회 실행하고, `app` 은 `service_completed_successfully` 뒤에 시작한다.
  3. 앱·migrate 에는 `env_file` 을 쓰지 않고 필요한 변수만 `environment` 로 주입한다. 컨테이너 안의 DB 주소는 `mysql:3306` 으로 고정한다. 필수 3개는 `${VAR:?메시지}` 로 누락 시 중단한다.
  4. 개발용 override(`docker-compose.dev.yml`)는 `./src` 와 테스트가 읽는 파일만 마운트한다. 저장소 전체·`.env` 는 마운트하지 않는다.
  5. 전달 방식은 **`git clone` 후 현지 빌드**, HTTP 전용(사내망·LAN, `COOKIE_SECURE=false`). 이미지 레지스트리·HTTPS 는 도입하지 않는다.
  6. `mysql` 의 호스트 포트는 `127.0.0.1` 에만 연다. 앱은 내부 네트워크로 접속한다.
- **대안**
  | 대안 | 장점 | 단점 | 판정 |
  | :--- | :--- | :--- | :--- |
  | `env_file: .env` 로 통째 주입 | 설정이 간단 | 루트 비밀번호와 호스트용 `MYSQL_HOST=127.0.0.1`·`MYSQL_PORT=3307` 이 앱 컨테이너로 들어가 DB 주소를 덮어쓴다 | 기각 |
  | 앱 시작 때 마이그레이션 자동 실행 | 서비스가 하나 줄어든다 | 인스턴스가 늘면 마이그레이션이 경합한다. 실패 원인이 앱 로그에 섞인다 | 기각 |
  | 저장소 전체를 dev 컨테이너에 마운트 | 설정이 가장 단순 | `.env`(루트 비밀번호)가 컨테이너에 노출된다 | 기각 |
  | 이미지 레지스트리(GHCR 등) / `docker save` | 소스 없이 실행, 오프라인 가능 | 계정·절차 추가, 현재 규모에 과함 | 보류(필요 시 추가) |
  | 리버스 프록시 + HTTPS | 비밀번호 보호, 인터넷 공개 가능 | 인증서·컨테이너 추가, 이번 범위 밖 | 보류(A10) |
  | **멀티스테이지 + migrate 분리 + 최소 environment** | 재현성·보안·캐시 효율 | 이미지 빌드가 필요하다 | **채택** |
- **결과**: 호스트에 Python 이 없어도 개발·테스트가 된다(컨테이너 안 pytest 578건 통과 확인). 새 PC 는 빈 DB 로 시작하므로 데이터 이전은 수동이다(A11). HTTP 전용이므로 공개망에는 쓸 수 없다(A10). 이미지는 개발용(375MB)·배포용(360MB) 두 종류다.

**변경 이력 행**: `v1.0 개정 | 2026-11-25 | ADR-009(앱 컨테이너화) 추가, ADR-007 에 결정 6(vendor 캐시·woff2 MIME) 추가 | Claude`
