## 1. 문제

지표 계산을 프론트엔드가 `/study/logs`의 최근 100건만 받아 했고, 서버의 오답 복습 출제도 같은 100건 규칙이었다.

| 증상 | 원인 | 결과 |
| :--- | :--- | :--- |
| 단어장 진행률 상한 | 100건 로그로 "맞힌 단어 수"를 셈 | 200단어장 최대 50%, 1,000제 최대 10% |
| 연속 학습일·주간 차트 과소 집계 | 날짜별 집계를 100건 안에서 함 | 하루 100문항 넘게 풀면 이전 날짜가 사라짐 |
| 오답 복습이 줄지 않음 | 최근 100건 중 한 번이라도 틀린 단어를 오답으로 침 | 복습에서 맞혀도 같은 단어가 반복됨 |
| 정답률 | 최근 100건 기준 | 오래 쓸수록 실제와 달라짐 |

## 2. 결정과 근거 (사용자 승인)

- **집계 방식 A (읽을 때 SQL 집계)**: 스키마 변경이 없고 이중 기록 불일치가 없다. B(단어별 요약 테이블)는 #1, #15의 요구가 정해지지 않았고, 개발 DB는 57행뿐이라 성능 근거도 없으며, REQ-016(단어별 누적 카운터 없음)을 뒤집는다. 연속 학습일·7일 차트는 날짜별 집계라 B로도 로그 집계가 필요하다. `study_logs`가 원본이라 나중에 B로 전환은 가능하다(백필 → 이중 기록 → 집계 모듈 교체).
- **전환을 싸게 하는 구조**: 집계를 `services/stats.py` 한 모듈에 모으고, 라우터와 퀴즈 출제는 그 함수만 부른다. 로그 기록을 `services/study_log.add_study_log` 한 곳으로 통합했다(기존에 `record_answer`, `submit_quiz` 두 곳에서 각자 `StudyLog`를 만들었고 #17로 세 번째 경로가 생길 예정이다).
- **범위**: 정확도 바로잡기만. 월간 추이, 취약 단어 목록, 단어별 이력은 #18로 분리.
- **지표 정의**: 오답 단어 = 단어별 마지막 결과가 오답, 진행률 = 한 번이라도 맞힌 단어 / 단어 수(현행 유지), 정답률 = 누적, 연속 학습일 = 하루 1문항 이상(한국 날짜, 오늘 안 풀었으면 어제부터).

## 3. 변경

**백엔드**
- `GET /api/study/stats` (신규): `answered, correct, accuracy(null 가능), streak_days, weekly[7](date,label,count,is_today), total_words, wordbook_progress[](wordbook_id,word_count,learned_words,percent), wrong_word_count`.
- `services/stats.py`: `wrong_word_ids`(윈도 함수 `ROW_NUMBER`로 단어별 마지막 결과), 누적 합계, 연속 학습일, 7일 활동, 단어장 진행률. 한국 날짜는 UTC 저장값에 9시간을 더해 `DATE`로 변환한다.
- `services/study.py`: `WRONG_REVIEW_WINDOW`, `_recent_wrong_word_ids` 제거. 퀴즈 출제가 `stats.wrong_word_ids`를 쓴다.
- `services/study_log.py`: `add_study_log`.
- 스키마 변경, 마이그레이션, 신규 인덱스 없음.

**프론트엔드**
- `core/stats-view.js`(신규): 서버 통계를 대시보드 카드, 이력 요약, 오답 복습 안내 문구로 바꾸는 순수 함수(`dashboardModel`, `historySummary`, `wrongReviewState`).
- 대시보드: 요청이 "단어장 전체 페이지 + 로그 100건"에서 "stats 1건"으로 줄었다. 정답률 힌트는 "최근 N문항" → "누적 N문항".
- 이력 화면: 요약이 누적 기준이 되었고 타임라인이 최근 100건임을 밝힌다. 오답 복습 개수는 서버 값.
- 퀴즈 설정: 오답 복습 가능 개수를 서버 값으로 표시(출제 규칙과 동일).
- 삭제한 죽은 코드: `core/stats.js`, `tests/stats.test.js`, `study-stats.js`의 `summarizeLogs`·`uniqueWrongWordIds`. `kstDayKeyOf`는 `backup.js`(파일 이름 날짜)가 쓰고 있어, 이미 있는 `format.js`의 `kstDateKey`를 쓰도록 바꿨다(파일 이름 테스트가 동작을 보장).

## 4. 테스트 (테스트 우선)

- 백엔드: `test_stats_api.py` 14건을 먼저 작성해 **15건 실패(Red, 기존 100건 창 테스트 1건 갱신 포함)** 를 확인한 뒤 구현해 통과. 150건 누적 정답률, 하루 30건 × 5일 연속 학습일, 어제부터 세기·끊김·그제만, 한국 자정 경계(14:59:59 / 15:00:00), 7일 창·같은 단어 중복·창 밖 제외, 150단어 단어장 진행률(100건 창이면 막혔을 값), 마지막 결과 규칙 4가지 경우, 창 없음, 오답 복습이 맞힐수록 줄어 4개 미만이면 시작 불가, 사용자 분리, 로그인 필요.
- 테스트가 구현 버그를 잡았다: `SUM(is_correct)`가 컬럼 타입(Boolean)을 따라 120이 `True`(=1)로 읽혔다. `CASE`로 정수 합계를 만들어 수정.
- 기존 `test_wrong_quiz_ignores_wrong_answers_older_than_the_100_log_window`는 없애는 규칙을 검증하던 테스트라 `...has_no_log_window_old_wrong_words_still_count`로 바꿨다.
- 프론트엔드: `stats-view.test.js` 8건을 먼저 작성해 모듈 없음으로 실패(Red)를 확인한 뒤 구현.
- 전체: 백엔드 328건, 프론트엔드 204건 통과.
- 실제 개발 DB(사용자 1명, 로그 58건)로 집계 확인: 오답 단어 수가 옛 규칙 18개 → 새 규칙 14개(복습에서 맞힌 단어가 빠짐).

## 5. 동작 변화 (사용자에게 영향)

- 오답 복습에서 맞히면 대상에서 빠지므로, "복습 가능한 오답 단어가 4개 미만" 상태가 이전보다 자주 나온다. 의도한 개선이다.
- 대시보드 정답률이 "최근 100문항"에서 "누적 전체"로 바뀌어, 오래 쓴 사용자의 숫자가 달라질 수 있다.
- 진행률이 100건에 막히지 않아 큰 단어장에서도 끝까지 오른다.

## 6. 한계와 미확인

- **브라우저 실사용 확인은 하지 않았다.** 대시보드, 이력, 퀴즈 설정 화면은 DOM 코드라 자동 테스트가 없다 (모듈 링크 검증과 순수 함수 테스트까지만).
- 성능은 측정하지 않았다 (현재 데이터 57행). 대시보드를 열 때마다 사용자 로그를 훑으므로 수만 건 규모에서는 측정이 필요하다. 필요하면 복합 인덱스(`user_id, word_id, created_at`)나 캐싱, 단어별 요약 테이블(B)을 검토한다.
- 플래시카드 학습은 #17 전까지 연속 학습일에 반영되지 않는다.
- 연속 학습일은 최대 약 10년(3,700일)까지 거슬러 센다.
