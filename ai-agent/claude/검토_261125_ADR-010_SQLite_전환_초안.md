# ADR-010 (초안) — 데이터베이스를 MySQL 8 에서 SQLite 로 전환

- 작성일: 2026-11-25
- 상태: 초안 (사용자 승인 후 `docs/voda-voca_Decision_Records` 새 버전에 반영)
- 관련: ADR-009(앱 컨테이너화), 작업계획_261125_SQLite_전환_및_기말과제_배포.md

## 배경
기말과제 서버 규칙이 DB 를 SQLite 로 제한한다(MySQL 등 기타 DB 불가, PostgreSQL 은 사전 협의 시에만). 서버는 컨테이너 쓰기를 `/data` 와 `/tmp` 로 제한하고 메모리 1GB, 실행 중 인터넷 차단 조건이다.

## 결정
SQLite 단일 파일 DB(`DB_PATH`, 기본 `/data/voca.db`)로 전환하고 드라이버는 `aiosqlite` 를 쓴다. MySQL 이중 지원은 하지 않는다. 과제용은 빈 DB 에서 시작하며 기존 MySQL 데이터는 이관하지 않는다.

## 연결 정책 (구현됨: `db/session.py`)
| 설정 | 이유 |
|---|---|
| `foreign_keys=ON` | 기본 꺼짐. 꺼져 있으면 ON DELETE CASCADE(회원 탈퇴, 단어장 삭제 연쇄)가 동작하지 않는다 |
| `journal_mode=WAL` | 읽기가 쓰기를 막지 않음 |
| `synchronous=NORMAL` | WAL 에서 안전하면서 쓰기 비용이 낮음 |
| `busy_timeout=5000` | 쓰기 충돌 시 즉시 실패하지 않고 대기 |
| `pool_pre_ping` 제거 | 서버가 없는 파일 DB 라 끊긴 커넥션 문제가 없음 |

## 결과와 대가
- 얻는 것: 제출 요건 충족, Docker DB 컨테이너 불필요, 테스트가 임시 파일 DB 로 빨라짐
- 잃는 것
  - 행 잠금(`SELECT ... FOR UPDATE`) 소멸 → 쓰기 직렬화는 SQLite 단일 쓰기자에 의존. 채점 중복 제출은 테스트로 검증한다
  - 콜레이션 기반 대소문자 무시 비교 소멸 → 닉네임은 NOCASE 유니크로 보장
  - 서버 확장성(다중 쓰기자)은 포기. 과제 규모(단일 컨테이너)에서는 문제없음
- 마이그레이션: MySQL 전용 리비전 12개를 SQLite 용 초기 리비전 1개로 재작성(후속 단계)

## 대체안
- PostgreSQL 17: 사전 협의가 필요하고 방언 전환 비용이 SQLite 와 비슷해 기각
- MySQL 유지: 과제 규칙상 불가
