## 2. 설계

### 2.1 사운드 큐 (data-driven)

현재 `playCorrect` 의 두 음을 하드코딩한 구조를 **큐 표**로 바꿉니다. 큐는 순수 데이터라 테스트가 쉽고 음색 조정이 코드 변경 없이 가능합니다.

| 큐 | 소리 | 구성 (제안값, 구현 시 귀로 조정) |
| :--- | :--- | :--- |
| `correct` | 상승 아르페지오 | C5(523.25) → E5(659.25) → G5(783.99), 간격 0.07s, 각 0.18s, sine |
| `milestone` | 4음 상승 | C5 → E5 → G5 → C6(1046.5), 간격 0.08s, 마지막 음 0.4s, sine+triangle |
| `wrong` | 저음 감쇠 드롭 | 196Hz → 130.8Hz 지수 하강 0.25s, 최대 음량 낮게(0.12), sine. 날카로운 어택 없이 부드럽게 |
| `complete` | 승리 팡파레 | G4 → C5 → E5 → G5 순차 후 C5+E5+G5 화음 0.6s 유지, triangle, 총 약 1.2s |

- **헤드룸**: 화음·겹침에서 클리핑되지 않게 공통 마스터 `GainNode`(약 0.6) 한 단을 두고 모든 음이 거기를 거쳐 `destination` 으로 갑니다. 음 하나당 최대 음량은 큐가 정합니다.
- **팝 노이즈 방지**: 기존 규칙 유지(0 대신 `0.0001` 에서 시작·종료, 지수 램프).
- **정리**: 음이 끝나면 노드 `disconnect` 로 GC 가 가능하게 합니다(`onended`).
- **정책은 엔진 밖**: 엔진은 `playCue(name)` 만 안다. "언제 어떤 큐를 내는가"는 §2.3 의 순수 함수가 정한다.
- **하위 호환**: `playCorrect()` 는 `playCue("correct")` 별칭으로 남깁니다. 단, 소리 자체가 두 음에서 아르페지오로 바뀌므로 `sound.test.js` 의 음 구성 단언(D5/A5)은 **의도된 변경으로 갱신**합니다.
- **구독**: `subscribe(listener)` 를 추가해 음소거가 바뀌면 모든 토글 버튼이 갱신되게 합니다(두 곳 이상에서 상태를 보이므로 필요).

### 2.2 `combo-model.js` (순수 함수)

러너와 UI 가 같은 계산을 쓰도록 **러너의 streak 산술을 이 모듈로 옮깁니다**(상태 필드명 `streak`/`bestStreak` 는 유지해 기존 러너 테스트·요약과 호환).

```
advanceCombo({count, max}, outcome)  // outcome: "correct" | "wrong" | "skip"
  → {count, max}                     // 정답 +1 / 그 외 0, max = Math.max
comboVisible(count)                  // count >= 2  (COMBO_MIN_VISIBLE)
isMilestone(count)                   // MILESTONES 에 포함 (제안: 5, 10, 15 — 세션이 15문항)
badgeView(prevCount, count)          // {visible, bounce, milestone, label} — bounce 는 count > prevCount 일 때만
soundCueFor(transition)              // 정책: 아래 표
```

`soundCueFor` 정책(단일 위치에서 테스트):

| 전이 | 큐 |
| :--- | :--- |
| 정답 응답, 콤보가 마일스톤에 닿음 | `milestone` (정답음을 **대체**, 겹치지 않음) |
| 정답 응답 | `correct` |
| 오답 응답 (**퀴즈 모드만**) | `wrong` |
| 플래시카드 "헷갈려요" | 무음 (자가 평가에 오답음은 벌처럼 느껴짐 — 결정 4) |
| 세션 완료 (중단 아님, 1문항 이상) | `complete` |
| 중단, 0문항, 오류, 건너뜀 | 무음 |

### 2.3 콤보 뱃지 UI

- **위치**: 진행 헤더 **바로 아래의 전용 줄**. 높이를 항상 확보해(예: 32px) 뱃지가 나타나도 카드가 밀리지 않습니다(레이아웃 시프트 방지). 360px 에서 헤더 한 줄에 넣기엔 폭이 부족하기 때문입니다(§2.4).
- **표시**: `🔥` 같은 이모지 대신 Lucide 아이콘(`flame`) + "N콤보". 마일스톤이면 한 단계 강한 스타일(`.combo-badge--milestone`).
- **바운스**: `@keyframes combo-pop`(scale 1→1.25→1, 약 320ms). 세션 화면은 상태가 바뀔 때마다 통째로 다시 그려지므로, **직전에 그린 콤보 값을 기억해 증가한 렌더에서만** 애니메이션 클래스를 붙입니다(그렇지 않으면 관련 없는 상태 변화에도 튐). `prefers-reduced-motion` 에서는 애니메이션 없이 표시만.
- **색**: 토큰만 사용(다크 모드 자동). 기존 `dark-theme.test.js` 의 컴포넌트 검사에 `.combo*` 접두를 추가.
- **접근성**: 해설 시트가 이미 `aria-live="assertive"` 로 연속 정답 문구를 읽으므로 뱃지는 `aria-hidden="true"`(시각 전용)로 두어 **이중 낭독을 막습니다**.
- **용어 통일**: 사용자 화면의 "연속 정답"을 **콤보**로 통일합니다. 해설 시트 문구 "N문제 연속 정답!" → "N콤보!", 완료 카드 "최고 연속" → "최대 콤보". 관련 기존 테스트(`session-view-model.test.js:129` 등)의 기대 문구를 같이 갱신합니다.
- **완료 요약**: 값은 이미 `summary.bestStreak` 로 있으므로 **라벨 변경과 위치 확인**이 전부입니다(새 필드 없음).

### 2.4 음소거 버튼 배치

- 세션 진행 헤더는 현재 ✕(44) + 진행 바 + "N/M"(52) + TTS(44). 음소거 버튼(44)을 더하면 360px(콘텐츠 폭 328px)에서 진행 바가 약 152px → **약 96px** 로 줄어듭니다(gap 12px 기준). 읽을 수는 있으나 좁아져 gap 을 8px 로 줄이는 안을 함께 씁니다(약 112px).
- 앱 헤더의 기존 토글은 그대로 두고, 두 토글이 `subscribe` 로 같은 상태를 따릅니다.
- **아이콘**: 효과음 토글을 앱 전체에서 `bell-ring`(켬) / `bell-off`(끔)로 통일하고, `volume-2` 는 **발음(TTS) 전용**으로 남깁니다. Lucide 0.460 에 두 아이콘이 있는지는 구현 첫 단계에서 확인합니다.
- 라벨: "효과음 끄기" / "효과음 켜기"(기존 "정답 소리"는 오답·완료음이 생기므로 부정확).
- TTS 는 효과음 음소거와 **별개**입니다(발음은 사용자가 직접 누르는 소리).

### 2.5 소리 겹침과 정책 메모
- 효과음과 TTS 가 동시에 날 수 있으나 서로 영향을 주지 않습니다(ducking 없음, 후속 후보).
- 효과음은 사용자가 답을 누른 이벤트에서 나므로 자동재생 제한에 걸리지 않습니다. 완료 팡파레는 마지막 "결과 보기" 탭 직후라 같은 제스처 흐름입니다. 컨텍스트가 suspended 면 기존대로 resume.

## 3. 결정이 필요한 사항 (승인 시 함께 답변)

1. **콤보 단일화**: `combo-model.js` 를 만들되 러너가 이를 위임해 사용하도록 하고 `streak`/`bestStreak` 필드는 유지 — **추천**. 대안(러너와 별개의 UI 전용 상태)은 어긋날 위험이 있어 비추천.
2. **음소거 버튼과 아이콘**: 세션 헤더에 추가 + 앱 헤더 토글과 상태 동기화 + 효과음 아이콘을 `bell-ring/bell-off` 로 통일(TTS 만 `volume-2`) — **추천**. 대안: 앱 헤더 토글만 유지하고 세션 헤더에는 두지 않기(헤더 폭 유지).
3. **마일스톤 값**: 5, 10, 15 — **제안**(세션이 15문항이라 3번 이하로 닿음). 3·6·9·12·15 처럼 더 촘촘히 할지.
4. **오답음 범위**: 퀴즈 모드만 재생, 플래시카드 "헷갈려요"는 무음 — **추천**.
5. **팡파레 조건**: 중단이 아니고 정답이 1개 이상일 때 — **추천**(전부 틀린 세션에 승리 음을 내지 않기 위함).
6. **문서**: REQ-137 을 "세션 효과음"으로 개정(오답음 기본 활성, 마일스톤·완료음, 음소거 위치), UIUX 설계서 §3.6·§12 보강 — v2.2 범위 유지.
7. **용어**: "연속 정답/최고 연속"을 "콤보/최대 콤보"로 통일 — **추천**.

## 5. 테스트 설계 요약

| 대상 | 방법 |
| :--- | :--- |
| 합성음 | `FakeAudioContext` 가 만든 오실레이터의 주파수·시작·정지 시각, 게인 램프 값과 시각, 연결 그래프를 단언. 시간은 `currentTime` 고정값이라 타이머 불필요 |
| 클리핑 | 같은 시각에 겹치는 음들의 최대 음량 합 × 마스터 게인 ≤ 1 을 계산해 단언 |
| 콤보 | 순수 함수 표 기반 테스트, 입력 객체 불변 확인 |
| 정책 | `soundCueFor` 전이 표 전수 |
| 화면 | 정적 검사(CSS 규칙, 배선, `aria-hidden`, 아이콘 이름), DOM 이 필요한 부분은 수동 |
| 한계 | **귀로 듣는 품질**(음색, 음량 균형)과 브라우저별 오디오 지연은 자동 테스트로 증명할 수 없음 → 수동 점검 |

## 6. 위험과 대응

| 위험 | 대응 |
| :--- | :--- |
