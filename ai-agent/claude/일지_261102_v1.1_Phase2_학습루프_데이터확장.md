## 2. 단어장 단어 수 집계 (`word_count`)

- `WordbookOut`에 `word_count: int`(기본 0)를 추가했습니다.
- **목록**: `words`와 `LEFT OUTER JOIN` 후 `GROUP BY wordbooks.id`로 한 번에 셉니다. 단어장마다 쿼리를 날리지 않으므로 N+1이 없습니다. 단어가 없는 단어장은 0입니다.
- **단건 응답(상세, 수정)**: `count_words()`로 한 번 셉니다. 생성 응답은 새 단어장이므로 0입니다.
- 프론트엔드: 카드마다 "N개 단어" 배지를 붙입니다. 천 단위 구분 기호를 씁니다 (`wordCountLabel`).

## 3. 오답 복습 퀴즈 (`wrong_only`)

### 3.1 출제 원천
- 최근 학습 기록 **100건**(이력 API의 최대 건수와 같은 기준)에서 `is_correct = false`인 **고유 단어**를 원천으로 합니다.
- 같은 단어가 여러 번 틀렸어도 한 번만 셉니다. 나중에 맞힌 단어도 기록 창 안에 틀린 답이 있으면 포함됩니다.
- 창 밖의 오래된 오답은 제외합니다 (테스트로 확인).
- 보기(오답 선지)는 사용자 전체 단어 풀에서 뽑습니다. 기존 로직과 같습니다.

### 3.2 가드
- 고유 오답 단어가 4개 미만이면 `400`입니다: `복습 가능한 오답 단어가 4개 미만입니다 (현재 N개)`.
- 출처는 `wordbook_id`, `bookmarks`, `wrong_only` 중 **정확히 하나**여야 합니다. 둘 이상이면 422입니다.

### 3.3 DB 변경 (마이그레이션 `aa1c92a9c7f9`)
- `quiz_sessions.source`의 CHECK 제약을 `('wordbook','bookmarks')`에서 `('wordbook','bookmarks','wrong')`으로 넓혔습니다. 기존 행은 그대로 유효합니다.
- 내리기는 `wrong` 세션을 먼저 지운 뒤 제약을 되돌립니다. 세션은 임시 데이터이므로 허용했습니다.

### 3.4 프론트엔드
- 학습 이력 화면: 최근 100건으로 고유 오답 수를 세고, **"오답 복습 퀴즈 시작"** 버튼을 둡니다. 4개 미만이면 비활성화하고 현재 개수를 안내합니다.
- 이력 화면의 집계 범위를 50건에서 100건으로 맞췄습니다. 그래야 UI의 개수와 서버의 원천이 같습니다.
- 퀴즈 설정은 `wrong=1` 출처를 받아 개수를 같은 기준으로 세고, 되돌아갈 곳을 이력 화면으로 둡니다.

## 4. 중급 1,000제 추천 프리셋

- `POST /api/wordbooks/presets/intermediate-1000`: 사용자 소유로 **"중급 필수 영단어 1,000"** 단어장을 만들고 단어 1,000건을 **한 트랜잭션**으로 넣습니다 (201).
  - 데이터 파일 `data/seeds/intermediate_1000.csv`가 없으면 **503**입니다 (`추천 단어장 데이터가 아직 준비되지 않았습니다`). 계정과 단어장 어느 것도 만들지 않습니다.
  - 같은 이름이 이미 있으면 **409**입니다.
  - 파일은 요청마다 읽으므로, 데이터를 바꾼 뒤 재시작하지 않아도 됩니다.
- 프론트엔드: 단어장 목록 상단에 **"추천 1,000제 추가"** 버튼을 두고, 확인 모달 후 호출합니다. 409와 503은 각각 다른 안내를 보여 줍니다.

## 5. 해결 완료(Resolved): 중급 1,000제 데이터

- **상태**: 해결 완료. 기존 Blocker 였던 "중급 1,000제 데이터 파일 없음"은 사용자가 1,000건 데이터를 `src/backend/data/seeds/intermediate_1000.csv`로 배치하면서 해소되었습니다.
- **원인**: 요청에 있던 데이터가 저장소와 `ai-agent/uploads/`에 없었습니다. 이 대화에서 제가 만든 중급 목록은 200개(`intermediate_200.json`)뿐이었고, 1,000개를 임의로 만들지 않았습니다.
- **파일 형식 정정**: 배치된 파일은 확장자는 `.json`이었지만 실제 내용은 CSV(헤더 `term,meaning,example`)였습니다. 이에 맞춰 파일명을 `intermediate_1000.csv`로 바꾸고 로더를 CSV 파싱으로 구현했습니다 (`services/seed.py`의 `_read_csv_words`, 헤더가 다르면 `ValueError`, UTF-8 BOM 허용).
- **데이터 검증**: 1,000건, 표제어 중복 없음(대소문자 무시), 필드 누락 없음, 길이 제한 이내. 예문에 표제어가 없던 3건을 수정했습니다.
  - `accompany`: 예문을 "A pianist will accompany the singer during the concert."로 교체 (기존 `accompanied`는 원형을 포함하지 않음)
  - `boundary`: 예문을 "Parents should set a clear boundary for young children."로 교체 (기존 `boundaries`는 원형을 포함하지 않음)
  - `pervade`: 오타 `pervailed` → `pervaded`
- **검증 테스트**: `test_seed_data.py::test_intermediate_1000_preset_file_has_1000_valid_words`가 위 조건을 실제 파일로 확인합니다. 파일이 바뀌면 이 테스트가 먼저 실패합니다.
- **테스트 전환**: `test_wordbook_api.py`, `test_preset_units.py`의 합성 데이터 생성도 CSV 형식으로 바꿨습니다.
- **결과**: 백엔드 pytest **276건 전건 통과** (직전 275 + 실제 파일 검증 1건).
- **남은 사항**: 브라우저에서 "추천 1,000제 추가" 버튼으로 실제 생성되는지 확인이 필요합니다. 이 환경에서는 HTTP 서버를 띄우지 않았습니다.

## 7. 설계 판단
| 항목 | 판단 | 이유 |
| :--- | :--- | :--- |
| 단어 수 집계 | GROUP BY 한 번 | 단어장마다 쿼리하면 N+1 이 됨 |
| 오답 원천 창 | 최근 100건 | 이력 API 의 최대 건수와 같아 UI 개수와 서버 원천이 일치 |
| 오답 원천 단위 | 고유 단어 | 같은 단어를 여러 번 틀려도 문항은 한 번만 나와야 함 |
| 출처 `wrong` | 세션 출처 CHECK 확장 | 기존 출처와 같은 표현으로 기록 (새 테이블 불필요) |
| 프리셋 데이터 누락 | 503 | 실패 원인을 "준비 중"으로 분명히 알림. 계정·단어장 누락 없이 실패 |
| 프리셋 데이터 파일 | 요청마다 읽기 | 데이터 교체가 재시작 없이 반영 (1,000건이라 읽기 비용은 작음) |
