## 3. 전체 구조

```text
[읽기 전용 콘텐츠]                          [사용자 개인 상태]
system_vocabularies ──1:N──> system_words ──┬─< user_word_progress  (사용자×단어 요약)
  (카탈로그)                  (단어)         ├─< study_logs          (문항별 이력, 기존)
                                            ├─< bookmarks           (기존)
users.active_vocabulary_id ──> system_vocabularies
quiz_sessions (기존) ── vocabulary_id ──> system_vocabularies
```

- 콘텐츠는 **서버 시드 파일**로만 바뀐다 (사용자 쓰기 경로 없음).
- 사용자는 `users.active_vocabulary_id`로 학습할 단어장을 고르고, 모든 학습 이력은 `system_words.id`를 참조한다.
- 폐기되는 것: `wordbooks`, `words` 테이블, 단어장·단어 CRUD, CSV 업로드, 프리셋 추가 API, 가입 시 기본 단어장 복사.

### 4.1 신규 테이블

공통: `TABLE_OPTIONS`, `UTC_NOW_DEFAULT`, `BIGINT(unsigned=True)` 사용. 소스 파일 헤더는 CLAUDE.md §5.2를 따른다.

| `title` | `VARCHAR(100)` NOT NULL | |

| 컬럼 | 타입 | 비고 |
| :--- | :--- | :--- |

### 4.2 기존 테이블 변경

| 테이블 | 변경 |
| :--- | :--- |
| `users` | `active_vocabulary_id BIGINT UNSIGNED NULL` + FK → `system_vocabularies.id` ON DELETE SET NULL |
| `study_logs` | `word_id` FK 대상을 `words.id` → `system_words.id`로 교체 (이미 `word_id`만 있고 wordbook 참조가 있으면 `vocabulary_id`로 교체. 구현 시 현행 컬럼 확인) |
| `bookmarks` | `word_id` FK 대상을 `system_words.id`로 교체 |
| `quiz_sessions` | `wordbook_id` → `vocabulary_id`로 이름 변경 + FK 교체. `source` 값 `'wordbook'` → `'vocabulary'`. 학습 모드 구분이 필요하면 `mode`(`quiz`/`flashcard`) 컬럼 추가 |
| `wordbooks`, `words` | **삭제** (전환 마이그레이션 마지막) |

### 4.3 전환 마이그레이션 (초기화 방식)

`words`를 `system_words`로 옮기지 않는다 (결정 1). 한 번의 마이그레이션 안에서 아래 순서로 처리한다.

1. 새 테이블 3종 생성, `users.active_vocabulary_id` 추가.
2. `study_logs`, `bookmarks`, `quiz_sessions` 행 삭제 (`DELETE`, FK 순서 고려). `user_word_progress`는 새 테이블이라 비어 있다.
3. 위 3개 테이블의 FK를 `system_words`/`system_vocabularies`로 교체.
4. `wordbooks`, `words` 삭제.
5. `downgrade()`는 스키마만 되돌리고 **데이터는 복구되지 않음**을 docstring에 명시한다.

> 운영 DB에 적용하기 전에는 반드시 백업을 받는다. 이 마이그레이션은 사용자 학습 이력을 지운다.
> 테이블 변경과 데이터 삭제는 CLAUDE.md §6 "사용자 사전 승인 필수" 대상이다. 적용 명령 전에 한 번 더 확인받는다.

### 5.1 API 명세

| 메서드·경로 | 인증 | 설명 |
| :--- | :--- | :--- |
| `GET /api/vocabularies` | 로그인 필요 | 카탈로그 + 내 진행률. `category`, `level` 로 거를 수 있다. 비회원 미리보기는 이번 범위 제외 (구현: B-5) |
| `GET /api/vocabularies/{id}/words` | 로그인 필요 | 단어 목록 (읽기 전용, `page`/`size`, 내 북마크 여부 포함) |

| `POST /api/study/sessions` | 로그인 필요 | 세션 생성 (`mode`, `count`, `include_memorized`, `source`=`all`(기본)\|`bookmarks`\|`wrong`). `all` 은 워터폴 출제, 나머지는 복습 풀에서 무작위 출제(활성 단어장 불변, 숙련 제외 없음, `vocabulary_id` null). 풀이 비면 409 `NO_WORDS_TO_STUDY`, 퀴즈는 4개 미만이면 400. 활성 단어장이 비어 있으면 첫 단어장을 활성으로 저장. 부수효과가 있으므로 `GET` 사용 금지 |

**삭제 대상**: `/api/wordbooks` 전체, `/api/words` 전체, 프리셋 추가 API, CSV 일괄 등록. 라우터에서 제거하며 별도 410 응답은 두지 않는다 (사용자가 없는 개발 DB).

**카탈로그 응답** (200):

```json
[
  {
    "id": 2,
    "slug": "secondary-1000",
    "title": "중고등 기본 1,000제",
    "category": "SECONDARY",
    "level": 2,
    "description": "교과서 및 모의고사 빈출 기본 어휘",
    "total_words": 1000,
    "user_progress": {
      "studied_words": 520,
      "memorized_words": 140,
      "progress_rate": 52.0,
      "is_active": true
    }
  }
]
```

- `studied_words` = 해당 단어장에서 `user_word_progress` 행이 있는 단어 수. `progress_rate` = `studied_words / total_words * 100`.
- N+1을 피하기 위해 진행률은 단어장별 `GROUP BY` 한 번으로 구한다.

**세션 생성 요청·응답** (`POST /api/study/sessions`):

```json
// 요청
{ "mode": "quiz", "count": 15, "include_memorized": false }
```

```json
// 응답 (200). mode 가 quiz 일 때
{
  "session_id": "<기존 quiz_sessions 식별자 형식 유지>",
  "mode": "quiz",
  "vocabulary_id": 2,
  "vocabulary_title": "중고등 기본 1,000제",
  "total_questions": 15,
  "items": [
    {
      "question_id": 1,
      "word_id": 105,
      "term": "postpone",
      "context": "The meeting was postponed until next Monday.",
      "options": ["연기하다", "가속하다", "조사하다", "설립하다"]
    }
  ]
}
```

- `count` 기본 15, 최소 1, 최대 30. `mode`는 `quiz` 또는 `flashcard`.
- **정답은 응답에 넣지 않는다.** 정답 판정은 서버가 하고, 문항별 기록 API의 응답으로 정오답과 해설(`meaning`, `example_meaning`)을 돌려준다. 현행 `quiz_sessions.questions`가 `correct_index`를 서버에 보관하는 구조라면 그 방식을 그대로 따른다 (구현 시 현행 스키마 확인).
- `flashcard` 모드는 `options`가 없고 `term`, `meaning`, `context`, `example_meaning`을 준다.
- `context`는 `example`이 NULL이면 생략한다.
- 퀴즈 문항 구성: 질문=`term` + 문맥 `example`(단어 강조는 프론트가 처리), 선택지=`meaning` 4개. 오답 보기는 같은 단어장의 다른 단어 뜻에서 뽑는다. 단어장 단어 수가 4개 미만이면 오류를 돌려준다.

### 5.2 출제 알고리즘 (워터폴, 결정 6)

`N` = 요청 문항 수. 대상은 활성 단어장의 단어이며, `include_memorized = false`이면 `is_memorized = TRUE`인 단어는 제외한다.

| 순서 | 풀 | 개수 |
| :-- | :--- | :--- |
| 1 | 오답 풀 (`last_result = 'WRONG'`) | `W = min(가용 오답, floor(0.3 × N))` |
| 2 | 복습 선확보 (오답 풀에 쓰이지 않은 기학습 단어, 무작위) | `R0 = min(가용 기학습 복습, floor(0.1 × N))` |
| 3 | 미학습 풀 (`user_word_progress` 행이 없는 단어, `order_index` 순) | `U = min(가용 미학습, N − (W + R0))` |
| 4 | 기학습 복습 잔여 충원 (미학습이 모자랄 때) | `R = N − (W + U)` 중 복습 풀에서 `R0`를 제외한 나머지를 채운 값. 즉 복습 합계는 `R0 + 추가분` |

- 기호 정리: 최종 복습 문항 수 = `R` (`R ≥ R0`). 4단계는 `W + R0 + U < N`일 때만 동작하고, 풀이 모자라면 가능한 만큼만 채운다.
- 예 (N=15): 오답 최대 4, 복습 선확보 1, 미학습 나머지 10. 미학습이 3개뿐이면 오답 4 + 미학습 3 + 복습 8.
- 가용 단어 총수가 `N` 미만이면 **전체를 반환**한다.
- 총수가 4 미만이면 퀴즈 모드는 오류, 플래시카드 모드는 허용한다.
- 반환 후에는 문항 순서를 섞는다 (오답이 맨 앞에 몰리지 않게).
- **결정 근거**: 이전 초안의 `U = min(미학습, N − W)`는 미학습이 남아 있는 동안 복습이 0문항이 되는 결함이 있어, 복습 10%를 먼저 확보하도록 사용자가 확정했다.
- 순수 함수(`select_session_words(wrong_ids, unseen_ids, review_ids, n)`)로 분리해 DB 없이 단위 테스트한다. 경계 사례: 오답 0건, 오답이 30% 초과, 복습 풀 0건, 미학습 부족(복습이 잔여를 채움), 총수 < N, `N=1`(`floor(0.3)=0`, `floor(0.1)=0`이라 미학습만), `N=9`(`floor(0.9)=0`으로 복습 선확보 0), 중복 id 없음.

### 5.3 학습 기록과 숙련도 갱신

- 문항 응답이 **처음** 기록될 때만 `study_logs` 삽입과 `user_word_progress` 갱신을 같은 트랜잭션에서 수행한다. 같은 문항을 다시 보내면 무시한다 (#8의 멱등 규칙 유지).
- 갱신 규칙 (`upsert`, `UNIQUE (user_id, word_id)` 활용):

| 결과 | 변경 |
| :--- | :--- |
| 정답 | `correct_count += 1`, `consecutive_correct_count += 1`, `last_result = 'CORRECT'`, 연속이 3 이상이면 `is_memorized = TRUE` |
| 오답 | `wrong_count += 1`, `consecutive_correct_count = 0`, `is_memorized = FALSE`, `last_result = 'WRONG'` |
| 공통 | `last_studied_at = now` |

- **플래시카드(#17)**: "알아요" = 정답, "헷갈려요" = 오답으로 같은 규칙에 넣는다. `study_logs`에는 모드를 구분할 수 있게 남긴다 (구현 시 `study_logs` 현행 컬럼을 확인해 모드 표시 방식을 정한다. 컬럼 추가가 필요하면 B-1 마이그레이션에 포함).
- 판정·갱신 로직은 `services/progress.py`의 순수 함수로 분리한다 (`apply_result(progress, is_correct) -> progress`). 숙련 경계값(2회 직전, 3회, 숙련 후 오답, 숙련 후 재도전)을 단위 테스트한다.
- `stats.py`의 기존 집계(`study_logs` 기반)는 그대로 둔다. 단어장별 진행률만 `user_word_progress`로 바꾼다 (#3 후속 #18의 기반).

## 7. 시드 파이프라인

```text
src/backend/data/seeds/
├── vocabularies.json            # 단어장 메타 (slug, title, category, level, description, sort_order)
└── words/<slug>.json            # [{ "term", "meaning", "example", "example_meaning" }, ...]
```

- 시드는 **초급·중급·고급 각 200단어, 총 600단어**로 한정한다. `beginner_200.json`, `intermediate_200.json`, `advanced_200.json`을 위 구조로 변환하고, `intermediate_1000.csv`와 프리셋 로더는 삭제한다. 변환은 일회성이며 결과만 저장소에 올린다.
- 초기 매핑 (확정): 초급 200 → `ELEMENTARY`/1 (`beginner-200`), 중급 200 → `SECONDARY`/2 (`intermediate-200`), 고급 200 → `CSAT`/3 (`advanced-200`).
- 새 카테고리(`CONVERSATION`, `TOEIC`, `BUSINESS` 등)는 `vocabularies.json`에 항목을 추가하는 것만으로 늘어나야 한다. 이를 위해 코드에 카테고리 목록을 하드코딩하지 않고, 시드 검증 테스트는 "category가 비어 있지 않고 50자 이하"만 본다.
- **멱등성**: `slug`로 단어장을, `(vocabulary_id, term)`으로 단어를 upsert한다. 단어장의 `content_hash`(메타 + 단어 목록의 SHA-256)가 같으면 쓰기를 생략한다.
- **삭제 정책**: 시드에서 빠진 단어는 DB에서 지우지 않는다 (학습 이력 FK 보호). 시더가 경고 로그만 남긴다. 완전 제거가 필요하면 별도 마이그레이션으로 처리한다.
- `total_words`는 시더가 실제 행 수로 갱신한다.
- 실행: `lifespan` 시작 시 `init_system_seeds()` 호출. 다중 워커가 동시에 시작해도 안전하도록 유니크 키 충돌을 무시하는 upsert를 쓴다. 테스트는 lifespan을 거치지 않고 함수를 직접 호출한다.
- 시드 데이터 검증 테스트(`test_seed_data.py` 확장): 필수 필드 누락, 중복 `term`, 길이 초과, 예문 없는 단어의 `example_meaning` 처리, slug 중복.

| B-6 | 기록 API가 `user_word_progress`를 갱신, 플래시카드 모드 | 멱등(같은 문항 재전송), 연속 정답 3회 숙련, 오답 리셋 |
| B-7 | 레거시 라우터·서비스·모델·테스트 삭제 | 전체 pytest |

| 위험 | 대응 |

## 12. 구현 현황 메모 (2026-11-05)

- **B-5 구현 결과**: 위 5개 엔드포인트와 `services/study_log.py` 의 `record_result`(이력 + 진행도 단일 진입점) 완료.
  `/api/vocabularies` 경로명은 설계 초안의 `/api/system-vocabularies` 를 대체한다.
- **세션 응답 규약**: 퀴즈 문항에는 정답·뜻을 싣지 않는다(`options` 만). 정답과 해설은 답 기록 응답에서 공개한다.
  플래시카드 문항은 뒷면(`meaning`, `example_meaning`)을 함께 준다. `answers` 값은 퀴즈=선지 번호, 플래시카드=1(알아요)/0(헷갈려요).
- **세션 종료**: 모든 문항에 답하면 서버가 세션을 끝낸다(`is_finished`). 마지막 답의 재전송은 끝난 뒤에도 200.
- **오류 코드(`X-Error-Code`)**: `NO_WORDS_TO_STUDY`(409, 학습할 단어 없음), `NO_VOCABULARY`(409), `QUIZ_ANSWER_LOCKED`, `QUIZ_ANSWER_INVALID`, `QUIZ_EXPIRED`, `QUIZ_ALREADY_SUBMITTED`, `QUIZ_WORD_MISSING`.
- **남은 정리(B-7)**: `models/word.py`, `models/wordbook.py` 와 `words`/`wordbooks` 테이블 DROP 마이그레이션, 옛 `/api/study/flashcards`·`/api/study/quiz/*` 정리 여부 결정.
