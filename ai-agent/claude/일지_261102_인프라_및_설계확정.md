## 2. MySQL 인프라 구성

- **이미지**: `mysql:8.0`, 컨테이너명 `voda-voca-mysql`.
- **서버 설정**
  - `--character-set-server=utf8mb4`
  - `--collation-server=utf8mb4_0900_ai_ci` (본 세션에서 `utf8mb4_unicode_ci`에서 변경)
  - `--default-time-zone=+09:00`
- **환경 변수**: 비밀번호, DB명, 사용자, 포트 등은 `.env`에서 주입한다. 저장소에는 `.env.example`만 커밋한다 (REQ-112).
- **헬스체크**: `mysqladmin ping` 기반, 10초 간격.
- **데이터 보존**: 명명된 볼륨 `voda-voca-mysql-data`에 저장한다.

### 확인된 사항 및 미완료
- 2026-11-02 세션 중 `docker compose ps`를 실행했을 때 `.env` 변수가 로드되지 않는 경고가 나왔다. 명령을 프로젝트 루트에서 `--project-directory .` 옵션과 함께 실행해야 한다.
- **컨테이너 재생성은 아직 하지 않았다.** compose 파일의 콜레이션 설정은 바뀌었지만, 실행 중인 서버에는 반영되지 않았다. `docker compose up -d`는 사용자 승인 후 진행한다 (CLAUDE.md §6).

## 4. 쟁점 협의 내역

### 4.1 데이터 설계 쟁점 (D1~D5)
| 쟁점 | 확정 | 근거 |
| :--- | :--- | :--- |
| D1 단어장 이름 중복 | 사용자 내 중복 금지, `UNIQUE (user_id, name)` | 혼란 방지 |
| D2 대소문자 | `utf8mb4_0900_ai_ci`로 대소문자 무시 수용 | 검색 편의와 일관성 |
| D3 북마크 소유권 | 서비스 계층 검증 필수, DB 복합 FK는 사용하지 않음 | 구현 단순화 |
| D4 최근 학습 목록 | `study_logs (user_id, created_at)` 인덱스로 쿼리 처리 | 역정규화 회피 |
| D5 검색 성능 | 접두사 검색 + UNIQUE 인덱스 | 추가 인덱스 비용 회피 |

### 4.2 study_logs 구조 전환
- **이전 설계**: 단어당 1행, `correct_count`·`wrong_count` 누적 카운터.
- **문제**: 확정된 "최근 100건 최신순" 조회를 만들 수 없다. 행이 단어별로 한 개뿐이므로 시간 순서가 남지 않는다.
- **전환 설계**: 문항 답안 1건당 1행 (`user_id`, `word_id`, `is_correct`, `created_at`). 인덱스는 `(user_id, created_at)`이다.
- **영향**: 정답률 같은 집계는 쿼리로 계산한다. 누적 카운터 컬럼은 없어졌다.

### 4.3 세션 테이블 채택
- JWT, 메모리, Redis와 비교했다. 자세한 근거는 ADR-001 참조.
- 채택 이유: 로그아웃 즉시 무효화, 재시작 후에도 유지, 기존 MySQL 재사용.

### 4.4 bcrypt 선정
- argon2id와 비교했다. 자세한 근거는 ADR-002 참조.
- bcrypt의 72바이트 제한을 Pydantic 검증으로 막는다. 빠뜨리면 긴 비밀번호의 뒷부분이 무시된다.

### 4.5 Collation 결정
- `utf8mb4_0900_ai_ci`로 통일했다. MySQL 8.0 기본값이며 대소문자와 악센트를 무시한다.
- 이전 설정 `utf8mb4_unicode_ci`는 compose 파일과 설계서에서 함께 바꿨다.
- **주의**: 이 콜레이션은 악센트도 무시한다 (`café` = `cafe`). 데이터 설계서 §2.1에 명시했다.
