# 작업계획 — 플래시카드·퀴즈 문항 수와 오늘의 목표 사용자 설정 (v2.2 후속, 가칭 REQ-147)

- 작성일: 2026-11-10 / 상태: **승인·구현 완료 (커밋 대기)**

## 1. 확정된 결정 (사용자 답변)

| 항목 | 결정 |
| :--- | :--- |
| 저장 위치 | **서버 DB, 사용자별** |
| UI 위치 | **홈 화면** (별도 설정 화면 없음) |
| 옵션 | **10 / 20 / 30** 세 가지, 세 설정 모두 동일 |
| 기본값 | **10** (현재 15에서 변경) |

설정 대상 3가지: ① 퀴즈 1회 문항 수 ② 플래시카드 1회 문항 수 ③ 오늘의 목표(하루 문항 수).

## 2. 현황 (코드 확인 결과)

- 프론트 상수 `SESSION_SIZE = 15`, `DAILY_GOAL = 15` (`core/home-model.js`), `DEFAULT_COUNT = 15` (`core/session-runner.js`).
- 서버 `SessionCreate.count` 는 기본 15, 1~30 허용 (`schemas/learning_session.py`). 세션 생성은 `count` 를 항상 프론트가 넘긴다.
- 사용자별 설정 저장소는 없다. `users` 테이블은 `active_vocabulary_id` 까지만 있다.
- 오늘 학습량은 `/api/study/stats` 의 `weekly[is_today].count` 로 이미 내려온다. 목표만 설정값으로 바꾸면 된다.

## 3. 설계

### 3.1 DB (마이그레이션 1건, **승인 필요**)
`users` 에 컬럼 3개 추가. `SMALLINT UNSIGNED NOT NULL DEFAULT 10`.
- `quiz_count`, `flashcard_count`, `daily_goal`
- `CHECK (col > 0)` 만 DB에 둔다. **허용 값(10/20/30)은 앱에서 검증**해서, 옵션을 늘릴 때 마이그레이션이 필요 없게 한다.
- 기존 사용자는 DEFAULT 로 전부 10이 된다. (이전 암묵적 15가 10으로 바뀐다. 사용자 영향: 첫 접속 때 문항 수가 줄어듦)
- downgrade 는 컬럼 3개 DROP (설정값만 사라지고 다른 데이터에는 영향 없음).
- 적용 전 `ai-agent/backups/` 에 mysqldump 를 받고 승인 후 `alembic upgrade head` 한다.

### 3.2 API
라우터 `routers/user_settings.py`, 접두사 `/api/users/me/settings`, 로그인 필수.
- `GET` → `{quiz_count, flashcard_count, daily_goal, options: [10, 20, 30]}`
- `PATCH` ← 일부 필드만 허용 (`{"daily_goal": 20}`). 허용 값 밖이면 422, 빈 본문은 변경 없이 현재값 반환. 응답은 GET 과 같다.
- 옵션 목록은 서버 상수 한 곳(`schemas/user_settings.py`)에서 정의하고 응답에 싣는다 → 프론트는 하드코딩하지 않는다.
- **세션 생성 변경**: `SessionCreate.count` 를 선택값으로 바꾼다. 생략하면 서버가 `mode` 에 맞는 사용자 설정(`quiz_count`/`flashcard_count`)을 쓴다. 명시하면 기존처럼 1~30 으로 그 값을 쓴다 (하위 호환). 즐겨찾기·오답 복습도 같은 설정을 따른다.

### 3.3 프론트
- 순수 모델 `core/settings-model.js`: 옵션 정규화, 설정 라벨, 낙관적 갱신·롤백 결정 (DOM 없음, node 테스트).
- 홈 `loadHome` 이 `/me/settings` 를 함께 받는다. 실패해도 홈은 동작해야 하므로 기본값(10/10/10)으로 폴백한다.
- 홈에 "학습 설정" 카드: 3행(퀴즈 · 플래시카드 · 오늘의 목표) × 칩 3개(10/20/30). 선택 즉시 PATCH, 실패하면 이전 값으로 되돌리고 토스트.
  - 모바일 우선: 칩은 높이 44px 이상, 360px 폭에서 한 줄에 3개. 색은 디자인 토큰만 써서 다크 모드 자동 대응(`dark-theme.test.js` 가 검사).
- 오늘의 목표 카드·진행률은 `daily_goal` 을 쓰고, 목표 변경 시 즉시 다시 그린다.
- 시작 버튼 문구는 현재 모드의 설정으로 `N문항 학습 시작` 이 되고, 모드 토글 시 같이 바뀐다.
- `session-runner.js` 는 `count` 를 보내지 않는다 (서버 설정 사용). `SESSION_SIZE`·`DAILY_GOAL`·`DEFAULT_COUNT` 상수는 제거한다.

### 3.4 정리성 작업 (함께)
- `core/api.js:146` JSDoc 예시의 옛 경로 `"/wordbooks"` 를 현행 경로로 교체. (그 외 정리 항목은 점검 결과 이미 완료)

## 5. 위험과 주의

- **서버 시작 시 시드 적재**: 이번 작업은 시드를 건드리지 않지만, 개발 서버가 켜져 있으면 마이그레이션 적용 순서에 유의한다 (코드 배포 전에 컬럼이 먼저 있어야 한다).
- 마이그레이션 적용 전에 구 코드가 새 컬럼을 모르는 것은 안전하다(DEFAULT). 반대로 코드가 먼저 올라가면 `Unknown column` 오류가 나므로 **DB 먼저, 코드 나중** 순서를 지킨다.
- 기본값 10 으로 하향되어, 사용자가 기존 15에 익숙하면 낯설 수 있다. 홈 첫 화면에서 바로 바꿀 수 있게 한다.
- 브라우저가 없는 환경이라 칩 레이아웃(360/390/412px)은 눈으로 확인하지 못한다. 구현 후 사용자 확인이 필요하다.
