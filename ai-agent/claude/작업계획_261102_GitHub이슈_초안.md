## 3. [버그] 누적 학습 지표 집계 (정답률, 진행률, 연속 학습일, 오답 판정)

- **라벨**: bug, enhancement, priority:high
- **배경**: 전체 점검(검토_261103)에서 최근 100건 기준 계산이 진행률 상한, 연속 학습일 과소 집계, 오답 복습 미수렴을 일으키는 것을 확인했다. 기존 3번(누적 통계)에 합쳐 재작성했다. 1번과 숙련도 이슈의 기반이다.

**본문**

증상 (점검에서 확인)
- 단어장 진행률 상한: 이력이 최근 100건뿐이라 200단어장은 최대 50%, 1,000제는 최대 10%까지만 올라갑니다 (`stats.js` computeWordbookProgress).
- 연속 학습일·주간 차트 과소 집계: 하루 100문항 이상 풀면 이전 날짜 기록이 100건 창 밖으로 밀려 연속 학습일이 1~2일로 보이고 차트가 비어 보입니다.
- 오답 복습이 줄지 않음: 최근 100건 중 한 번이라도 틀린 단어를 오답으로 칩니다 (`services/study.py` _recent_wrong_word_ids). 복습에서 맞혀도 예전 오답이 100건 더 쌓일 때까지 같은 단어가 반복됩니다.

요구사항
- 누적 정답률, 단어별 정답 이력, 주간·월간 추이, 취약 단어 목록을 백엔드에서 집계합니다.
- 집계 API는 페이지 없이 요약 값을 돌려줍니다.
- 연속 학습일과 주간 차트는 기간 전체 로그에서 일자별로 집계합니다 (100건 제한 없음).
- 오답 복습 대상은 "단어별 가장 최근 결과가 오답인 단어"로 바꿉니다. 맞히면 대상에서 빠집니다.
- 단어장 진행률은 전체 이력 기준 "정답 이력이 있는 단어 수 / 단어 수"로 계산합니다.
- 기존 프론트 통계(stats.js)는 집계 API 응답으로 대체합니다.
- 설계서의 REQ-016(최근 100건 조회)과의 관계를 정리해 갱신합니다.

완료 기준
- [ ] 집계 엔드포인트와 인덱스 (N+1 없음)
- [ ] 100건 제한이 없는 정답률, 진행률, 연속 학습일, 주간 차트
- [ ] 오답 복습에서 맞힌 단어가 대상에서 빠지는 것을 테스트로 검증
- [ ] 대시보드 연동 및 회귀 테스트
- [ ] 설계 문서(요구사항, 데이터, API)에 반영

점검 결과: `ai-agent/claude/검토_261103_전체점검_학습지표_UX_결함.md`

## 8. [버그] 퀴즈 중도 이탈 시 학습 기록 소실, 플래시카드 학습 미반영

- **라벨**: bug, priority:high
- **배경**: 점검 §2.

**본문**

증상
- 퀴즈는 마지막 문항 뒤 일괄 제출할 때만 `study_logs`에 기록합니다. 문항마다 정답을 바로 보여 주는데도, 중간에 닫거나 30분이 지나면 푼 답이 전부 사라집니다 (`quiz.js` finish, `services/study.py` submit_quiz).
- 플래시카드는 학습 기록이 전혀 없어 연속 학습일, 차트, 진행률에 잡히지 않습니다.
- 이탈 확인은 X 버튼에만 있고, 브라우저 뒤로가기나 하단 탭 이동에는 경고가 없습니다.
- 퀴즈 결과는 `sessionStorage`에만 있어 다른 탭에서는 볼 수 없습니다.
- 30분 제한이 학습 앱에서는 압박이 됩니다.

요구사항
- 문항에 답할 때마다(또는 일정 간격으로) 서버에 기록하거나, 이탈·만료 시 지금까지 푼 답만 부분 제출할 수 있게 합니다. 어느 쪽이든 푼 답은 이력에 남아야 합니다.
- 30분 제한은 "마지막 활동 후 N분" 또는 부분 제출 허용으로 완화합니다.
- 플래시카드에 "알아요 / 헷갈려요" 같은 간단한 표시를 두고 기록해 학습일 집계에 반영합니다 (기록 방식은 설계에서 확정).
- 퀴즈 진행 중 뒤로가기·탭 이동 시 이탈 확인을 보여 줍니다.
- 결과 화면은 새로고침·다른 탭에서도 다시 볼 수 있게 하거나, 최소한 이력 화면에서 같은 정보를 찾을 수 있게 합니다.

완료 기준
- [ ] 중도 이탈·만료 후에도 푼 답이 `study_logs`에 남는 것을 API 테스트로 검증
- [ ] 이미 제출된 문항의 중복 기록 방지 (멱등)
- [ ] 플래시카드 학습이 학습일 집계에 반영됨
- [ ] 뒤로가기·탭 이동 이탈 확인
- [ ] 설계 문서(요구사항, API, UI/UX)에 반영

## 9. [버그] 플래시카드가 500장에서 조용히 잘림

- **라벨**: bug, priority:high
- **배경**: 점검 §3-1.

**본문**

증상
- 플래시카드는 최대 500장만 받고 서버가 준 `total`을 무시합니다 (`flashcards.js` FLASHCARD_LIMIT). 단어가 500개를 넘으면 표제어 알파벳순 앞 500개만 나오고, 끝에서 "모든 카드를 봤습니다"가 표시됩니다.
- 셔플도 받아 온 500장 안에서만 섞이므로 뒤쪽 단어는 영원히 나오지 않습니다. 1,000제 단어장에서 바로 재현됩니다.

요구사항
- 전체 카드를 볼 수 있게 합니다. 서버 셔플 + 페이지 단위 추가 로딩, 또는 한도를 올리고 잘리면 안내하는 방식 중 설계에서 정합니다.
- 진행 표시(n / total)는 서버 `total` 기준으로 합니다.
- 한도에 걸릴 때 사용자에게 알립니다.

완료 기준
- [ ] 500개를 넘는 단어장에서 모든 단어가 한 번씩 나옴 (테스트)
- [ ] 진행 표시가 전체 개수 기준
- [ ] 셔플이 전체 범위에 적용됨

점검 결과: `ai-agent/claude/검토_261103_전체점검_학습지표_UX_결함.md`

## 15. [기능] 단어 숙련도 판정과 숙련 단어 학습 제외

- **라벨**: enhancement, priority:high
- **배경**: 현재는 숙련도 개념이 없어 이미 아는 단어도 플래시카드와 퀴즈에 계속 나옵니다. `words`에 숙련도 컬럼이 없고, `study_logs`는 문항 단위 기록뿐이며 단어별 누적 카운터는 두지 않기로 한 상태입니다(REQ-016). 1번(간격 반복)의 "익힘" 단계와는 별개로, 익힌 단어를 출제 대상에서 빼는 동작을 독립 기능으로 다룹니다. 3번(누적 통계)을 먼저 하거나 함께 진행하는 것이 좋습니다.

**본문**

요구사항
- 사용자별·단어별 숙련도를 판정합니다. 기준은 확정 전이며 후보는 아래와 같습니다 (결정 필요).
  - (안 A) 최근 연속 N회 정답이면 숙련. 오답이 나오면 해제
  - (안 B) 누적 정답 횟수와 정답률이 기준 이상이면 숙련
  - 판정에 필요한 단어별 정답 이력은 집계 쿼리나 사용자·단어별 요약 테이블로 가져옵니다. REQ-016(누적 카운터 미사용) 변경 여부를 설계 단계에서 결정합니다.
- 숙련 단어는 단어장 목록과 상세에서 계속 보이고, 숙련 뱃지와 필터("전체 / 학습 중 / 숙련")를 제공합니다.
- 숙련 단어는 플래시카드와 퀴즈 출제 대상에서 제외합니다. 제외 적용 여부는 학습 시작 화면에서 "숙련 단어 포함" 옵션으로 바꿀 수 있습니다.
- 사용자가 단어별로 숙련 상태를 직접 켜고 끌 수 있습니다 (수동 설정이 자동 판정보다 우선).
- 숙련 해제 규칙: 숙련 이후 오답이 나오거나 사용자가 해제하면 학습 대상으로 돌아옵니다.
- 경계 처리
  - 제외 후 출제 원천이 4개 미만이면 기존 `QUIZ_MIN_SOURCE_WORDS` 오류 대신 "학습할 단어가 없습니다. 숙련 단어를 포함해 볼까요?" 안내를 보여줍니다.
  - 북마크한 단어도 숙련이면 제외 대상입니다 (북마크 범위 학습 포함).
  - 오답 보기(distractor) 풀에는 숙련 단어를 계속 사용할 수 있습니다.
  - 오답 복습 모드는 숙련 해제 대상이므로 영향을 받지 않습니다.
- 1번(간격 반복)과의 관계: 이 이슈가 먼저 구현되면 1번은 숙련 단계를 재사용하고, 1번이 먼저면 이 이슈는 1번의 "익힘" 단계를 제외 기준으로 연결합니다. 중복 컬럼을 만들지 않도록 설계 단계에서 한 번에 정합니다.

완료 기준
- [ ] 숙련 판정 기준 확정(안 A/B)과 REQ-016 처리 방침 결정, 설계 문서 반영
- [ ] 사용자·단어별 숙련 상태 저장 (마이그레이션 포함, 기존 데이터 보존)
- [ ] 숙련 판정과 해제 규칙 단위 테스트 (경계값: N회 직전·직후, 숙련 후 오답)
- [ ] 플래시카드·퀴즈 출제에서 숙련 단어 제외, "숙련 포함" 옵션 API 파라미터
- [ ] 단어장 화면의 숙련 뱃지, 필터, 수동 토글 (모바일 터치 대응)
- [ ] 출제 원천 부족 시 안내 화면과 API 오류 응답
- [ ] 다른 사용자의 단어·숙련 상태에 접근할 수 없음을 검증하는 권한 테스트
