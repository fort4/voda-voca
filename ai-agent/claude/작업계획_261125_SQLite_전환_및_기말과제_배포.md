## 1. 전수조사 결과 (MySQL 의존 지점)

### 1.1 설정·연결
| 위치 | 내용 | 조치 |
|---|---|---|
| `requirements.txt` | `asyncmy`, `cryptography`(MySQL 인증용) | `aiosqlite` 로 교체, `cryptography` 제거 |
| `core/config.py` | `MYSQL_*` 5개 필수 필드, `mysql+asyncmy` URL | `DB_PATH`(기본 `/data/voca.db`) 하나로 축소, `sqlite+aiosqlite` URL |
| `db/session.py` | `pool_pre_ping` (MySQL wait_timeout 대응) | 제거 가능. 연결 시 `PRAGMA foreign_keys=ON`, `journal_mode=WAL`, `busy_timeout` 설정 |
| `.env.example`, compose, `test_config.py` | `MYSQL_*` 변수 | `DB_PATH`, `SECRET_KEY` 로 정리 |

### 1.2 모델 (`models/*.py`, 9개)
- `sqlalchemy.dialects.mysql` 의 `BIGINT/INTEGER/SMALLINT/TINYINT(unsigned)`, `DATETIME(fsp=3)`, `BINARY(32)` 사용 → 표준 `BigInteger/Integer/SmallInteger/DateTime/LargeBinary` 로 교체
  - SQLite 의 PK 자동증가는 `INTEGER PRIMARY KEY` 여야 하므로 PK 는 `BigInteger().with_variant(Integer, "sqlite")` 사용
  - unsigned 는 의미가 없어지므로 값 범위는 `CheckConstraint` 가 이미 있는 곳(`> 0`)에 맡김
- `models/base.py`: `TABLE_OPTIONS`(InnoDB, utf8mb4, collation) 제거, `UTC_NOW_DEFAULT = (UTC_TIMESTAMP(3))` → SQLite 용 기본값(`strftime('%Y-%m-%d %H:%M:%f','now')`)으로 교체. 앱 쪽 `utcnow()` 로 채우는 방식이 더 단순
- `CHAR_LENGTH(TRIM(...))` CheckConstraint 2건 (`users`, `system_vocabulary`) → `length(trim(...))`
- `quiz_session.answers` JSON `server_default (JSON_OBJECT())` → `'{}'`
- `Enum(... name="uwp_last_result")` → SQLite 는 VARCHAR + CHECK 로 생성됨 (동작 확인 필요)

### 1.3 서비스 (실제 동작이 달라지는 곳, 위험도 높음)
| 위치 | MySQL 의존 | 조치 |
|---|---|---|
| `services/study_log.py:46` | `mysql_insert ... on_duplicate_key_update` (진행도 upsert) | `sqlalchemy.dialects.sqlite.insert ... on_conflict_do_nothing` |
| `services/system_seed.py:218,282` | 동일 (단어장·단어 upsert) | 동일 |
| `study_log.py:54`, `system_seed.py:233`, `study.py:132` | `with_for_update()` 행 잠금 | SQLite 는 무시됨. 동시 쓰기 직렬화는 SQLite 의 쓰기 단일성(WAL + `busy_timeout`)에 의존. 세션 채점 중복 제출 방지가 유지되는지 **테스트로 검증** |
| `services/stats.py:30` | `date_add(col, INTERVAL 9 HOUR)` KST 일자 변환 | `date(col, '+9 hours')` (SQLite) — 방언 헬퍼 한 곳으로 격리 |
| `services/auth.py`, `system_seed.py:94` | 대소문자·악센트 무시 비교를 DB 콜레이션(`utf8mb4_0900_ai_ci`)에 의존 | SQLite 기본은 대소문자 구분. 닉네임 UNIQUE 는 `COLLATE NOCASE`(또는 저장 시 소문자 정규화 컬럼)로 보장. **보안·무결성 영향이 있어 테스트 필수** |
| `stats.py` `row_number()` 윈도 함수 | MySQL 8 | SQLite 3.25+ 지원, python:3.12 번들 SQLite 로 문제 없음 |
| `main.py:57` `SELECT 1` | 호환 | 변경 없음 |

### 1.4 마이그레이션 (Alembic 12개)
- 전 리비전이 `mysql.BIGINT/DATETIME`, `mysql_engine` 옵션, `(UTC_TIMESTAMP(3))`, `(JSON_OBJECT())` 를 사용 → **SQLite 에서 실행 불가**
- 빈 DB 시작이 승인되었으므로 **리비전 12개를 하나의 새 초기 리비전(`0001_initial_sqlite`)으로 재작성**한다 (옛 `wordbooks/words` 생성 후 삭제 이력은 제거). 기존 MySQL 이력은 `docs/old` 가 아니라 git 이력에 남는다
- `alembic/env.py`: `render_as_batch=True`, `compare_type=True` 유지. 기동 시 `alembic upgrade head` 를 자동 실행(lifespan 또는 컨테이너 entrypoint)해 VOCA-NFR-003 충족
- `alembic check`(푸시 전 검사)는 SQLite 로 계속 동작

### 1.5 테스트 (38개 파일)
- `no_db` 단위 테스트는 대부분 영향 없음. 단 `test_config.py`, `test_container_files.py`, `test_health.py`, `test_no_db_guard.py` 는 `MYSQL_*` 에 의존 → 수정
- DB 통합 테스트는 `conftest.py` 가 실제 MySQL 에 접속. **임시 SQLite 파일(tmp_path) 또는 인메모리** 로 바꾸면 Docker 없이 전체 테스트가 돌아 TDD 주기가 빨라진다 (부수 이득)
- MySQL 전용 검사 재작성: `test_transition_schema.py`(GROUP_CONCAT, INFORMATION_SCHEMA), `test_system_models.py:321`(varchar/utf8mb4 컬럼 규격 → `PRAGMA table_info`)
- 회귀 방지 테스트 신설: MySQL 방언 import/문법이 코드에 다시 들어오지 않게 검사 (`dialects.mysql`, `INTERVAL`, `UTC_TIMESTAMP` grep 테스트)

## 5. 위험과 대응
- **동시성**: `with_for_update` 가 무력화됨 → 세션 채점 중복 제출 테스트로 검증, 필요 시 `UPDATE ... WHERE` 낙관적 조건으로 보강
- **닉네임 대소문자**: 중복 가입 허용 사고 방지 → 유니크 제약 + 테스트
- **마이그레이션 재작성**: 기존 MySQL DB 와 호환 끊김(빈 DB 승인으로 수용). 로컬 개발 MySQL 데이터는 폐기됨을 README 에 명시
- **시드 자동 적재**: 서버 시작 시 적재(메모리 기록 참고). 빈 DB 에서 첫 기동 시간(400+600 단어) 측정, 점검 30초 제한 내 응답하도록 적재를 응답 이후로 미루거나 배치 insert 확인
- **외부 의존**: 점검 워크플로 세부 동작은 실행해 봐야 확정됨(경로 접두사 규칙 등)
