## 1. 문제와 해법

**문제**: 퀴즈는 마지막에 일괄 제출할 때만 `study_logs`에 기록했다. 문항마다 정답을 바로 보여 주는데도, 중간에 닫거나 30분이 지나면 푼 답이 전부 사라졌다. 결과는 `sessionStorage`에만 있어 다른 탭에서 볼 수 없었다.

**해법 (방식 A)**: 답을 고를 때마다 서버에 기록한다.
- `quiz_sessions.answers`(JSON, `{"문항번호": 선지}`)를 추가했다. 학습 이력 INSERT와 같은 트랜잭션에서 갱신하며, 재전송을 멱등으로 처리하고 결과 화면을 서버에서 다시 만드는 근거가 된다.
- 해설은 출제 때 받은 정답으로 화면에서 즉시 보이므로, 기록은 뒤에서 비동기로 한다. 체감 지연이 없다.
- 선택 근거: 방식 C(이탈 시 부분 제출)는 모바일에서 앱 종료·프로세스 종료 시 이벤트가 오지 않아 핵심 시나리오를 못 막는다. 방식 B(`study_logs`에 세션·문항 컬럼)는 가장 큰 테이블을 바꾸고 기존 행 처리가 필요해 변경 범위가 크다.

## 2. API 변경

| 구분 | 내용 |
| :--- | :--- |
| 신규 `POST /api/study/quiz/sessions/{id}/answers` | 답 1건 기록. 같은 답 재전송은 200(멱등, 이력 중복 없음), 다른 답으로 변경은 409 `QUIZ_ANSWER_LOCKED`. 응답에 `expires_at`(기록할 때마다 +30분) |
| 신규 `GET /api/study/quiz/sessions/{id}` | 문항 + 내가 고른 답 + 요약. 끝나지 않은 세션도 조회 가능. 타인 세션은 404 |
| 변경 `POST .../submit` | "퀴즈 끝내기"로 의미 완화. `answers`는 비어도 되고 일부만 보내도 된다. 이미 기록된 문항은 서버 값이 우선하고 다시 쓰지 않는다. 이전 방식(전체 답 일괄 제출)도 그대로 동작 |
| 변경 응답 `QuizResultOut` | `answered` 추가. `accuracy`는 푼 문항 기준(푼 문항이 없으면 0). `total`은 출제 문항 수 |
| 만료 | 출제 후 30분 고정 → 마지막 응답 후 30분. 기록할 새 답이 없으면 만료된 세션도 끝낼 수 있다 |
| 오류 코드 헤더 | `QUIZ_ANSWER_LOCKED` 추가 (기존 4종과 함께). 오류 매핑을 `_quiz_http_error` 한곳으로 통합 |

## 3. 프론트엔드

- `core/answer-recorder.js`: 답을 고른 순서대로 한 번에 하나씩 보내는 큐. 네트워크 오류·429·5xx는 최대 4회 재시도하고, 그 밖의 4xx는 바로 실패로 분리한다. `retryFailed()`, `flush()`, `isIdle()` 제공.
- `quiz.js`: 답을 고르면 큐에 넣고, 끝낼 때만 큐가 빌 때까지 기다린다. 전부 푼 경우 전체 답을 함께 보내 저장 실패분을 서버가 채운다. 저장 실패 시 안내와 "다시 저장" 버튼, `online` 복귀 시 자동 재시도, 저장 중 탭을 닫으면 `beforeunload` 경고. 만료되면 "푼 문항 결과 보기"로 부분 결과를 볼 수 있다.
- `views/quiz-result.js`(신규): 결과를 서버에서 받아 그린다. 새로고침·다른 탭에서도 같은 결과. 일부만 푼 결과는 푼 문항 기준임을 밝히고 풀지 않은 문항은 "풀지 않음"으로 표시한다.
- `quiz.js`가 523줄(CLAUDE.md §4 원칙 4 초과)이었고 변경으로 601줄이 되어, 결과 화면을 분리했다 → 467줄.
- 삭제한 죽은 코드: `core/result-cache.js`, `core/quiz-state.js`와 각 테스트. 서버 데이터로 결과를 그리게 되어 `sessionStorage` 캐시와, 오답 목록으로 정답 선지를 역추정하던 `deriveQuizItems`가 필요 없어졌다.

## 5. 한계와 미확인

- **브라우저 실사용 확인은 하지 않았다.** `quiz.js`의 DOM 연결(큐 연결, 저장 실패 안내, 만료 후 부분 결과, `beforeunload`)은 자동 테스트가 없다. import 링크 검증과 단위 테스트까지만 했다. 직접 한 번 풀어 보며 확인이 필요하다.
- 과거에 제출된 세션은 `answers`가 `{}`이다. 과거 결과를 서버에서 다시 만들 수는 없다 (원래 `sessionStorage`에만 있었다).
- `beforeunload` 경고는 모바일에서 보이지 않는 경우가 많다. 모바일의 실질적 보호는 "답을 고르는 즉시 기록"이다. 저장 직전에 앱이 종료되면 그 한 문항은 유실될 수 있다.
- 이어 풀기(미완료 세션 재개)는 지원하지 않는다. 데이터는 있으므로(`GET`으로 조회 가능) 후속 기능으로 가능하다.
- 개발 DB에 마이그레이션 `7c2d4e91b5a3`을 적용했다 (테스트 DB와 같다).
