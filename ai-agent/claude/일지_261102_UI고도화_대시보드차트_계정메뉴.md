## 3. 설계 판단

### 3.1 백엔드: 학습 이력에 `wordbook_id` 추가
- 단어장별 진행률을 프론트에서 계산하려면 각 학습 기록이 어느 단어장 소속인지 알아야 한다. 기존 `StudyLogOut`에는 `word_id`, `term`뿐이었다.
- `GET /api/study/logs` 응답에 `wordbook_id`를 추가했다 (`services/study.py` 조인 한 줄, `schemas/study.py` 필드, `routers/study.py` 매핑).
- 기존 필드는 그대로다. 테스트(`test_study_api.py`)에 단어장 ID 일치 검증을 추가했다.

### 3.2 통계의 데이터 범위: 최근 100건
- 학습 이력 API의 `limit` 최댓값이 100이다. 대시보드의 **정답률, 연속 학습일, 주간 차트, 진행률은 모두 최근 100건 기준**이다.
- 그래서 "누적"이라는 표현을 쓰지 않고, 화면에는 "최근 N문항", "오늘 기준"처럼 범위를 밝혔다.
- 누적 통계가 필요하면 백엔드에 집계 엔드포인트를 두는 것이 맞다. 이번 작업에서는 백엔드 집계를 새로 만들지 않았다 (범위와 회귀 위험을 줄이기 위해).

### 3.3 통계 계산: `core/stats.js`
- 모든 함수는 순수 함수다. 현재 시각은 인자로 받아 테스트에서 고정한다.
- 날짜 경계는 **한국 시각 자정**이다. UTC 기준 날짜로 나누면 밤 9시 이후 학습이 다음 날로 넘어가므로 쓰지 않았다.
- `computeWordbookProgress(wordbookId, studyLogs, wordCount)`: 요청 명세의 두 인자에 **단어 수(`wordCount`)를 더했다**. 진행률의 분모는 단어장의 단어 수이고, 그 값은 학습 기록이 아니라 단어장 목록에서 오기 때문이다.
- `computeWeeklyActivity`: "학습한 단어 수"로 정의해, 같은 단어를 같은 날 여러 번 풀어도 한 번으로 센다.
- 연속 학습일: 오늘 기록이 없으면 어제부터 센다. 하루가 끝나기 전에 연속이 깨져 보이지 않도록 하기 위해서다.

### 3.4 차트: `core/weekly-chart.js`
- 막대 높이 계산(`barGeometry`)과 막대 경로(`barPath`)는 DOM 없이 테스트한다. 렌더링(`renderWeeklyChart`)은 `createElementNS`로 SVG를 만든다.
- 최댓값이 0이면 분모를 1로 바꿔 0으로 나누지 않는다.
- 막대를 누르거나 포커스하면 그 날의 단어 수가 막대 위에 표시된다. 키보드 포커스로도 동작한다 (`tabindex`, `role="img"`, `aria-label`).

### 3.5 단어장 카드 구조
- 카드를 두 행으로 나눴다. 위 행은 기존처럼 본문 버튼과 수정·삭제, 아래 행은 진행률 바와 퀵 액션(플래시카드, 퀴즈)이다.
- 성격 태그는 **단어장 이름으로 판정**한다. 기본 제공 4종(초급·중급·고급 200제, 중급 1,000제)만 해당 태그를 받고, 나머지는 "내 단어장"이다. 사용자가 같은 이름을 만들어도 태그가 바뀌지 않는다.
- 퀵 액션은 기존 학습 경로(`sourceRouteQuery`)를 그대로 쓴다. 새 라우트를 만들지 않았다.

### 3.6 계정 드롭다운: `app.js`
- 닉네임 칩 클릭 → 칩 아래 `position: fixed` 팝오버. 위치는 칩의 `getBoundingClientRect()`로 계산한다.
- 바깥 클릭은 투명한 백드롭(`dropdown-backdrop`)으로 처리하고, ESC는 `keydown` 리스너로 처리한다. 닫을 때 리스너를 반드시 뗀다.
- 로그아웃은 `confirmDialog`로 한 번 확인한 뒤 처리한다.
- **회원 탈퇴는 기존 두 단계 흐름을 그대로 쓴다.** 드롭다운에서 메뉴를 닫은 뒤 `withdraw()`를 호출한다. 이 흐름은 닉네임 직접 입력을 요구하는 SweetAlert2 모달이므로, "중앙 모달 제거"는 **계정 메뉴**에 한정된다.
- 다크 모드는 `--surface`, `--border`, `--text` 같은 토큰으로 처리해 `html.dark`에서 자동 전환된다.

### 3.7 CSV 백업: `core/backup.js`
- 백업 형식은 **가져오기 형식과 다르다**. 가져오기(`term,meaning,example`)에는 단어장 이름 열이 없다. 백업에는 단어장 이름이 필요하므로 헤더를 `단어장,표제어,뜻,예문,예문 뜻`으로 정했다.
- 한 파일에 모든 단어장을 담는다. "대표 단어장" 하나만 내보내는 방식은 쓰지 않았다.
- 엑셀에서 한글이 깨지지 않도록 UTF-8 BOM을 붙인다. 줄바꿈은 CRLF다.
- 데이터가 많으면 요청이 많아진다 (단어장마다 100건씩). 현재 데이터 규모(약 1,400단어)에서는 문제가 없다.

## 6. 알려진 제한

- 통계와 진행률은 **최근 100건 기준**이다 (§3.2). 오래 쓴 계정은 진행률이 실제보다 낮게 보일 수 있다.
- 진행률은 "정답 이력이 있는 단어" 기준이다. 틀린 뒤 맞힌 단어와 맞힌 적 없는 단어를 구분하지 않는다.
- 주간 차트의 값은 "학습한 단어 수"(고유 단어)다. 문항 수가 아니다.
- 백업은 클라이언트에서 단어를 전부 받아 만든다. 단어가 수만 개로 늘면 백엔드 내보내기 엔드포인트가 필요하다.

## 7. 브라우저 검증 체크리스트 (이 환경에서 수행하지 못함)

1. **대시보드 상단**: 요약 카드 3개(총 단어, 정답률, 연속 학습일)가 한 줄에 보이고, 모바일 폭(360px)에서 글자가 잘리지 않는지 확인한다.
2. **주간 차트**: 막대 7개와 요일 라벨이 보이고, 가장 높은 막대가 차트 높이를 꽉 채우는지 확인한다. 막대를 탭하면 위에 "N개"가 나타나고, 다른 곳을 누르면 사라진다.
3. **차트 키보드**: Tab으로 막대에 포커스가 가고 값이 표시되는지 확인한다.
4. **단어장 카드**: 기본 3종은 초급(초록), 중급(인디고), 고급(보라) 태그가 보이고, 사용자가 만든 단어장은 회색 "내 단어장"이다.
5. **진행률 바**: 학습 기록이 없으면 0%, 기록이 있으면 비율만큼 채워지는지 확인한다. 바 높이는 얇은(h-1.5) 게이지다.
6. **퀵 액션**: 레이어 아이콘은 플래시카드, 재생 아이콘은 퀴즈로 이동하고, 뒤로 가기 시 단어장 목록으로 돌아오는지 확인한다.
7. **계정 드롭다운**: 닉네임 칩을 누르면 칩 아래에 메뉴가 뜬다. 바깥 클릭과 ESC로 닫히고, 칩을 다시 누르면 토글된다.
8. **CSV 백업**: "내 단어장 CSV 백업"을 누르면 `보다보카-단어장-YYYYMMDD.csv`가 내려받아지고, 엑셀에서 한글이 깨지지 않는지 확인한다.
9. **로그아웃**: 확인 대화상자가 뜨고, 취소하면 아무 일도 없는지 확인한다.
10. **회원 탈퇴**: 드롭다운의 위험 구역 항목을 누르면 기존 두 단계 확인 모달이 뜨는지 확인한다.
11. **다크 모드**: 헤더 테마 버튼으로 전환한 뒤 드롭다운, 차트, 태그, 진행률 바의 색이 어둡게 바뀌는지 확인한다.
12. **콘솔 오류**: 새로고침 후 콘솔에 오류가 없는지 확인한다. Lucide 아이콘이 모두 SVG로 바뀌었는지 확인한다.
13. **통계 실패 시**: 네트워크를 끊고 단어장 화면을 열어, 요약 영역에만 "통계를 불러오지 못했습니다"가 보이고 목록은 정상인지 확인한다.
