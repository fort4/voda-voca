## 2. 표제어 실시간 검색 (`core/search.js`)

- **300ms trailing 디바운스**: 입력이 멈춘 뒤 300ms가 지나야 요청합니다. 중간 입력 값은 보내지 않습니다.
- **요청 취소**: 새 검색을 보내기 직전에 이전 `AbortController`를 abort합니다. 취소로 생긴 `AbortError`는 오류로 알리지 않습니다.
- **오래된 응답 버림**: 요청마다 증가하는 번호를 붙입니다. 응답이 도착했을 때 번호가 최신이 아니면 화면에 반영하지 않습니다. 취소가 늦게 도착해도 이 검사로 막습니다.
- **같은 검색어 억제**: 바로 앞에 보낸 검색어와 같으면 다시 보내지 않습니다. 실패한 검색어는 다음 입력에서 재시도하도록 기억을 비웁니다.
- **즉시 실행과 취소**: `flush()`는 디바운스를 건너뛰고 바로 검색합니다 (지우기 버튼, 화면 진입, 등록 뒤 새로고침). `cancel()`은 대기 중 검색과 진행 중 요청을 모두 멈춥니다 (화면 이탈).
- **페이지 초기화**: 검색어가 바뀌면 페이지는 1로 돌아가고, 기존 결과는 흐리게(`opacity-50`) 유지한 채 새 결과를 기다립니다.
- **더 보기 보호**: `token` 값을 검색어가 바뀔 때마다 올립니다. 더 보기 응답이 옛 검색어 것이면 버립니다.

## 3. 북마크 토글 (`core/bookmark.js`, 낙관적 UI)

- **즉시 전환**: 별을 누르면 화면이 바로 바뀌고, 요청은 뒤에서 보냅니다. 전환 시점에 `pending`(전송 중)을 켭니다.
- **PUT과 DELETE**: 목표 상태가 `true`면 `PUT`, `false`면 `DELETE`를 보냅니다. 두 호출은 멱등입니다 (API 규격 §3.4).
- **연타 합치기**: 요청이 진행 중이면 새 요청을 쌓지 않고 **최종 원하는 상태만** 기억합니다. 응답이 오면 그 상태가 서버와 다를 때만 한 번 더 보냅니다.
  - 테스트로 확인한 예: 해제 상태에서 `켜기 → 끄기`를 연타하면 `PUT` 한 번 뒤 `DELETE` 한 번을 보냅니다. `켜기 → 끄기 → 켜기`를 연타하면 `PUT` 한 번만 보냅니다.
- **실패 시 되돌림**: 요청이 실패하면 서버 상태로 되돌리고, 토스트로 알립니다. 단어가 사라졌다는 404이면 목록을 새로 받습니다.
- **상태 표현**: 별의 `aria-pressed`와 `aria-busy`로 상태를 나타냅니다. 채움 표시는 `app.css`의 `[aria-pressed="true"] svg` 규칙이 맡으므로, Lucide가 SVG를 나중에 바꿔도 상태가 유지됩니다.

## 4. 단건 등록·수정·삭제 (`views/word-form.js`)

- **검증**: 표제어 1~100자, 뜻 1~200자, 예문 0~500자 (선택). 서버와 같은 제한값을 씁니다 (`core/validate.js`).
- **비동기 확인 흐름**: 저장 요청은 SweetAlert2의 `preConfirm`에서 보냅니다. 실패하면 모달을 닫지 않고 오류를 보여 줍니다.
  - 409는 표제어 칸 아래와 모달 메시지에 표시합니다.
  - 422는 칸별 오류로 바꿉니다.
- **변경 필드만 PATCH**: 원래 값과 비교해 바뀐 필드만 보냅니다. 아무것도 바뀌지 않았으면 요청하지 않습니다. 예문은 `null`로 지울 수 있습니다 (`diffWord()`, 테스트 3건).
- **삭제**: 수정 모달의 "삭제" 버튼은 모달을 먼저 닫고, 그다음 확인 다이얼로그를 띄웁니다. SweetAlert2 창을 겹치지 않기 위해서입니다. 확인 문구에 북마크와 학습 기록도 함께 삭제된다고 적습니다 (REQ-011).

## 5. 일괄 등록 (`lib/csv.js`, `views/bulk-import.js`)

### 5.1 파싱 (클라이언트 전담, 결정 3)
- **구분자**: `.tsv` 파일이면 탭, 그 밖은 첫 내용 줄에 탭이 있으면 탭, 없으면 쉼표입니다.
- **RFC 4180 에 가까운 파서**: 큰따옴표로 감싼 필드, 안의 구분자와 줄바꿈, `""` 이스케이프를 처리합니다. CRLF와 LF를 모두 받고, BOM은 걷어냅니다. 완전히 빈 줄은 버립니다.
- **닫히지 않은 따옴표**: `CsvParseError`로 알리고, 시작 줄 번호를 붙입니다.
- **헤더 행**: 첫 줄이 `표제어,뜻` 또는 `term,meaning`(대소문자 무시)이면 건너뜁니다.
- **깨진 인코딩**: 디코딩 결과에 U+FFFD가 있으면 "UTF-8로 저장한 뒤 다시 선택해 주세요"로 안내합니다.
- **파일 크기**: 256KB를 넘으면 읽지 않습니다.

### 5.2 검증
- **행 오류**: 빈 표제어, 빈 뜻, 글자 수 초과, 열 세 개 초과(쉼표나 탭이 잘못된 경우를 잡음).
- **요청 안 중복**: 대소문자와 악센트를 무시하고 비교합니다 (`termKey()`: NFKD 분해 후 결합 기호 제거, 소문자화). 뒤에 나온 행에 "N행과 같은 표제어입니다"를 붙입니다.
- **100건 제한**: 101건 이상이면 전송을 막고, 나눠 등록하면 원자성이 없다는 점을 안내합니다.
- **오류 행 처리**: 오류가 하나라도 있으면 전송 버튼을 막습니다. "오류 행만 보기" 토글로 행을 걸러 봅니다.

### 5.3 전송과 응답 처리
- **페이로드**: `{"items": [{term, meaning, example}]}`만 보냅니다. 행 번호와 구분자 정보는 보내지 않습니다. 빈 예문은 `null`입니다.
- **201**: 모달을 닫고, 토스트로 등록 개수를 알린 뒤 목록을 새로 받습니다.
- **409**: 응답의 `conflict_term`과 요청 표기가 정확히 같은 **첫 행**을 붉게 강조하고, 배너에 메시지를 씁니다. `conflict_term`이 `null`이면 배너만 보입니다.
- **422**: 응답의 `loc`에서 `["body","items",i,…]`의 `i`를 꺼냅니다. 전송 목록의 `i`번째가 화면의 `i`번째 유효 행이므로 그 행에 메시지를 붙입니다. `["body"]`처럼 요청 전체 오류는 배너에 씁니다.
- **401**: 전역 세션 만료 흐름에 맡기고, 모달을 닫습니다.
- **404**: 단어장이 없다는 배너를 띄웁니다.

### 5.4 화면 구성 결정
- 미리보기는 **카드 목록**으로 통일했습니다. UI 설계서는 데스크톱에서 표를 쓰라고 했지만, 1차에서는 한 가지 구현으로 모든 폭을 지원하는 쪽을 택했습니다. 표 전환은 후속 개선으로 남깁니다.
- 직접 입력 칸에 붙여넣은 내용과 파일 내용은 같은 입력칸을 씁니다. 파일을 고르면 내용이 입력칸에 들어가 사용자가 고칠 수 있습니다.

### 7.3 테스트가 잡은 실제 결함
- **CSV 줄 번호 오류**: 레코드의 시작 줄을 기록하는 순서가 잘못되어, 두 번째 이후 레코드의 줄 번호가 한 줄 앞서 있었습니다. 이 값은 오류 메시지의 "N행"에 쓰이므로 사용자에게 잘못된 행을 가리키게 됩니다. `endRecord()` 호출 전에 줄 번호를 먼저 올리도록 고쳤습니다. 테스트 `parseDelimited: 기본 CSV 와 CRLF`와 `빈 줄은 버리고 BOM`이 이 결함을 잡았습니다.
- **테스트 파일 문법 오류**: 테스트 제목 문자열 안의 `""`가 따옴표를 닫아 파일 전체가 로드되지 않았습니다. 제목을 백틱 문자열로 바꿨습니다.

## 8. 알려진 한계와 후속 과제
- **브라우저 미검증**: 화면 동작은 아직 실제 브라우저에서 확인하지 않았습니다. 수동 체크리스트(보고 메시지 참고)로 확인해야 합니다.
- **클라이언트 중복 판정**: `termKey()`는 서버 콜레이션과 완전히 같은 규칙이 아닙니다. 최종 판정은 서버 409·422가 합니다. 클라이언트가 막지 못한 중복은 서버가 잡습니다.
- **미리보기 카드화**: 데스크톱 표 전환은 하지 않았습니다.
- **단어 목록 학습 진입**: 플래시카드와 퀴즈 시작 버튼은 3단계 범위입니다.
- **일괄 등록 후 목록**: 등록 뒤에는 검색어를 유지한 채 목록을 새로 받습니다.
