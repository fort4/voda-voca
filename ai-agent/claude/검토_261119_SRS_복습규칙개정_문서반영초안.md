# 검토 — SRS 복습 규칙 개정(REQ-150)의 `docs/` 반영 초안

`docs/` 는 승인 후에만 수정하므로 이 초안을 사용자가 승인하면 해당 문서에 반영하고 변경 이력 행을 추가한다.
(구현은 이미 끝났다. 테스트: 전체 pytest 557건, node 463건, 커버리지 98%.)

## 개정 내용 (사용자 확정 2026-11-19)
| # | 이전 | 개정 | 이유 |
| :-: | :--- | :--- | :--- |
| 1 | 다음 복습 시각 = 답한 시각 + 간격 | **간격일 뒤 한국 날짜의 0시** (`kst_day_start`) | 밤 11시에 맞힌 단어가 다음 날 오전에 열면 기한 전이 되는 문제 |
| 2 | 기한 전 정답도 단계 +1 | **기한(`next_review_at`) 전 정답은 단계·시각 유지** (정답 수·연속 정답·숙련은 평소대로). 오답은 기한과 무관하게 −2 | 같은 날 30분 사이 3번 맞히면 단계 3(7일 뒤)이 되던 문제 |

변경 코드: `services/srs.py`(`kst_day_start`, `schedule_next` 에 `current_due`), `services/progress.py`, `services/stats.py`(`KST_OFFSET` 공유). **스키마·마이그레이션 변경 없음.**
기존 행의 `next_review_at` 은 옛 규칙으로 저장되어 있으나 다음 답부터 새 규칙을 따른다.

## 반영 대상과 문구

### 1. Requirement_Spec_v2.2_261119.md — REQ-150
- `다음 복습 시각을 `지금 + 단계별 간격`(0·1·3·7·14·30일)으로 정한다.` →
  `다음 복습 시각을 **간격일 뒤 한국 날짜의 0시**(간격 0·1·3·7·14·30일)로 정한다(그 날 하루 종일 "오늘 복습"에 뜬다). 복습 기한이 되기 전에 맞힌 정답은 단계와 복습 시각을 바꾸지 않고(정답 수·연속 정답·숙련 판정은 평소대로 쌓는다), 오답은 기한과 무관하게 단계를 내린다.`
- 변경 이력 행: `v2.2 개정 | 2026-11-19 | REQ-150 개정: 복습 시각을 한국 날짜 0시로, 기한 전 정답은 단계·시각 유지`

### 2. Data_Design_v2.2_261119.md — §3.4
- `next_review_at` 컬럼 설명 끝: `단계별 간격 0·1·3·7·14·30일` → `...이며, 답한 시각이 아니라 간격일 뒤 한국 날짜 0시(UTC 로 저장)다`
- 복습 단계 규칙 문단: `next_review_at = 답 시각 + 새 단계의 간격` → `next_review_at = (답한 시각이 속한 한국 날짜의 0시) + 새 단계의 간격(일)`, 이어서 "기한 전 정답은 단계·`next_review_at` 유지, 오답은 기한과 무관하게 감쇠, NULL 이면 기한 전이 아님, 옛 값은 마이그레이션 없이 다음 답부터 새 규칙" 추가
- 변경 이력 행: `v2.2 개정 | 2026-11-19 | SRS 복습 시각 규칙 개정(REQ-150). 스키마·마이그레이션 변경 없음`

### 3. Decision_Records_v1.0_261119.md — ADR-006
- 결정 7: 다음 복습 시각은 간격일 뒤 한국 날짜 0시 (이유와 대안 "답한 시각 + 간격" 기각)
- 결정 8: 기한 전 정답은 단계·시각 유지 (실측: 30분 사이 3번 정답 → 단계 3, 7일 뒤. 대안 "기한 전 정답도 상승" 기각)
- 대안 표에 위 두 행 추가, 변경 이력 행 추가

### 4. Test_Specification_v1.1_261119.md
