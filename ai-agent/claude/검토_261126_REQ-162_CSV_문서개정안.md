## 1. 요구사항 명세 v2.3

> **REQ-162 | CSV 일괄 등록 | M** — (2026-11-26 신설, VOCA-FR-003, 이슈 #32) ① 관리자는 표준·관리자 단어장 하나를 골라 CSV 파일로 단어를 올린다. ② 상한은 1회 500행(열 이름 줄·빈 줄 제외), 파일 512KB. ③ 인코딩은 UTF-8(BOM 허용). 아니면 거부하고 "CSV UTF-8" 저장을 안내한다. ④ 첫 줄은 열 이름이다. `term`, `meaning` 필수, `example`, `example_meaning` 선택, 순서 무관, 대소문자·앞뒤 공백 무시. 그 밖의 열·이름 없는 열·중복 열은 거부한다. 빈 줄은 무시한다. 값의 규칙은 한 건 등록(REQ-161 ①)과 같다. ⑤ 상한 초과·형식 오류는 파일 전체를 거부하고, 오류 행 번호(첫 줄이 1)와 이유를 앞에서 20행까지 알린다. ⑥ 같은 단어장의 표제어 중복(대소문자·악센트 무시, 파일 안의 중복 포함)은 건너뛰고 건수를 보고한다. 기존 단어는 바꾸지 않는다. ⑦ 요청 1회, 트랜잭션 1회. 등록 건수와 건너뛴 건수를 보여 준다. 등록한 단어는 관리자 등록분이다(REQ-161 ③~⑥ 적용).

## 2. API 연동 규격서 v2.2

| # | 메서드·경로 | 본문 | 성공 | 실패 |
| :-: | :--- | :--- | :-: | :--- |
| 26 | `POST /api/admin/vocabularies/{vocabulary_id}/words/import` | CSV 원문, `Content-Type: text/csv` | 200 `{"created": n, "skipped": n}` | 400, 401, 403, 404, 413, 415 |

- 400 `CSV_INVALID`: `{"detail": string, "errors": [{"row": n, "message": string}]}`. 인코딩·행 수 초과처럼 파일 전체의 문제면 `errors` 는 빈 배열이다. 422 의 `detail` 은 필드 오류 배열이라 쓰지 않았다.
- 413 `CSV_TOO_LARGE`: 512KB 초과. `Content-Length` 가 없어도 읽는 도중에 멈춘다.
- 415: `text/csv` 가 아님.
- §1.5 입력 제한, §4 상태 코드 표(413·415), §5.3 래퍼의 `contentType` 옵션을 더한다.

## 3. 아키텍처 설계서·결정 기록·데이터 설계서

- 아키텍처 §5: `services/csv_import.py`(DB 없는 파싱·검증) 추가. 저장은 `services/admin_content.py`.
- **ADR-013 (신설)** CSV 를 원문 본문으로 받고, 받는 동안 쓰기 잠금을 놓는다.
  - 배경: 모든 트랜잭션이 `BEGIN IMMEDIATE`(ADR-010)라 권한 확인 조회만으로 쓰기 잠금을 잡는다. 그대로 본문을 받으면 느린 업로드가 다른 사용자의 쓰기를 막는다.
  - 결정: ① `multipart` 대신 `text/csv` 원문(`python-multipart` 의존성 없음) ② 권한 확인 뒤 `commit` 하고 본문을 읽는다 ③ 파싱·검증을 모두 마친 뒤 새 트랜잭션 하나로 저장한다.
  - 대안: `multipart`(의존성 추가), 화면에서 CSV 를 JSON 으로 바꿔 보내기(검증 규칙이 두 곳에 생김).
  - 결과: 잠금 시간이 저장 구간으로 한정된다. 본문을 받는 사이 단어장이 지워지면 404 다.
- 데이터 설계서: 스키마 변경 없음. 개정 불필요.

## 4. UI/UX 설계서

- 탐색 카드(관리자): 단어 시트를 여는 버튼 이름이 "미리보기"가 아니라 **"단어 관리"**(아이콘 `list-checks`)다. 표준·관리자 단어장 모두. 시트의 접근성 이름도 같다. 일반 사용자는 그대로다 (2026-11-26 사용자 결정). §3 의 REQ-160·161 "관리자" 항목에 반영한다.
- 단어 시트(관리자): "단어 추가" 옆에 "CSV 등록"(2열).
- 등록 모달: 형식 안내 2줄, 파일 선택(`.csv`), 등록·취소. 선택 안 함·확장자·크기는 보내기 전에 알린다. 실패하면 모달을 연 채 이유와 오류 행 목록(스크롤)을 보인다. 성공하면 결과 모달(등록·건너뜀 건수) 뒤 목록과 단어 수를 새로 고친다.
