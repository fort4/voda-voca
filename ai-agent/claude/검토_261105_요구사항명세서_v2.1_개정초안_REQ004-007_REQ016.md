## 0. 결정이 필요한 사항 (먼저 읽어 주세요)

요구사항 ID 체계 규칙: "번호는 재사용하지 않으며, 폐기 시 상태만 `폐기`로 바꾼다". 그런데 REQ-004~007 은 "내 단어장 생성·조회·수정·삭제"라서 **의미가 통째로 바뀐다.** 두 가지 방식이 있다.

| 안 | 내용 | 장단점 |
| :--- | :--- | :--- |
| **A (이 초안의 선택)** | REQ-004~007 은 `폐기` 처리하고, 후속 요구사항 REQ-140~143 을 신설한다. 추적표에 "대체" 열을 둔다 | ID 규칙 준수, 과거 이슈·커밋의 REQ-004 언급이 옛 의미로 남아 혼동 없음. 문서가 약간 길어짐 |
| B | ID 를 유지한 채 제목·기준만 새 의미로 덮어쓴다 (예: REQ-004 = 카탈로그 조회) | 문서가 짧음. 옛 코드·테스트 주석의 `REQ-004` 가 다른 뜻이 되어 추적성이 깨짐 |

B 를 원하시면 §1 의 REQ-140~143 을 REQ-004~007 자리에 그대로 옮기면 된다 (내용은 같다).
REQ-016 은 의미가 이어지므로 **ID 를 유지하고 기준만 고친다.**

### 1.2 신설

| ID | 요구사항 | 우선순위 | 상세 기준 (Acceptance Criteria) |
| :--- | :--- | :---: | :--- |
| REQ-140 | 표준 단어장 카탈로그 조회 | M | 로그인한 사용자는 서버가 제공하는 표준 단어장 목록을 조회한다 (`GET /api/vocabularies`). 항목마다 `slug`, `title`, `category`, `level`, `description`, `total_words` 와 **본인의 진행률**(`studied_words`, `memorized_words`, `progress_rate`, `is_active`)을 포함한다. `category`, `level` 쿼리로 거를 수 있다 (`level` 1~5, 범위 밖은 422). 진행률은 단어장별 `GROUP BY` 한 번으로 구한다 (N+1 금지). 비로그인은 401. 사용자는 단어장을 만들거나 고치거나 지울 수 없으며 해당 경로는 존재하지 않는다 (별도 410 응답 없음). |
| REQ-141 | 표준 단어 목록 조회 | M | 단어장 안의 단어를 읽기 전용으로 조회한다 (`GET /api/vocabularies/{id}/words`, `page`/`size`, 본인 북마크 여부 포함). 없는 단어장은 404. 단어는 `term`, `meaning`, `example`, `example_meaning` 을 가진다 (예문이 없으면 `example_meaning` 도 NULL). |
| REQ-142 | 활성 단어장 설정 | M | 사용자는 학습할 단어장 하나를 고른다 (`POST /api/users/me/active-vocabulary`, 본문 `{"vocabulary_id"}`). 성공하면 그 단어장의 카탈로그 항목을 돌려주고, 같은 값을 다시 보내도 성공한다. 없는 단어장은 404. 활성 단어장이 없는 사용자가 세션을 시작하면 첫 단어장이 자동으로 활성이 된다. 활성 단어장이 삭제되면 `NULL` 로 돌아간다 (`ON DELETE SET NULL`). |
| REQ-143 | 표준 단어장 시드 | M | 콘텐츠는 서버 시드 파일로만 바뀐다. 앱 시작 시 멱등으로 적재한다 (`slug` 가 멱등 키, `content_hash` 가 같으면 쓰기를 생략). 초기 범위는 초급·중급·고급 각 200단어(총 600)다. `category` 는 자유 문자열이며 새 카테고리는 스키마 변경 없이 시드만으로 추가한다. |

## 2. §4.4 REQ-016 — 개정안 (ID 유지)

### 2.1 현행 (v2.0)

> 퀴즈 제출 시 **문항별 정답 여부와 제출 시각**을 저장한다. 사용자의 최근 학습 이력 **100건을 최신순**으로 조회할 수 있다 (Q5 확정: 1차 포함). 한 퀴즈의 기록은 단일 트랜잭션으로 저장한다.

### 2.2 개정 (v2.1)

| ID | 요구사항 | 우선순위 | 상세 기준 (Acceptance Criteria) |
| :--- | :--- | :---: | :--- |
| REQ-016 | 학습 이력 기록 | S | 학습 세션(`/study/session`)에서 **문항에 답할 때마다**(`POST /api/study/sessions/{id}/answer`) 그 답 1건의 **정답 여부, 학습 모드(`quiz`/`flashcard`), 기록 시각**을 `study_logs` 에 저장한다. 플래시카드는 "알아요"를 정답, "헷갈려요"를 오답으로 기록한다. 이력 1건의 기록과 사용자×단어 진행도(`user_word_progress`: 정답·오답 횟수, 연속 정답, 숙련 여부) 갱신은 **하나의 트랜잭션**이다. 같은 문항에 같은 답을 다시 보내면 이력을 늘리지 않고 같은 응답을 돌려주며(멱등), 다른 답으로 바꾸려 하면 409 `QUIZ_ANSWER_LOCKED` 이다. 사용자의 최근 학습 이력 **100건을 최신순**으로 조회할 수 있다 (`GET /api/study/logs`). 이 이력은 학습 통계(`GET /api/study/stats`)와 오답 단어 목록(`GET /api/study/wrong-words`, 단어별 **마지막 결과가 오답**인 단어)의 근거다. |

바뀐 점과 이유:

| 항목 | v2.0 | v2.1 | 이유 |
| :--- | :--- | :--- | :--- |
| 기록 시점 | 퀴즈 **제출** 시 일괄 | 문항 **답변** 시 즉시 | 중간에 닫아도 푼 답이 남는다 (이슈 #8, 구현은 2026-11-03 부터). v2.0 문구가 실제 동작과 달랐다 |
| 트랜잭션 단위 | 퀴즈 1회 | 답 1건 (이력 + 진행도) | 동시 요청에서도 진행도 카운트가 정확하다 (행 잠금) |
| 학습 모드 | 퀴즈만 | `quiz` + `flashcard` | 플래시카드가 세션 러너로 통합됨 (통합 설계안 결정 5) |
| 참조 대상 | 개인 `words` | `system_words` | 중앙 제공형 전환 (REQ-140) |
| 제출 API | `/api/study/quiz/sessions/*` | `/api/study/sessions/*` | 옛 퀴즈 API 는 D단계에서 제거됨 |

§7 추적 행 (개정): `REQ-016 | 학습 이력 기록 | S | Data Design(study_logs, user_word_progress) | src/backend/services/study_log.py, services/learning_session.py, routers/study_session.py, routers/study.py | test_study_log_progress.py, test_learning_session_api.py, test_study_logs_api.py | 구현 완료`
