## 2. 백엔드

### 2.1 스키마 (마이그레이션 `3384caa6f116`)
- `users.email` 컬럼과 `uk_users_email` 고유 키를 제거했습니다.
- `nickname`에 `uk_users_nickname` 고유 키를 추가했습니다. 같은 닉네임은 대소문자와 무관하게 한 개만 존재합니다 (DB 콜레이션 `utf8mb4_0900_ai_ci`).
- **안전장치**: 업그레이드 전에 중복 닉네임을 검사하고, 있으면 중단합니다. 데이터를 임의로 고치지 않습니다.
- **내리기**: `nickname` 고유 키를 되돌리고 `email`을 NULL 허용으로 다시 만듭니다. 제거된 이메일 값은 복구되지 않습니다. 이 점은 마이그레이션 주석에 명시했습니다.
- 적용 전 확인: 현재 `users`에는 행 1개가 있고 중복 닉네임은 없었습니다.

### 2.2 가입과 로그인
- 가입 입력은 `{nickname, password}`입니다. 닉네임은 공백 제거 후 **2~30자**, 비밀번호는 **8자 이상, 72바이트 이하**입니다.
- 로그인 입력은 `{nickname, password}`입니다. 로그인 쪽 검증은 느슨하게 두었습니다. 없는 닉네임은 422가 아니라 401입니다. 입력 길이 상한만 200자로 둡니다.
- 닉네임 중복은 DB 제약 위반으로 판정해 **409** `이미 사용 중인 닉네임입니다.`를 돌려줍니다 (동시 요청에도 안전).
- 응답 `UserOut`은 `{id, nickname, created_at}`입니다. 예전 `email` 필드를 보내도 무시합니다.

### 2.3 레이트 리미터 (REQ-121)
- 계정 차단 키를 이메일에서 **닉네임**으로 바꿨습니다 (`acct:<닉네임 소문자>`). IP 키 동작은 그대로입니다.

### 2.4 회원 탈퇴: `DELETE /api/auth/me`
- 인증이 필요합니다. 쿠키가 없거나 만료되었으면 401이고, 아무것도 지우지 않습니다.
- `users` 행을 지우면 DB의 `ON DELETE CASCADE`가 다음을 함께 지웁니다: 세션, 단어장, 단어, 북마크, 학습 이력, 퀴즈 세션.
- 응답은 **204**이고, 세션 쿠키를 `Max-Age=0`으로 만료시킵니다.
- 탈퇴한 닉네임은 다시 가입할 수 있습니다.

### 2.5 테스트 갱신
- 공통 헬퍼를 닉네임 기준으로 바꿨습니다 (`unique_nickname`, `signup_and_login`). 정리 패턴은 `tvoda-%`입니다.
- 인증 API 테스트를 전면 다시 썼습니다. 추가한 검증:
  - 탈퇴 성공, 그리고 연관 행 전부가 사라졌는지 확인 (세션, 단어장, 단어, 북마크, 학습 이력, 퀴즈 세션)
  - 쿠키 없음과 만료 쿠키는 401이고 아무것도 지우지 않음
  - 탈퇴 후 옛 쿠키 무효, 같은 닉네임 재가입 가능
  - 다른 사용자는 영향 없음
  - 이메일 필드가 응답에 없음, 이메일을 보내도 무시됨
- 닉네임 경계 테스트 (2자 허용, 1자 거부, 30자 허용, 31자 거부, 공백 제거 후 길이 기준) 추가

### 2.6 한 번 실패했다가 통과한 테스트
- 첫 전체 실행에서 `test_selective_prefix_search_uses_unique_index`가 한 번 실패했습니다. 이메일 참조를 고친 뒤 **3회 연속 전체 실행에서 모두 통과**했습니다.
- 원인은 확인하지 못했습니다. 이메일 참조 수정과 맞물린 우연일 수도 있고, 실행 순서나 테이블 통계에 따른 간헐적 문제일 수도 있습니다. 재현되면 원인을 따로 조사하겠습니다.

## 3. 프론트엔드

### 3.1 디자인 시스템 (`css/app.css`, `index.html`)
- **토큰**: 배경 zinc-50, 표면 흰색, 보더 zinc-200, 본문 zinc-900, 포인트 indigo-600, 위험 red-600. 카드 반경 16px, 컨트롤 반경 12px.
- **그림자**: 카드용 얇은 그림자와 떠오름용 그림자를 나눴습니다. 보더는 zinc-200을 기본으로 씁니다.
- **표면 클래스 `.surface`**: 기존 카드마다 흩어져 있던 `bg-white shadow-sm ring-1 ring-*` 조합을 이 한 클래스로 바꿨습니다. Tailwind가 런타임에 넣는 유틸리티와 순서가 섞여 토큰을 가리는 일을 막기 위해서입니다.
- **인터랙션**: 누를 수 있는 카드는 호버에 1px 떠오르고, 누르면 가라앉습니다. 버튼은 누르면 0.97배로 줄어듭니다. 키보드 포커스 링은 인디고로 분명하게 보입니다.
- **헤더**: 블러 배경과 얇은 하단 보더, 브랜드 마크를 씁니다.
- **하단 탭바**: 알약형 활성 인디케이터, 안전 영역(`env(safe-area-inset-bottom)`) 대응.
- **접근성**: 동작 줄이기를 켜면 모든 애니메이션과 전환을 끕니다.

### 3.2 간소화된 인증 폼
- 로그인과 가입 모두 **닉네임과 비밀번호만** 받습니다. 이메일 입력은 없습니다.
- 가입 폼은 닉네임 칸 아래에 "2~30자, 다른 사람과 겹치지 않는 이름" 안내를 둡니다.
- 닉네임 중복은 409를 **닉네임 칸**에 표시합니다.
- 로그인 429 카운트다운은 그대로 유지합니다.

### 3.3 단어장 상세의 삭제 액션 (`views/words.js`)
- 헤더를 세 줄로 나눴습니다. 제목, 2×2 액션 격자(플래시카드, 퀴즈, 일괄 등록, 단어 추가), 그리고 **오른쪽 아래의 [단어장 삭제]** 위험 액션입니다.
- 아이콘만 두지 않고 글자를 항상 보여 줍니다. 좁은 화면에서도 위험 액션을 놓치지 않게 하기 위해서입니다.
- 삭제 확인 창은 CASCADE 범위를 적습니다: 모든 단어, 북마크, 학습 기록이 영구 삭제되고 되돌릴 수 없다는 내용입니다. 성공하면 `#/wordbooks`로 이동합니다.

### 3.4 계정 메뉴와 회원 탈퇴 (`app.js`)
- 상단의 **닉네임 칩**(첫 글자 아바타 + 닉네임)을 누르면 계정 메뉴가 열립니다. 메뉴에는 로그아웃과 회원 탈퇴가 있습니다.
- **회원 탈퇴는 두 단계로 확인합니다.**
  1. 경고 확인: 계정과 모든 데이터가 영구 삭제된다는 내용
  2. 최종 확인: 닉네임을 **정확히 입력**해야 "탈퇴하기"가 활성화됩니다. 입력 검증은 `nicknameConfirmationMatches()`가 맡습니다 (앞뒤 공백만 무시하고 대소문자는 구분).
- 탈퇴가 성공하면 세션 저장소를 비우고, 사용자 상태를 지우고, 탭바를 숨기고, 로그인 화면으로 이동합니다.
- 로그아웃도 같은 방식으로 퀴즈 결과 캐시를 지웁니다.

### 3.5 플래시카드와 퀴즈 폴리싱
- **플립 카드**: 앞면과 뒷면을 `.flip-face`로 통일했습니다. 뒷면은 인디고 톤의 그라데이션과 보더를 씁니다. 뒤집기는 520ms의 부드러운 곡선입니다.
- **퀴즈 선택지**: 번호 칩을 따로 두고, 선택한 항목에는 **체크 아이콘**과 짧은 팝 애니메이션(`choice-selected`)을 줍니다. 버튼 높이는 44px 이상입니다.
- 문제 카드도 표면 클래스로 바꾸고 진입 애니메이션을 줍니다.

### 3.6 정리
- 이메일이 남은 곳을 찾아 제거했습니다 (`state.js` 타입 정의, `api.js` 주석).
- 검증 테스트는 이메일 규칙을 닉네임 규칙으로 바꾸고, 탈퇴 확인 테스트를 추가했습니다.

## 4. 설계 판단

| 항목 | 판단과 이유 |
| :--- | :--- |
| 닉네임 대소문자 | DB 콜레이션이 맡습니다. `Apple`과 `apple`은 같은 닉네임입니다. 로그인도 대소문자와 무관합니다 |
| 로그인 검증 완화 | 없는 닉네임에 422를 주면 형식을 노출하게 됩니다. 401로 통일해 계정 존재 여부를 숨깁니다 |
| 탈퇴 2단계 확인 | 되돌릴 수 없는 동작이라 경고 확인과 닉네임 입력 확인을 함께 둡니다 |
| 탈퇴 시 세션 저장소 전체 비우기 | 이 앱이 쓰는 저장소는 퀴즈 결과 캐시뿐이므로 전체를 비워도 다른 데이터를 잃지 않습니다 |
| 위험 액션의 위치 | 단어장 삭제는 화면 맨 아래에 두어 실수로 누를 가능성을 낮춥니다. 글자 라벨을 씁니다 |

## 5. 열린 사항

1. **기존 계정의 이메일 소실**: 마이그레이션으로 `users.email`을 제거하면서, 현재 DB의 기존 계정 1건의 이메일 값이 사라졌습니다. 요청하신 제거 방향에 따른 결과이지만, 되돌릴 수 없는 데이터 손실이므로 기록해 둡니다.
2. **설계서 미반영**: 다음 문서가 아직 이메일 기준입니다. 프론트엔드 마일스톤 완료 후 일괄 승격 정책에 따라 함께 갱신합니다.
   - 요구사항 명세 REQ-001 (계정), 데이터 설계서 §3.1 (users 테이블), API 연동 규격 §3.1 (가입·로그인 본문), 회원 탈퇴 API 추가
3. **브라우저 확인 대기**: 디자인 개편과 탈퇴 흐름은 실제 브라우저에서 아직 확인하지 않았습니다. 아래 가이드를 따라 확인해야 합니다.
4. **간헐 실패 조사 보류**: §2.6의 테스트 1회 실패는 재현되지 않았습니다. 재현되면 조사합니다.
