### 1.2 세션 스냅샷
퀴즈·플래시카드 문항은 세션 생성 시 `quiz_sessions.questions` JSON 에 **스냅샷**으로 저장되고(`study.py:117`, `learning_session.py:73 _flashcard_question`), 채점 응답은 이 스냅샷으로 만듭니다. 따라서 새 키를 스냅샷에 넣어야 하며, **이미 진행 중인 세션에는 키가 없을 수 있어** 읽을 때 `.get("phonetic")` 로 null 처리해야 합니다.

### 1.3 숨은 함정 두 가지

1. **content_hash**: 시드 로더는 해시가 같으면 단어장을 건드리지 않습니다. 해시 입력(`compute_content_hash`)과 변경 비교 튜플에 `phonetic` 을 넣지 않으면 JSON 에 발음기호를 채워도 **DB 에 반영되지 않습니다.** 해시 입력을 바꾸면 세 단어장의 해시가 모두 바뀌어 **첫 시작 때 한 번 재적재**됩니다(실제 변경은 `phonetic` 뿐이라 안전).
2. **pytest 가 개발 DB 를 쓴다**: `test_real_seed_loads_600_words_and_is_idempotent` 가 실제 시드를 **개발 DB 에 적재**합니다(테스트 주석: "개발 DB 에 600단어가 남는다"). 시드 JSON 에 발음기호가 들어간 뒤 전체 `pytest` 를 돌리면 **DB 의 `phonetic` 600행이 UPDATE** 됩니다. `CLAUDE.md` §6 은 상태 변경 DB 명령에 사전 승인을 요구하므로, 데이터 병합 단계에서 백업과 명시적 승인을 거칩니다(§4 단계 3).

### 1.4 데이터 성격 (600단어 분석)
- 고유 600개, 전부 **소문자 알파벳 한 단어**(공백·하이픈·아포스트로피·대문자 없음). 영어 발음 사전으로 조회하기 쉬운 형태입니다.
- 품사에 따라 발음이 달라지는 단어(동형이음·강세 이동) 후보 14개: `advocate, close, deliberate, finance, frequent, house, increase, minute, object, permit, progress, read, refuse, research`. 시드의 `meaning`/`example` 에 맞는 발음을 **사람이 확인**해야 합니다.

## 3. 설계

### 3.1 DB / ORM
- **스키마 변경 없음.** `system_words.phonetic VARCHAR(100) NULL` 그대로 사용. utf8mb4 라 IPA 확장 문자(ˈ ˌ ː ə ɪ ʊ ʃ θ ð ŋ 등)를 저장할 수 있습니다. 단어 한 개의 IPA 는 100자에 한참 못 미칩니다.
- 모델 주석만 "확장 필드, 미사용"에서 "phonetic 사용(v2.2)"으로 정정하고, `pos`·`level` 만 미사용으로 남깁니다.
- 검색·인덱스에 쓰지 않으므로 콜레이션(악센트 무시)은 영향이 없습니다.

### 3.2 시드 로더 (`system_seed.py`)
- `PHONETIC_MAX = 100`, `SeedWordData.phonetic: str | None`.
- 파싱: `_text(item.get("phonetic"), "phonetic", where, PHONETIC_MAX, required=False)` 에 **IPA 문자 검증**을 더합니다. 허용: 라틴 소문자·IPA 확장(U+0250–02AF)·수정 문자(U+02B0–02FF: ˈ ˌ ː)·결합 기호(U+0300–036F)·공백. 거부: 한글, 슬래시·대괄호(표시 규칙은 UI 가 입힘), 대문자 전용 문자열, 제어 문자. NFC 정규화.
- `compute_content_hash` 의 단어 항목에 `phonetic` 추가, 갱신 비교 튜플·INSERT 딕셔너리에 `phonetic` 추가. `phonetic` 키가 없는 시드는 `None` 으로 해석해 **기존 시드 파일·테스트와 호환**합니다.
- 멱등: 같은 시드 반복 시 `unchanged`, 값만 바뀌면 `updated`(단어 UPDATE 건수에 반영), 시드에서 값을 지우면 NULL 로 되돌림.

### 3.3 API 스키마와 비노출 규격

| 스키마 | 필드 | 퀴즈 | 플래시카드 |
| :--- | :--- | :--- | :--- |
| `VocabularyWordOut` (단어 목록) | `phonetic: str \| None` | — | — (모드와 무관) |
| `SessionItemOut` (출제) | `phonetic: str \| None = None` | **항상 null** | 값 (뒷면용, 뜻과 같은 취급) |
| `SessionAnswerOut` (채점) | `phonetic: str \| None` | 값 | 값 |

- 출제 응답의 기존 패턴(플래시카드 전용 필드는 퀴즈에서 `null`)을 그대로 따릅니다(`meaning`, `example_meaning` 과 동일).
- **퀴즈 비노출 근거**: 출제 응답은 `term`, `context`, `options` 만 갖는다는 REQ-124 규격을 지킵니다. IPA 가 한국어 보기의 정답을 직접 알려 주지는 않지만, "문항에는 채점 전 정보를 최소로 싣는다"는 원칙과 서버가 값을 내려보내지 않는 쪽이 클라이언트 실수에 안전하기 때문입니다. 서버 응답에서 막고 **테스트로 고정**합니다.
- 스냅샷: `_flashcard_question` 과 퀴즈 빌더(`study.py:117`)에 `"phonetic": word.phonetic` 추가. 읽을 때는 `question.get("phonetic")` (진행 중인 옛 세션 호환).
- 모두 **추가 필드**라 하위 호환입니다(옛 클라이언트는 무시).
- 이번 범위에서 **제외**: 북마크 목록(`bookmark.py`), 오답 복습 목록(`study.py`) 응답. 요청된 세 화면이 아니며, 필요하면 후속으로 같은 규칙에 따라 추가합니다(결정 6).

### 3.4 프론트엔드

| 화면 | 배치 | 비고 |
| :--- | :--- | :--- |
| **해설 시트** (퀴즈 채점 후) | 표제어 줄: `표제어` + `/발음기호/` + 🔊. 폭이 좁으면 발음기호가 아래 줄로 감 | 플래시카드에는 해설 시트가 없음(바로 다음 카드) |
| **플래시카드 뒷면** | 뒷면 맨 위에 작은 줄 `표제어 /발음기호/`, 그 아래 뜻(큰 글씨)·예문 | 뒷면에는 표제어가 없어서 **발음기호만 덩그러니 두지 않고 표제어와 함께** 보입니다. 앞면은 지금처럼 단어만(발음기호 비표시) |
| **단어 바텀시트** | 행 첫 줄: `표제어` 옆에 `/발음기호/` 인라인 | 오른쪽의 🔊 버튼(44px)과 겹치지 않게 `min-w-0 flex-1` 유지 |
| 퀴즈 문항 화면 | 표시하지 않음 | PHN-3 |

- **순수 함수** `core/phonetic.js`: `formatPhonetic(raw)` → `/ˈæpəl/` 또는 `null`(빈 값·공백·null). 저장값에 슬래시가 섞여 들어와도 한 쌍만 남깁니다.
- **스타일** `.phonetic`: 글자 크기 `--fs-caption`(13px), 색 `--muted`, 굵기 400, `letter-spacing: 0`(전역 -0.01em 은 IPA 에 어울리지 않음), `white-space: nowrap`. 색은 토큰만 쓰므로 다크 모드가 자동으로 따라옵니다. `dark-theme.test.js` 의 컴포넌트 검사 대상에 `phonetic` 접두를 추가합니다.
- **글리프 커버리지**: Pretendard 는 IPA 확장 글리프를 모두 갖지 않을 수 있어 일부 문자가 시스템 폰트로 대체됩니다. `--font-ipa` 스택(Pretendard Variable → "Noto Sans", "Segoe UI", "Lucida Sans Unicode", system-ui)을 두고, 대체 폰트에서 기준선·굵기가 어색하면 Google Fonts 의 Noto Sans 를 `unicode-range: U+0250-02FF` 서브셋으로 추가하는 안을 후속 후보로 둡니다. **실제 렌더링은 기기에서 직접 확인해야 합니다**(수동 점검 매트릭스).
- **접근성**: IPA 는 스크린리더가 어색하게 읽으므로 `.phonetic` 은 `aria-hidden="true"` 로 시각 전용으로 두고, 발음은 기존 🔊 버튼(REQ-125)이 맡습니다. `lang="en-fonipa"` 는 부여하지 않음(지원 불균일).
- null 이면 요소 자체를 그리지 않아 레이아웃이 그대로입니다.

### 3.5 IPA 데이터 확보 (가장 큰 위험)
600개를 즉흥적으로 쓰면 오류가 섞일 수 있어, **출처가 분명한 사전을 변환**하는 방식을 제안합니다.

- **원천**: CMU Pronouncing Dictionary(CMUdict, BSD 계열 라이선스, 미국식 ARPAbet). 변환표(ARPAbet→IPA)로 IPA 를 만듭니다. 영어 단일 단어 600개는 거의 모두 수록되어 있을 것으로 예상합니다.
- **도구**: 일회성 스크립트를 `ai-agent/claude/` 에 두고(앱 코드 아님), 임시 가상환경에서 실행합니다(프로젝트 `.venv` 를 건드리지 않음). 패키지 설치와 네트워크 사용은 승인 후 진행합니다.
- **검수 절차**: ① 자동 변환 ② 미수록 단어 목록 출력 → 수기 보충 ③ 동형이음 후보 14개는 시드의 `meaning`/`example` 에 맞춰 수기 확정 ④ 전체 600개를 `단어 / IPA / 뜻` 표로 뽑아 사용자가 훑어볼 수 있게 제출 ⑤ 시드 JSON 에 병합.
- **표기 규칙(제안)**: 미국식, 슬래시 없이 저장, 1차 강세 `ˈ`, 2차 강세 `ˌ`, 장음 `ː`, 음절 구분점 없음. 화면에서만 `/…/` 를 입힙니다.
- 대안(비추천): 사전 없이 직접 작성 — 속도는 빠르나 검증 근거가 없어 정확도 보증이 어렵습니다. Wiktionary 추출 — CC BY-SA 표기 의무가 생겨 라이선스 부담이 큽니다.
