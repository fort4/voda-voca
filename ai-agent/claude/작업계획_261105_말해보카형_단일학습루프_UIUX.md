## 1. 개요 및 설계 원칙

### 1.1 배경 및 문제의식
- 기존 구조는 **단어장 목록 → 단어장 상세 → 개별 단어 관리/학습 선택**으로 이어지는 전통적인 CRUD 관리자형 화면 흐름을 유지하고 있음.
- 사용자가 학습을 시작하기까지 진입 뎁스(Depth)가 깊고, 수백 개의 단어가 나열된 정적 테이블 형태는 모바일 환경에서 학습 집중도를 분산시킴.

### 1.2 핵심 설계 원칙
1. **One Screen, One Task (원 스크린 원 포커스)**:
   - 한 화면에서는 하나의 단어/문항에만 시선을 집중시키며, 스크롤 없는 카드 뷰를 기본으로 한다.
2. **Chunk-based Progression (라운드형 학습 세션)**:
   - 10~15문항 단위의 '오늘의 라운드'로 학습을 분할하여 완료 경험을 극대화한다.
3. **Instant Bottom-Sheet Feedback (즉시 피드백 하단 시트)**:
   - 선택지 선택 직후 다음 페이지로 넘어가지 않고, 하단에서 슬라이드 업되는 시트를 통해 정오답 여부, 뜻, 예문, 발음 재생 기회를 즉각 제공한다.
4. **Bottom Nav Native Shell (하단 탭바 중심 내비게이션)**:
   - 모바일 한 손 조작성을 위해 상단 햄버거 메뉴를 배제하고 하단 4대 탭바로 주요 화면을 1-Depth로 이동한다.

## 2. 화면 라우팅 및 뷰 계층 재편

불필요한 관리/등록 라우트를 완전 제거하고, 학습 중심의 선형 구조로 단순화합니다.

```text
[기존 라우트]                                 [신규 개편 라우트]
/#/ (대시보드 통계)                 ───>     /#/ (홈: 오늘의 학습 루프 중심)
/#/vocabularies (목록)              ───>     /#/explore (중앙 단어장 카탈로그 탐색)
/#/vocabularies/:id (상세/편집)     ───>     [제거: 카탈로그 내 바텀시트 프리뷰로 대체]
/#/vocabularies/new (단어장 생성)   ───>     [제거: 중앙 제공형 전환]
/#/words/new, edit (단어 편집)      ───>     [제거]
/#/study/flashcard (플래시카드)     ───┐
/#/study/quiz (4지선다 퀴즈)        ───┴─>   /#/study/session (통합 세션 카드 러너)
/#/history (학습 로그 테이블)       ───>     /#/review (복습함 및 취약 단어)
```

### 디렉터리 구조 변경안 (`src/frontend/js/`)
```text
src/frontend/js/
├── app.js                         # 라우터 및 글로벌 셸 이벤트
├── core/
│   ├── api.js                     # 중앙 단어장 및 세션 기록 엔드포인트 연동
│   ├── sound.js                   # 정오답 피드백 사운드 및 TTS 제어
│   └── session-runner.js          # [신규] 학습 세션 상태 머신 (문항 큐 관리)
└── views/
    ├── home-view.js               # [개편] 홈 (오늘의 학습 루프)
    ├── explore-view.js            # [개편] 중앙 단어장 탐색기 (카탈로그)
    ├── study-session-view.js      # [신규] 집중형 1문항 카드 덱 러너
    ├── review-view.js             # [신규] 오답 복습 및 북마크 모아보기
    └── components/                # 재사용 UI 컴포넌트
        ├── bottom-nav.js          # 하단 탭 내비게이션
        ├── feedback-sheet.js      # 즉시 피드백 슬라이드 바텀시트
        └── progress-header.js     # 세션 진행 게이지 및 상단 컨트롤러
```

## 3. 핵심 화면 와이어프레임 및 레이아웃 명세

### 3.1 홈 화면 (`/#/`, `views/home-view.js`)
복잡한 수치 나열 대신 오늘의 목표 완수와 세션 즉시 진입을 유도합니다.

```text
+--------------------------------------------------+
| [보다보카]                        🔥 7일   [계정] |
|--------------------------------------------------|
|                                                  |
|              현재 선택된 단어장 배지               |
|            [ 중급 필수 1,000제 (Lv.2) ]          |
|                                                  |
|                  ┌────────────┐                  |
|                  │  (아이콘)  │                  |
|                  │   단어 마스코트 │                  |
|                  └────────────┘                  |
|               "오늘 남은 단어: 15개"              |
|                                                  |
|         +------------------------------+         |
|         |       [ 오늘 학습 시작 ]       |  <-- 메인 진입 CTA (대형 버튼)
|         +------------------------------+         |
|                                                  |
|  진행률: [██████████░░░░░░░░░░] 52% (520/1,000)  |
|                                                  |
|--------------------------------------------------|
|  [주간 학습 스트릭 잔디]                          |
|  월 [■]  화 [■]  수 [■]  목 [■]  금 [□]  토 [□]  일 [□] |
+--------------------------------------------------+
|  [🏠 홈]     [🔍 탐색]     [⭐ 복습함]     [📊 통계] |  <-- 하단 탭바
+--------------------------------------------------+
```
- **상단 헤더**: 로고, 연속 학습일(`streak_days`) 뱃지, 계정 드롭다운.
- **포커스 영역**: 현재 활성화된 단어장 이름, 일러스트/아이콘, 잔여 문항 수.
- **메인 CTA**: `오늘 학습 시작` 클릭 시 `/#/study/session`으로 즉시 진입.
- **하단 영역**: 최근 7일 연속 출석 스트릭 시각화 (인라인 SVG 도트).

### 3.2 집중 학습 세션 화면 (`/#/study/session`, `views/study-session-view.js`)
모든 노이즈를 제거하고 현재 풀이 중인 1개의 문항에만 시각을 고정합니다.

```text
+--------------------------------------------------+
|  [✕ 중단]     [████████░░░░░░░░] (6/15)     [🔊]  |  <-- 세션 헤더
|--------------------------------------------------|
|                                                  |
|  +--------------------------------------------+  |
|  | [힌트] 품사: v. | 중급 단어                 |  |
|  |                                            |  |
|  |  "The project was _________ until next     |  |
|  |   month due to budget cuts."               |  |  <-- 예문 중심 빈칸 (Cloze)
|  |                                            |  |
|  |  (예산 삭감으로 인해 프로젝트가 다음 달까지     |  |
|  |   연기되었다.)                              |  |
|  +--------------------------------------------+  |
|                                                  |
|  +--------------------------------------------+  |
|  | 1. postpone                                |  |
|  +--------------------------------------------+  |
|  | 2. accelerate                              |  |  <-- 4지선다 선택지
|  +--------------------------------------------+  |
|  | 3. investigate                             |  |
|  +--------------------------------------------+  |
|  | 4. establish                               |  |
|  +--------------------------------------------+  |
|                                                  |
|                  [⭐ 북마크 추가]                 |
+--------------------------------------------------+
```
- **상단 헤더 (`progress-header.js`)**: 세션 이탈(✕), 현재 진행도 게이지바(`current/total`), 전체 문장 읽어주기 TTS 토글.
- **질문 카드**: 문맥 기반 빈칸 문장 및 해석 힌트.
- **선택지 블록**: 엄지손가락 터치가 용이한 대형 버튼 (최소 높이 56px). 선택 시 즉시 비활성화 처리되어 중복 탭 방지.

### 3.3 즉시 피드백 하단 시트 (`feedback-sheet.js`)
선택지를 누르는 즉시 화면 하단에서 미끄러져 올라오며 정답 여부와 상세 해설을 제공합니다.

#### [정답 피드백 상태 (Emerald 테마)]
```text
+--------------------------------------------------+
|  [선택지 영역 블러/비활성화 처리]                  |
|==================================================|
| ▲ [emerald-600 배경 슬라이드 업]                  |
|                                                  |
|  🎉 정답입니다!                                   |
|                                                  |
|  • postpone [pəʊstˈpəʊn] : 연기하다, 미루다        |
|  • 유의어: put off, delay                         |
|                                                  |
|  +--------------------------------------------+  |
|  |           [ 다음 문항으로 (Enter) ]         |  |  <-- 탭 즉시 다음 카드로 전환
|  +--------------------------------------------+  |
+--------------------------------------------------+
```

#### [오답 피드백 상태 (Rose 테마)]
```text
+--------------------------------------------------+
|  [선택지 영역 블러/비활성화 처리]                  |
|==================================================|
| ▲ [rose-600 배경 슬라이드 업]                     |
|                                                  |
|  😅 아쉬워요!                                     |
|  내가 고른 답: accelerate (가속하다)               |
|  정답: postpone (연기하다, 미루다)                 |
|                                                  |
|  • 예문 다시 듣기 [🔊]                             |
|                                                  |
|  +--------------------------------------------+  |
|  |               [ 확인 (Enter) ]              |  |
|  +--------------------------------------------+  |
+--------------------------------------------------+
```
- **인터랙션**:
  - 선택지 탭 즉시 정답 버튼은 초록색, 오답 버튼은 붉은색 흔들림(`shake`) 애니메이션 적용.
  - 동시에 하단 시트가 `translate-y-full`에서 `translate-y-0`으로 200ms 트랜지션 실행.
  - `Enter` 키 또는 대형 확인 버튼 탭 시 다음 문항 카드로 교체.

## 4. 프론트엔드 인터랙션 상태 머신 명세

세션 화면의 부드러운 전환을 위해 `SessionEngine` 상태 머신을 정의합니다.

```text
[IDLE] ──(세션 시작)──> [READY] ──(문항 렌더링)──> [QUESTION_ACTIVE]
                                                          │
                                                    (선택지 탭)
                                                          │
                                                          ▼
                                                  [EVALUATING]
                                             (정오답 사운드 + API 전송)
                                                          │
                                                          ▼
[FINISHED] <──(마지막 문항)── [FEEDBACK_SHEET] <──────────┘
    │                               │
    │                        (확인 / 다음 탭)
    │                               │
    └─────────(다음 문항)───────────┘
```

### 상태별 제어 규칙
1. `QUESTION_ACTIVE`:
   - 키패드(1~4번), 선택지 클릭 활성화.
   - 상단 프로그레스 바 현재 인덱스 업데이트.
2. `EVALUATING`:
   - 모든 버튼 `pointer-events: none` 비활성화 (더블 탭 방지).
   - `POST /api/study/quiz/sessions/{id}/answer` 비동기 발송 (#8/#17 연동).
   - 결과에 따라 Web Audio API / CSS 효과 트리거.
3. `FEEDBACK_SHEET`:
   - 하단 시트 슬라이드 업 (`z-index: 50`).
   - 스페이스바, 엔터키, 하단 버튼 클릭 시 다음 문항으로 전이.
4. `FINISHED`:
   - 세션 완주 축하 연출 (간이 콘페티 효과 또는 성취 배지).
   - 이번 라운드 정답률, 획득 경험치, [한 번 더 하기] / [홈으로] CTA 제공.

## 5. 단계별 구현 및 검증 계획

### 1단계: 셸 및 하단 내비게이션 구축
- 기존 상단 바 위주의 레이아웃에서 모바일 하단 탭바(`bottom-nav.js`) 구조로 전환.
- 라우터(`app.js`) 정리: 비활성화할 관리자 라우트 제거 및 신규 라우트(`/#/explore`, `/#/study/session`, `/#/review`) 등록.

### 2단계: 집중형 세션 카드 뷰 및 피드백 시트 제작
- `views/study-session-view.js` 및 `feedback-sheet.js` 컴포넌트 구현.
- 4지선다 빈칸 문항 카드 레이아웃 및 Tailwind 전환 트랜지션 클래스 구성.
- 키보드 단축키(1~4, Space, Enter) 및 사운드 효과 바인딩.

### 3단계: 중앙 단어장 탐색기 및 홈 화면 연동
- `views/home-view.js`: 원클릭 세션 시작 중심의 단순화된 홈 뷰 구현.
- `views/explore-view.js`: 서버 제공형 단어장 목록 카드 및 '현재 학습 단어장으로 설정' 인터랙션 구현.

### 4단계: 모바일 반응형 및 다크 모드 검증
- 모바일 뷰포트 너비(360px, 390px, 412px)에서 하단 시트 및 버튼 탭 영역 침범 여부 점검.
- 다크 모드 색상 토큰 전수 점검 (`bg-slate-900`, `text-slate-100`, `border-slate-800`).
