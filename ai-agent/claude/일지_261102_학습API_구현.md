## 3. 핵심 정책

### 3.1 `quiz_sessions` 기반 상태 보관 (30분 만료)
- 출제 시 문항 정보를 서버에 저장합니다. 클라이언트에는 정답 인덱스를 보내지 않습니다 (응답 스키마에 `correct_index` 필드 없음, 테스트로 확인).
- 컬럼: `user_id`, `wordbook_id`(북마크 출처면 NULL), `source`('wordbook' | 'bookmarks', CHECK), `questions`(JSON), `is_submitted`, `expires_at`(출제 시각 + 30분, UTC).
- 문항 JSON 한 건: `question_id`, `word_id`, `term`, `choices`(4개), `correct_index`. 제출 채점과 오답 응답에 필요한 값은 모두 여기에 담으므로, 제출 시점에 단어 테이블을 다시 읽지 않아도 됩니다. 단, 단어 존재 여부는 별도로 확인합니다 (§3.4).
- 만료 판정: `now >= expires_at`이면 제출을 거부합니다 (400). 경계값(만료 직전 29분 59초)은 허용됨을 테스트로 확인했습니다.

### 3.2 중복 제출 방어: `SELECT ... FOR UPDATE` (비관적 락)
- 제출 시 세션 행을 `FOR UPDATE`로 잠급니다. 같은 세션에 동시 요청이 와도 한 요청만 진행하고, 나머지는 잠금이 풀린 뒤 `is_submitted=True`를 보고 409를 받습니다.
- 테스트 `test_concurrent_submits_only_one_succeeds`: 4개 요청을 `asyncio.gather`로 동시에 보내 결과가 `[200, 409, 409, 409]`이고, 이력은 4행만 생기는 것을 확인했습니다.
- 순차 재제출 역시 409이며 이력이 중복되지 않습니다 (`test_submit_twice_is_409_and_logs_are_not_duplicated`).
- 낙관적 방식(조건부 UPDATE로 `is_submitted` 확인)도 가능하지만, 이 경우 채점 계산 후 이력 INSERT까지 같은 트랜잭션에 묶기가 번거로워 잠금을 택했습니다.

### 3.3 제출의 단일 트랜잭션 (REQ-106)
- 한 번의 커밋에 세션 `is_submitted=True` 갱신과 `study_logs` 다건 INSERT가 함께 들어갑니다.
- 검사 순서: 존재(404) → 이미 제출(409) → 만료(400) → 답안 형식(400) → 단어 존재(409).
- 테스트 `test_submit_with_bad_answer_set_is_400`: 누락·중복·알 수 없는 문항 제출 후에도 세션이 `is_submitted=False`로 남아, 올바른 재제출이 가능합니다.

### 3.4 문항 단어 삭제 시 409 (부분 기록 방지)
- 출제 후 문항 단어가 삭제되면 `study_logs`의 FK가 깨집니다. 그래서 제출 시 문항 단어 ID 전체를 `SELECT`로 확인하고, 하나라도 없으면 롤백 후 409를 반환합니다.
- 커밋 시점 경쟁(확인 후 삭제)에 대비해, 커밋의 `IntegrityError` 중 `fk_study_logs_word`인 경우도 같은 409로 바꿉니다.
- 테스트: `test_deleted_word_blocks_submit_without_partial_write` (세션 미제출, 이력 0건 확인), 서비스 단위 테스트 2건(FK 실패→409, 다른 무결성 오류는 그대로 전파).

### 3.5 4지선다 출제 알고리즘 (결정 3 반영)
1. 출처 단어를 무작위 순서로 섞어 순회하며 문항을 만듭니다. 요청 `count`에 도달하면 중단합니다. 따라서 문항 수는 `min(count, 가용 단어 수)`입니다.
2. 오답 3개는 **단어가 속한 원본 단어장에서 먼저** 뽑습니다.
3. 부족하면 사용자의 **전체 단어 풀**에서 보충합니다.
4. 뜻이 정답과 같거나 이미 뽑은 뜻과 같은 단어는 건너뜁니다. 선지 4개는 서로 달라야 합니다.
5. 3개를 채울 수 없으면 그 단어는 문항에서 제외하고 다음 단어로 넘어갑니다. 한 문항도 못 만들면 400입니다.
- 테스트: 원본 단어장 우선(`test_distractors_come_from_the_original_wordbook_first`), 보충 경로와 중복 뜻 건너뛰기, 3개 불가 시 None(단위).
- 출제 원천은 단어장이면 해당 단어장 단어, 북마크면 본인 북마크 단어입니다. 둘 다 4개 미만이면 400입니다.

### 3.6 학습 이력 기록 (REQ-016)
- 문항마다 `study_logs` 1행(`user_id`, `word_id`, `is_correct`)을 INSERT합니다. 단어별 누적 카운터는 두지 않습니다 (데이터 설계 D4).
- 응답에는 정답 수, 정답률(0~100, 소수 첫째 자리), 오답 목록(표제어, 정답 뜻, 선택한 뜻)을 담습니다.
- 이력 조회는 `ORDER BY created_at DESC, id DESC`로 최신순이며, 본인 기록만 보입니다 (테스트 `test_logs_are_scoped_to_the_requesting_user`).

### 3.7 시각 처리
- 라우터의 `_now()`가 현재 UTC 시각을 한 곳에서 제공합니다. 만료 테스트는 이 함수를 `monkeypatch`로 바꿔 시각을 조작합니다.
