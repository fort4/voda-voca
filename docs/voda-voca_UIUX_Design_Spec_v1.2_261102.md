## 1. 설계 원칙

1. **모바일이 기준입니다.** 360px 폭을 최소 기준으로 그리고, 430px와 데스크톱으로 넓힙니다. 가로 스크롤은 어떤 폭에서도 생기지 않습니다 (REQ-020).
2. **한 화면에 한 가지 작업**을 둡니다. 이동 중 학습(S-02)은 두 번 이상 탭하지 않아도 카드 넘기기를 시작할 수 있어야 합니다.
3. **서버가 정답을 알고 있습니다.** 퀴즈 화면은 정답 인덱스를 모르는 상태로 그립니다. 채점은 제출 후에만 보입니다 (REQ-014, REQ-015).
4. **오류는 가까운 곳에 보입니다.** 입력 오류는 입력 칸 아래, 화면 오류는 화면 안, 확인이 필요한 행위는 SweetAlert2 모달에 둡니다 (REQ-022).
5. **브라우저 기본 `alert`, `confirm`, `prompt`는 쓰지 않습니다** (REQ-022).

## 2. 정보 구조와 라우팅 (해시 기반)

빌드가 없으므로 `location.hash`로 화면을 나눕니다. 새로고침이나 뒤로 가기에서도 같은 화면이 유지됩니다.

| 경로 | 화면 | 접근 | 비고 |
| :--- | :--- | :-: | :--- |
| `#/login` | 로그인 | 비로그인 | `?next=` 로 돌아갈 경로를 받음 |
| `#/signup` | 회원가입 | 비로그인 | |
| `#/wordbooks` | 단어장 대시보드 | 로그인 | 기본 진입 화면 |
| `#/wordbooks/:id` | 단어 목록 (검색 포함) | 로그인 | 단어장 상세 |
| `#/wordbooks/:id/flashcards` | 플래시카드 | 로그인 | `?shuffle=true` 옵션 |
| `#/wordbooks/:id/quiz` | 퀴즈 (시작 → 진행 → 결과) | 로그인 | 단어장 4개 미만이면 시작 불가 |
| `#/bookmarks` | 북마크 모아보기 | 로그인 | 북마크 기반 학습 진입점 |
| `#/bookmarks/flashcards` | 북마크 플래시카드 | 로그인 | |
| `#/bookmarks/quiz` | 북마크 퀴즈 | 로그인 | 북마크 4개 미만이면 퀴즈 비활성, 플래시카드만 허용 (REQ-019) |
| `#/history` | 학습 이력 요약 | 로그인 | 최근 100건 |
| `#/me` | 내 정보 · 로그아웃 | 로그인 | 상단 메뉴에서 진입 |

**하단 탭 바 (모바일)**: 단어장 · 북마크 · 학습 이력 · 내 정보의 4개 탭을 둡니다. 탭 하나의 터치 영역은 최소 44×44px입니다 (REQ-114).

**화면 전환 규칙**
- 로그인이 필요한 경로에 비로그인 상태로 들어가면 `#/login?next=<원래 경로>`로 보냅니다.
- 세션 만료(401)도 같은 규칙을 따릅니다 (API 규격서 §5.2).

## 3. 화면 정의

각 화면에는 요구사항 ID, 진입 경로, 주요 요소, 주요 동작, 빈·오류 상태를 적습니다.

### 3.1 로그인 · 회원가입 (REQ-001, REQ-121)

**목적**: 계정을 만들고 세션을 시작합니다.

**로그인 화면 요소**
- 닉네임 입력 (`autocomplete="username"`, v1.1: 이메일 없음)
- 비밀번호 입력 (`type="password"`, `autocomplete="current-password"`, 표시 전환 아이콘)
- "로그인" 기본 버튼 (전체 너비, 높이 48px)
- "회원가입" 텍스트 링크

**회원가입 화면 요소**
- 닉네임(2~30자, 다른 사람과 겹치지 않는 이름 안내), 비밀번호(8자 이상, 72바이트 이하 안내). 이메일 입력은 없다 (v1.1)
- 가입 성공 시 로그인 화면으로 이동하고 "가입이 완료되었습니다. 로그인해 주세요." 토스트

**동작**
- 로그인 성공 → `next` 경로 또는 `#/wordbooks`
- 401 → 비밀번호 칸 아래에 "닉네임 또는 비밀번호가 올바르지 않습니다." (입력 값은 유지, 비밀번호만 지움)
- 429 → 버튼을 비활성화하고 카운트다운을 표시합니다. 규격은 §5.2 참조.
- 409 (가입) → 닉네임 칸 아래에 "이미 사용 중인 닉네임입니다."

**상태**: Idle, Submitting(버튼 스피너), Blocked(429 카운트다운), Error(401·409·422·네트워크)

### 3.2 단어장 대시보드 (REQ-004~007)

**목적**: 단어장을 보고, 만들고, 고치고, 지웁니다.

**요소**
- 헤더: 제목 "내 단어장", 우측 "새 단어장" 버튼 (아이콘 `plus`)
- 카드 목록: 단어장 이름, 설명(한 줄 말줄임), 단어 수 배지(`N개 단어`, 천 단위 구분 기호, REQ-128), 수정 시각
- 카드 액션: 탭하면 단어 목록으로 이동. 카드 안의 `더보기`(아이콘 `ellipsis-vertical`)에서 수정·삭제

**동작**
- 새 단어장: SweetAlert2 폼 모달. 이름(1~50자, 필수), 설명(0~200자, 선택). 409는 이름 칸 아래 표시.
- 수정: 같은 모달을 값을 채워 엽니다. 보낸 필드만 바뀝니다.
- 삭제: SweetAlert2 확인 모달 "단어장을 삭제하면 단어, 북마크, 학습 기록이 모두 사라집니다." 확인 버튼은 빨간색. 삭제 후 목록에서 즉시 제거.
- 추천 1,000제: 단어장 화면의 보조 버튼 `추천 1,000제 추가`(아이콘 `sparkles`)를 누르면 확인 모달 "추천 1,000제를 추가할까요?"가 뜬다. 확인하면 프리셋 생성 요청을 보낸다 (REQ-130, §3.11).
- 목록은 20개씩 나눕니다. 목록 끝에 "더 보기" 버튼을 둡니다 (무한 스크롤은 쓰지 않습니다. 복귀 위치 관리가 어렵기 때문).

**상태**
- Loading: 카드 모양 스켈레톤 3개
- Empty: 일러스트 대신 아이콘(`book-open`) + "아직 단어장이 없습니다." + "첫 단어장 만들기" 버튼 (S-01 시나리오)
- Error: "단어장을 불러오지 못했습니다." + "다시 시도" 버튼
- Success: 카드 목록

### 3.3 단어 목록 · 접두사 검색 (REQ-008~011)

**목적**: 단어장 안의 단어를 찾고, 추가하고, 고칩니다.

**요소**
- 상단 고정 헤더: 뒤로가기(아이콘 `arrow-left`), 단어장 이름, 우측 "단어 추가" 버튼과 "일괄 등록" 버튼(아이콘 `upload`, §3.8)
- 단어장 상세 헤더 아래 2×2 액션 격자(플래시카드, 퀴즈, 일괄 등록, 단어 추가)와 **화면 맨 아래 [단어장 삭제]** 위험 액션을 둔다 (v1.1). 삭제는 확인 모달에서 '모든 단어, 북마크, 학습 기록이 영구 삭제되며 되돌릴 수 없다'를 안내한 뒤 실행하고, 성공하면 단어장 목록으로 이동한다 (REQ-007).
- 검색창: 상단 고정, 아이콘 `search`, 자리 표시자 "표제어 앞부분으로 검색"
- 목록 행: 표제어(굵게), 뜻(한 줄 말줄임), 북마크 별 아이콘(`star`, 채움/빈 상태)
- 하단 고정 액션 바(학습 시작): "플래시카드" · "퀴즈" 두 버튼. 퀴즈는 단어가 4개 미만이면 비활성 + 안내 문구

**동작**
- 검색: 300ms 디바운스, 이전 요청 취소, 검색 중에는 이전 결과를 흐리게 (API 규격서 §5.5)
- 단어 추가: 전체 화면 시트(모바일) 또는 가운데 모달(데스크톱). 표제어, 뜻, 예문(선택). 409는 표제어 칸 아래 "같은 단어장에 이미 있는 표제어입니다."
- 행을 탭하면 상세 시트가 열립니다. 상세에서 수정, 삭제, 북마크를 합니다.
- 북마크 별 탭: 낙관적 갱신. 실패하면 되돌리고 토스트 "북마크를 저장하지 못했습니다."
- 삭제: SweetAlert2 확인 모달 "이 단어의 북마크와 학습 기록도 함께 삭제됩니다."

**상태**
- Loading: 행 스켈레톤 5개
- Empty(목록 없음): "아직 단어가 없습니다." + "단어 추가" 버튼
- Empty(검색 결과 없음): "'{q}'로 시작하는 단어가 없습니다." (검색어 유지, 지우기 버튼)
- Error: 목록 자리에 "단어를 불러오지 못했습니다." + "다시 시도"
- 404: 단어장을 찾을 수 없음 화면 (단어장 대시보드로 이동 버튼)

**추가 규격 (v1.2, REQ-125)**
- 각 단어 행에 스피커 버튼(아이콘 `volume-2`)을 두고 표제어를 읽는다.

### 3.4 플래시카드 (REQ-012, REQ-013, REQ-019)

**목적**: 카드를 넘기며 암기합니다. 이동 중 학습(S-02)의 핵심 화면입니다.

**요소**
- 상단: 닫기(아이콘 `x`), 진행 표시 "5 / 24", 셔플 토글 버튼(아이콘 `shuffle`, 켜짐 상태 표시)
- 카드: 화면 가로 폭에서 좌우 16px 여백을 뺀 너비, 높이는 내용에 맞추되 최소 240px
  - 앞면: 표제어(큰 글씨)
  - 뒷면: 뜻(큰 글씨) + 예문(있을 때, 작은 글씨)
- 하단: 이전(아이콘 `chevron-left`) · 뒤집기 안내 · 다음(아이콘 `chevron-right`) 버튼 (각 최소 44×44px)

**동작**
- 카드 탭 → 뒤집기 (CSS 3D `rotateY`, 300ms, `prefers-reduced-motion`이면 페이드)
- 좌우 스와이프 → 이전·다음 카드 (§7)
- 셔플 켜기 → `shuffle=true`로 새 세트를 받아 무작위 순서로 시작 (REQ-013). 끄기 → 표제어 순서로 복원.
- 마지막 카드에서 다음 → "모든 카드를 봤습니다." 완료 화면 (다시 보기, 목록으로)
- 북마크 기반: `#/bookmarks/flashcards` 로 들어오면 카드별 북마크 별을 표시하고 해제도 가능

**상태**
- Loading: 카드 스켈레톤
- Empty: 카드가 없으면 "학습할 단어가 없습니다." + 뒤로가기
- Error: "카드를 불러오지 못했습니다." + 다시 시도
- Success: 카드 진행

**추가 규격 (v1.2, REQ-125, REQ-127)**
- 스피커 버튼(아이콘 `volume-2`)으로 표제어를 읽는다.
- 단축키(데스크톱): `←`/`→` 이전·다음 카드, `Space`/`Enter` 뒤집기, `S` 셔플 토글. 버튼에 포커스가 있을 때는 브라우저의 버튼 동작에 맡기고, 입력 칸이나 모달이 열려 있으면 무시한다.

### 3.5 객관식 퀴즈 (REQ-014, REQ-015, REQ-019)

**목적**: 뜻 4지선다로 실력을 점검하고, 결과와 틀린 단어를 보여 줍니다.

**흐름**: 시작 화면 → 진행 → 제출 확인 → 결과 화면

**시작 화면**
- 문항 수 선택: 5, 10(기본), 20 (가용 단어가 적으면 자동으로 줄어든다는 안내 문구)
- "퀴즈 시작" 버튼. 단어 4개 미만이면 버튼 비활성 + "퀴즈는 단어가 4개 이상 있어야 시작할 수 있습니다."

**진행 화면**
- 상단: 진행 표시 "3 / 10", 남은 시간(§3.5.1 참조), 나가기 버튼
- 문제: 표제어 (큰 글씨, 가운데 정렬)
- 선지: 4개의 세로 버튼. 각 버튼 최소 높이 52px, 전체 너비
- 선택 상태 (v1.1, 즉각 피드백, REQ-124): 보기를 누르는 즉시 판정합니다. 정답은 초록 배경과 체크 표시, 내가 고른 틀린 답은 빨강 배경과 엑스 표시로 나타냅니다. 판정 뒤에는 보기를 바꿀 수 없습니다 (문항 잠금).
- 하단: 이전 문항 버튼. 보기를 고르면 아래의 해설 카드가 나타나고, 그 카드의 [다음 문항] 버튼으로 넘어간다. 마지막 문항의 해설 카드에는 [최종 결과 보기] 버튼이 나오며, 누르면 기록을 저장하고 결과 화면으로 간다.
- 모든 문항에 답해야 제출할 수 있습니다. 답하지 않은 문항 번호는 진행 표시 아래 점으로 표시합니다.

**해설 카드 (v1.1)**
- 구성: 정오 표시 ("정답입니다!" 또는 "아쉬워요, 오답입니다."), 정답 뜻, "예문 해설" 블록, 다음 문항 또는 최종 결과 보기 버튼.
- 예문이 없는 단어는 "이 단어에는 해설 예문이 없습니다."를 보여 준다.
- 해설 카드는 보기를 고른 문항에서만 나타나며, 미선택 상태에서는 안내 문구("보기를 고르면 바로 채점됩니다.")만 보인다. 빈 값(null)이 화면에 글자로 나오지 않도록 조건부 노드는 안전 헬퍼로만 붙인다 (v1.1 수정).
- 최종 제출은 확인 모달 없이 [최종 결과 보기]로 바로 기록을 저장한다. 모든 문항에 답하기 전에는 마지막 해설 카드가 나타나지 않는다.

**결과 화면** (REQ-015)
- 상단 요약: 정답 수와 정답률 "7 / 10 · 70%" (큰 숫자). 제출 응답의 `correct_count`, `accuracy`를 씁니다.
- **문항별 비교**: 문항 순서대로 카드를 나열합니다. 카드마다 표제어와 선지 4개를 보여 줍니다.
  - 정답 선지: 초록 배경 + 체크 아이콘 + "정답" 글자
  - 내가 고른 틀린 선지: 빨간 테두리 + 엑스 아이콘 + "내 답" 글자
  - 나머지 선지: 기본 표시
  - 맞힌 문항은 내가 고른 선지가 정답입니다. 틀린 문항은 `wrong_items`의 `correct_meaning`과 같은 선지가 정답입니다 (API 규격서 §6).
- **오답 노트**: 틀린 단어만 모읍니다. 표제어, 정답 뜻, 내가 고른 뜻을 보여 주고, 행마다 북마크 별을 둡니다 (S-03: 틀린 단어 북마크). 별 탭은 `PUT`/`DELETE /api/bookmarks/{word_id}`를 호출하고, 낙관적 갱신 후 실패하면 되돌립니다.
- 액션: "다시 풀기"(같은 출처로 새 퀴즈 출제), "단어장으로", "학습 이력 보기"
- 정답률 100%면 짧은 축하 문구 한 줄 (과장하지 않음).
- **결과 캐싱 (확정: §11 결정 9)**
  - 제출 응답이 200이면 `sessionStorage`에 `voda.quizResult.<session_id>` 키로 결과를 저장합니다. 값은 제출 응답, 문항별 `{term, choices, selected_index, correct_index}`, 저장 시각입니다.
  - 결과 화면을 열 때 같은 세션 ID의 캐시가 있으면 그대로 렌더링합니다. 없으면 "이 탭에서는 결과를 다시 볼 수 없습니다. 새 퀴즈를 시작해 주세요." 안내와 시작 화면 이동 버튼을 보입니다.
  - 읽기·쓰기는 `try/catch`로 감쌉니다. 저장 공간이 부족하거나 저장소를 쓸 수 없으면 결과는 메모리에서만 보여 주고, 새로고침 시 안내로 대체합니다.
  - 로그아웃 시 `voda.quizResult.*` 키를 모두 지웁니다.
  - 캐시는 탭을 닫으면 사라집니다. 다른 기기나 다른 탭에서는 볼 수 없습니다 (확정된 한계).

**만료·제출 실패 처리 (API 규격서 §3.5 기준)**
- 제출 400(만료): "퀴즈 제한 시간(30분)이 지났습니다." 결과 대신 시작 화면으로 이동
- 제출 409(이미 제출): 결과를 다시 불러올 수 없으므로 "이미 제출된 퀴즈입니다." 안내 후 시작 화면
- 제출 409(단어 삭제): "퀴즈에 포함된 단어가 삭제되었습니다. 퀴즈를 다시 시작해 주세요." 시작 화면으로

**상태**
- Loading(출제 중): 선지 자리에 스켈레톤
- Submitting: 제출 버튼 스피너, 모든 버튼 비활성
- Error(출제 실패 400): 조건 안내 메시지 (단어 4개 미만 등)
- Expired: 남은 시간 0 → 선택과 제출 비활성 + "시간이 지났습니다" 안내 (§3.5.1)

**추가 규격 (v1.2, REQ-125, REQ-127, REQ-129)**
- 스피커 버튼으로 문항의 표제어를 읽는다.
- 단축키: 숫자 `1`~`4`로 보기를 고른다. 피드백 카드가 뜬 뒤에는 `Enter`/`Space`로 다음 문항으로 넘어간다.
- 출처 설정에 **오답 복습**이 있다 (`/study/quiz?wrong=1`). 제목은 "오답 복습 퀴즈"이고, 뒤로 가기는 학습 이력으로 간다.

#### 3.5.1 세션 카운트다운 타이머 (확정: §11 결정 2)

- **표시 기준**: 출제 응답의 `expires_at`(출제 후 30분). 문항별 제한 시간은 없습니다.
- **표시 형식**: "남은 시간 24:37" (분:초, 숫자는 고정폭). 접근성을 위해 `aria-live="off"`로 두고, 5분 이하와 종료 시점에만 한 번씩 스크린리더에 알립니다.
- **시계 보정**: 출제 응답의 `Date` 헤더로 서버와 기기 시계의 차이(`offset`)를 구합니다. 잔여 시간은 `expires_at - (Date.now() + offset)`입니다. 기기 시계가 틀려도 맞게 나옵니다.
- **갱신**: 1초마다 다시 계산합니다. 탭이 백그라운드에 있었어도 시각 차이로 계산하므로 오차가 쌓이지 않습니다.
- **5분 이하**: 글자를 강조색으로 바꾸고 옆에 시계 아이콘(`timer`)을 둡니다. 색만으로 구분하지 않습니다.
- **0이 되면**: 선지 선택과 제출 버튼을 비활성화하고 "시간이 지났습니다. 퀴즈를 다시 시작해 주세요." 안내를 띄웁니다. 제출 요청은 보내지 않습니다 (서버가 400으로 거절하기 때문).
- **제출 중 0이 되는 경우**: 제출 요청이 이미 나갔다면 서버 응답(200 또는 400)을 따릅니다.
- **화면 이탈**: 퀴즈 화면을 떠나면 타이머를 멈춥니다. 돌아오면 같은 세션이 아직 살아 있는지 서버 기준으로 판단하는 것은 없으므로, 퀴즈는 새로 시작합니다 (API 규격서 §5.2).

### 3.6 북마크 모아보기 (REQ-017, REQ-018, REQ-019)

**목적**: 내가 표시한 단어를 한곳에서 보고, 그 단어들로 학습합니다.

**요소**
- 헤더: "북마크" 제목, 개수 "총 12개"
- 목록 행: 표제어, 뜻(한 줄), 단어장 이름 (작은 글씨 칩), 북마크 별(해제 가능)
- 하단 고정 액션 바: "플래시카드" · "퀴즈" (북마크 4개 미만이면 퀴즈 비활성 + "북마크가 4개 이상이면 퀴즈를 할 수 있습니다.")
- 페이지 20개씩, "더 보기" 버튼

**동작**
- 행의 별 해제 → 목록에서 즉시 제거 (낙관적 갱신, 실패 시 복원)
- 행 탭 → 해당 단어의 단어장 단어 목록으로 이동

**상태**
- Empty: "북마크한 단어가 없습니다." + "단어장으로 가서 별을 눌러 보세요" 안내 버튼
- Loading / Error / Success는 공통 규격 (§4)

### 3.7 학습 이력 요약 (REQ-016)

**목적**: 최근 학습의 정답률 흐름을 봅니다.

**요소**
- 요약 카드 (상단): 최근 100건 기준 정답률 (%) 과 정답 수 / 전체 수
- 목록: 날짜(연-월-일 시:분, KST), 표제어, 정답 아이콘(`check` 초록 / `x` 빨강). 텍스트로도 "정답" "오답"을 씁니다 (색맹 대응).
- 날짜 구분선: 같은 날짜끼리 묶음 헤더

**동작**
- 목록은 API가 최신순으로 줍니다. 클라이언트에서 다시 정렬하지 않습니다.
- 행 탭 → 해당 단어의 단어장 단어 목록으로 이동 (단어장이 이미 삭제되었으면 행을 탭해도 이동하지 않음; 학습 이력은 단어 삭제와 함께 지워지므로 이 경우는 생기지 않습니다)

**상태**
- Empty: "아직 학습 기록이 없습니다." + "퀴즈 시작하기" 버튼
- Loading / Error / Success는 공통 규격 (§4)

**추가 규격 (v1.2, REQ-129)**
- 요약 카드 아래에 **오답 복습 퀴즈 시작** 버튼(아이콘 `target`)을 둔다. 최근 100건의 고유 오답 단어가 4개 이상일 때만 활성화된다.
- 4개 미만이면 버튼을 비활성화하고 "복습 가능한 오답 단어가 4개 이상이어야 합니다 (현재 N개)."를 보여 준다. 4개 이상이면 "틀린 단어 N개로 복습합니다."를 보여 준다. 서버의 400 메시지(`… 4개 미만입니다 (현재 N개)`)는 개발자용 오류 본문이며, 화면에는 위 문구를 쓴다.
- 누르면 퀴즈 설정 화면이 `wrong=1`로 열린다.

### 3.8 단어 일괄 등록 모달 (REQ-008, 확정: 일괄 등록 도입)

**목적**: 단어를 한 번에 여러 개 등록합니다. 단어장 상세 화면의 "일괄 등록" 버튼에서 엽니다.

**입력 방식 (탭 2개, 확정: 결정 7)**
- **파일**: `.csv`, `.tsv`, `.txt` 파일 선택. `accept=".csv,.tsv,.txt,text/csv,text/tab-separated-values,text/plain"`.
- **직접 입력**: 여러 줄 입력칸(글자 크기 16px). 엑셀이나 메모장에서 복사해 붙여넣을 수 있습니다.

**입력 형식 규칙 (확정: CSV 및 TSV, 파싱은 프론트엔드 전담)**
| 항목 | 규칙 |
| :--- | :--- |
| 한 줄 | `표제어,뜻` 또는 `표제어,뜻,예문`. 예문은 생략 가능 (TSV는 탭으로 구분) |
| 구분자 | **CSV**: 쉼표(`,`). **TSV**: 탭. 파일은 확장자로 정합니다 (`.tsv`는 TSV, 그 밖은 CSV). 직접 입력은 첫 번째 비어 있지 않은 줄에 탭이 있으면 TSV로 봅니다 |
| 따옴표 | 필드에 구분자가 있으면 큰따옴표로 감쌉니다 (`"사과, 과일"`). 큰따옴표는 `""`로 씁니다. TSV에도 같은 규칙을 씁니다 |
| 헤더 | 첫 줄이 `표제어,뜻` 또는 `term,meaning`(대소문자 무시, 구분자는 파일 형식에 맞춤)이면 헤더로 보고 건너뜁니다 |
| 빈 줄 | 무시 |
| 공백 | 앞뒤 공백 제거 (서버와 같은 규칙) |
| 인코딩 | UTF-8 (BOM 허용). 다른 인코딩이면 "UTF-8로 저장한 뒤 다시 선택해 주세요." 안내 |
| 파일 크기 | 256KB 이하. 넘으면 거부 |

**서버 전달 형식**: 파싱과 검증이 끝난 행만 `{"items": [{"term", "meaning", "example"}]}`로 보냅니다. CSV·TSV 구분이나 행 번호 같은 입력 형식 정보는 서버로 보내지 않습니다. 행 번호는 클라이언트 메모리에만 둡니다.

**파싱과 검증 (클라이언트, 전송 전)**
- 입력을 `parseBulkText(text)`로 나눠 행 목록을 만듭니다. 각 행은 `{lineNo, term, meaning, example, errors[]}`입니다.
- 행마다 검사합니다.
  - 표제어 또는 뜻이 비어 있음
  - 표제어 100자, 뜻 200자, 예문 500자 초과
  - 같은 요청 안에서 표제어 중복 (대소문자·악센트 무시. 서버와 같은 취지지만 정확히 같은 알고리즘은 아님. 서버 422가 최종 방어)
- 오류 문구 예: "3행: 뜻이 비어 있습니다.", "7행: 'apple'이 2행과 같은 표제어입니다."
- **100건 초과**: 전송 버튼을 비활성화하고 "한 번에 100건까지 등록할 수 있습니다. 파일을 나눠 선택해 주세요."를 보입니다. 나눠 등록하면 각 묶음이 따로 저장되므로, 한 번에 전부 저장된다는 보장은 없다고 함께 안내합니다.

**미리보기**
- 행 목록을 표로 보여 줍니다. 열은 행 번호, 표제어, 뜻, 예문, 상태입니다. 구분자(CSV/TSV)는 화면에 한 줄로 알려 줍니다.
- 360~430px에서는 표 대신 **카드 목록**으로 바꿉니다. 가로 스크롤은 만들지 않습니다.
- 오류 행: 빨간 배경 + 경고 아이콘 + 오류 문구. 색만으로 표시하지 않습니다.
- "오류만 보기" 토글을 둡니다.
- 입력이 없으면 "파일을 고르거나 내용을 붙여넣으면 여기에 미리 보입니다."를 보이고, 전송 버튼은 비활성입니다.

**전송 규칙**
- 오류 행이 하나라도 있으면 전송 버튼을 비활성화합니다. 서버도 전부 성공 또는 전부 실패이므로, 오류가 있는 상태로 일부만 보내지 않습니다.
- 전송 버튼 문구는 "N개 등록"입니다. 전송 중에는 버튼에 스피너를 보이고, 입력과 닫기 버튼을 모두 비활성화합니다. 재클릭은 무시합니다.
- 입력한 내용은 메모리에만 둡니다. `localStorage`와 `sessionStorage`에는 저장하지 않습니다.

**서버 응답별 처리** (API 규격서 §3.3 #10b)
| 응답 | 처리 |
| :--- | :--- |
| 201 | 모달 닫기, 토스트 "N개 단어를 등록했습니다.", 단어 목록을 첫 페이지부터 다시 불러옴 |
| 422, `loc`가 `["body","items",i,...]` | 해당 행을 강조하고 오류 문구를 표시. `i`는 전송한 행 목록의 순서이므로, 전송 시 행 번호와 매핑을 보관합니다 |
| 422, `loc`가 `["body"]` | 요청 안 중복 메시지를 상단 배너에 표시 (행을 특정할 수 없음) |
| 409 | 모달을 유지합니다. 상단 배너에 "'{conflict_term}'은(는) 이미 이 단어장에 있습니다. 아무 단어도 저장되지 않았습니다."를 표시합니다. 미리보기에서 표제어가 `conflict_term`과 같은 **첫 행**을 강조합니다 (API 규격서 §3.3 #10b). `conflict_term`이 `null`이면 행 강조 없이 배너만 보입니다 (결정 8) |
| 404 | "단어장을 찾을 수 없습니다." 안내 후 대시보드 이동 버튼 |
| 401 | API 규격서 §5.2 (세션 만료 흐름). 입력 내용은 잃지 않도록 메모리 상태를 유지하고, 로그인 후 돌아와도 같은 화면을 다시 보여 줌 |
| 네트워크 오류 | 입력 유지, "인터넷 연결을 확인해 주세요." + 다시 시도 버튼 |

**닫기 규칙**
- 입력이 있는 상태에서 닫으려 하면 SweetAlert2 확인 모달 "입력한 내용이 사라집니다. 닫을까요?"를 띄웁니다.
- 전송 중에는 닫기 버튼과 배경 탭을 막습니다.

**상태**: Empty(입력 없음), Parsed(오류 없음), HasErrors(오류 있음, 전송 불가), TooMany(100건 초과), Submitting, Success, Error(409·422·404·401·네트워크)

### 3.9 회원 탈퇴 (계정 메뉴, v1.1 신설) — REQ-122

- 진입: 상단바의 닉네임 칩을 누르면 계정 메뉴가 열린다. 메뉴에는 로그아웃과 회원 탈퇴가 있다.
- 1단계 확인: "회원 탈퇴를 진행할까요?" 확인 모달. 계정과 모든 단어장, 단어, 북마크, 학습 기록이 영구 삭제되고 되돌릴 수 없다고 안내한다. 확인 버튼은 "계속"이다.
- 2단계 확인: 닉네임을 **정확히 입력**해야 "탈퇴하기" 버튼이 동작한다. 입력이 다르면 "닉네임이 일치하지 않습니다."를 보여 준다. 앞뒤 공백만 무시하고 대소문자는 구분한다.
- 성공: 세션 저장소를 비우고 로그인 화면으로 이동하며, "회원 탈퇴가 완료되었습니다." 토스트를 띄운다.
- 실패: 오류 토스트를 띄우고 계정은 그대로 둔다.

### 3.10 기본 단어장 (단어장 목록, v1.1 신설) — REQ-123

- 가입 직후 목록에 "초급 필수 영단어 200", "중급 핵심 영단어 200", "고급 심화 영단어 200" 3개가 보인다. 일반 단어장과 같은 카드로 보이며, 수정과 삭제가 가능하다.
- 각 단어장은 단어 200개를 가지며, 단어 상세에서 일반 단어장과 같은 방식으로 검색하고 학습할 수 있다.

### 3.11 추천 1,000제 (단어장 화면, v1.2 신설) — REQ-130

- 목적: 중급 필수 영단어 1,000개를 한 번에 내 단어장으로 받는다.
- 흐름: `추천 1,000제 추가` → 확인 모달 → 생성 요청 → 성공 시 목록 새로고침. 새 단어장은 이름 `중급 필수 영단어 1,000`, 단어 수 배지 1,000개로 보인다.
- 토스트: 성공 "추천 단어장을 추가했습니다." / 이미 있음(409) "이미 추가된 추천 단어장입니다." / 데이터 없음(503) "추천 단어장 데이터가 아직 준비되지 않았습니다."
- 실패 시 단어장은 만들어지지 않는다 (서버가 한 트랜잭션으로 처리, API §3.2 #5b).

## 4. 상태 머신 공통 규격

모든 데이터 영역은 아래 상태 중 하나입니다. 상태는 한 번에 하나만 가집니다.

```text
           요청 시작
   Idle ──────────────▶ Loading ──성공(데이터 0건)──▶ Empty
                          │
                          ├──성공(데이터 있음)──▶ Success
                          │
                          └──실패──▶ Error ──재시도──▶ Loading
```

| 상태 | 화면 표시 | 전이 조건 |
| :--- | :--- | :--- |
| Idle | 아무것도 그리지 않음 | 화면 진입 전 |
| Loading | 스켈레톤(같은 모양의 회색 블록 3~5개). 텍스트 "불러오는 중"은 스크린리더 전용 | 요청 시작 |
| Empty | 아이콘 + 한 문장 + 행동 버튼 1개 | 성공이고 항목 0개 |
| Success | 실제 목록 또는 내용 | 성공이고 항목 1개 이상 |
| Error | 메시지 + "다시 시도" 버튼 | 실패(0, 5xx, 404 제외) |
| NotFound | "찾을 수 없습니다." + 상위 화면 이동 버튼 | 404 |
| Unauthorized | 화면 전환 (로그인으로) | 401 (API 규격서 §5.2) |

**Error 메시지 규칙**
- 네트워크 오류(0): "인터넷 연결을 확인해 주세요."
- 5xx·503: "서버에 문제가 있습니다. 잠시 후 다시 시도해 주세요."
- 그 밖의 실패: 서버 `detail`을 쓰되 기술 용어가 있으면 쉬운 말로 바꿉니다.

**규칙**
- 스켈레톤은 실제 목록과 같은 높이를 가져 화면이 튀지 않게 합니다 (CLS 방지).
- 재시도 버튼은 중복 요청을 막기 위해 요청 중에는 비활성입니다.
- Empty와 Error를 같은 문구로 쓰지 않습니다.

## 6. 모바일 우선 반응형 규격

### 6.1 뷰포트 기준
| 구분 | 폭 | 레이아웃 |
| :--- | :--- | :--- |
| 최소 기준 | 360px | 단일 열, 좌우 여백 16px |
| 기준 | 390px | 단일 열 |
| 큰 모바일 | 430px | 단일 열, 여백 16px 유지 (카드 너비만 늘어남) |
| 태블릿 | 768px 이상 | 최대 너비 720px 가운데 정렬, 모달은 가운데 팝업 |
| 데스크톱 | 1024px 이상 | 최대 너비 960px 가운데 정렬. 단어 목록은 표제어·뜻 두 열 표 |

- 뷰포트 메타: `<meta name="viewport" content="width=device-width, initial-scale=1">` (REQ-021)
- 360px, 390px, 430px 세 폭에서 주요 화면을 캡처해 가로 스크롤이 없는지 확인합니다 (REQ-119). 검증 절차는 테스트 정의서에 씁니다.

### 6.2 Tailwind 브레이크포인트 사용 규칙
- 기본 클래스는 모바일 값을 씁니다. `sm:`(640px)과 `md:`(768px)에서 넓힙니다.
- 고정 폭(`w-[360px]`)은 쓰지 않습니다. `w-full`과 `max-w-*`를 씁니다.
- 가로 스크롤 방지: 긴 표제어는 `break-words` 또는 `truncate`로 처리합니다.

### 6.3 터치 타깃 (REQ-114)
- 모든 버튼과 링크는 **최소 44×44px**입니다. 아이콘만 있는 버튼도 같습니다 (아이콘이 24px여도 패딩으로 영역을 넓힘).
- 인접한 타깃 사이 간격은 최소 8px입니다.
- 목록 행 전체를 탭 영역으로 씁니다. 행 안의 별 아이콘은 별도의 44px 영역을 가집니다.

### 6.4 글자 크기 (REQ-115)
- 본문 기본 16px (`text-base`). 입력 칸도 16px 이상이어야 iOS가 확대하지 않습니다.
- 표제어는 플래시카드에서 36px 이상, 목록에서는 18px.
- 행간은 1.5 이상.

## 7. 터치 인터랙션과 제스처 (REQ-021)

| 동작 | 대상 | 규칙 |
| :--- | :--- | :--- |
| 탭 | 모든 버튼, 행, 카드 | `touch-action: manipulation`으로 300ms 지연을 없앱니다 (REQ-021) |
| 좌우 스와이프 | 플래시카드 | 가로 이동이 48px 이상이고 세로 이동보다 커야 넘김. 세로 스크롤과 충돌하지 않게 세로 제스처는 무시 |
| 카드 탭 | 플래시카드 | `pointerup`에서 이동 거리가 8px 미만일 때만 뒤집기 (스와이프 끝과 구분) |
| 길게 누르기 | 단어 행 | 쓰지 않습니다. 탭으로 상세를 엽니다 (길게 누르기는 발견하기 어렵고 모바일 브라우저의 텍스트 선택과 충돌) |
| 당겨서 새로고침 | 목록 | 쓰지 않습니다. 기본 브라우저 동작을 막지 않도록 `overscroll-behavior: contain`만 적용 |

**스와이프 구현 규칙**
- `pointerdown`에서 시작 좌표를 기록하고, `pointermove`에서 `touch-action: pan-y`로 세로 스크롤은 브라우저에 맡깁니다.
- 가로 스와이프가 확정되면 카드 `transform`을 손가락 위치에 따라 움직입니다 (지연 없이).

## 10. 접근성

- 아이콘 버튼에는 `aria-label`을 붙입니다 (예: 이전 카드 "이전 카드").
- 색만으로 정답·오답을 구분하지 않습니다. 아이콘과 텍스트를 함께 씁니다.
- 대비: 본문 텍스트는 WCAG AA (4.5:1) 이상.
- 로딩 상태는 `aria-busy="true"`와 스크린리더 전용 텍스트로 알립니다.
- 모달을 열면 포커스를 모달 안으로 옮기고, 닫으면 열었던 버튼으로 돌려보냅니다.
- 동작 줄이기 설정(`prefers-reduced-motion`)을 따르면 카드 뒤집기를 페이드로 바꿉니다.
