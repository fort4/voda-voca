## 1. 설계 원칙

1. **모바일이 기준입니다.** 360px 폭을 최소 기준으로 그리고, 430px와 데스크톱으로 넓힙니다. 가로 스크롤은 어떤 폭에서도 생기지 않습니다 (REQ-020).
2. **한 화면에 한 가지 작업**을 둡니다. 홈에서 **한 번 탭하면** 학습이 시작되어야 합니다 (S-02). 학습 세션은 한 문항에만 집중하게 하고 탭바를 숨깁니다.
3. **서버가 정답을 알고 있습니다.** 출제 응답에는 정답이 없고(REQ-014), 보기를 고르면 서버가 채점해 정오와 해설을 돌려줍니다(REQ-124). 화면은 정답을 미리 알지 못한 채 그립니다.
4. **오류는 가까운 곳에 보입니다.** 입력 오류는 입력 칸 아래, 화면 오류는 화면 안, 확인이 필요한 행위는 SweetAlert2 모달에 둡니다 (REQ-022).
5. **브라우저 기본 `alert`, `confirm`, `prompt`는 쓰지 않습니다** (REQ-022).
6. **없는 값은 그리지 않습니다.** 예문, 예문 뜻 등 값이 없으면 그 줄을 렌더링하지 않습니다.

## 2. 정보 구조와 라우팅 (해시 기반)

### 2.1 라우트

빌드가 없으므로 `location.hash`로 화면을 나눕니다 (`src/frontend/js/routes.js`).

| 경로 | 화면 | 접근 | 탭바 | 비고 |
| :--- | :--- | :-: | :-: | :--- |
| `#/` | 홈 | 로그인 | 보임 | 기본 진입 화면 (활성 탭 "홈", 정확히 `/` 일 때만) |
| `#/explore` | 탐색 | 로그인 | 보임 | 활성 탭 "탐색" |
| `#/review` | 복습함 | 로그인 | 보임 | 활성 탭 "복습함" |
| `#/stats` | 통계 | 로그인 | 보임 | 활성 탭 "통계" |
| `#/study/session` | 학습 세션 러너 | 로그인 | **숨김** | 쿼리 `mode=quiz\|flashcard`, `source=bookmarks\|wrong`(생략하면 활성 단어장 `all`) |

| `#/signup` | 회원가입 | 비로그인 | 숨김 | |

- 로그인하지 않은 사용자가 로그인 필요 경로로 가면 `#/login?next=...` 로 보냅니다 (API 규격서 §5.2).
- 등록되지 않은 경로(옛 `#/wordbooks`, `#/study/flashcards`, `#/study/quiz`, `#/bookmarks`, `#/history`)는 연결되지 않습니다 (`routes.test.js` 가 부재를 검증).

### 2.2 하단 탭 내비게이션 (`views/components/bottom-nav.js`, 규칙은 `core/nav.js`)

**4열** 탭바입니다 (`grid-cols-4`, 최대 폭 `max-w-screen-md`, 탭 높이 최소 56px, REQ-114).

| 순서 | 탭 | 아이콘 | 이동 | 활성 판정 |
| :-: | :--- | :--- | :--- | :--- |
| 1 | 홈 | `home` | `#/` | 경로가 `/` 와 **정확히** 같을 때 |
| 2 | 탐색 | `search` | `#/explore` | `/explore` 또는 그 하위 |
| 3 | 복습함 | `star` | `#/review` | `/review` 또는 그 하위 |
| 4 | 통계 | `bar-chart-3` | `#/stats` | `/stats` 또는 그 하위 |

**탭바 노출/숨김 규칙** (`isTabbarVisible`)
| 조건 | 탭바 |
| :--- | :--- |
| 로그인하지 않음 | 숨김 |
| `/login`, `/signup` | 숨김 |
| **`/study/session`** (학습 세션) | **숨김** — 한 문항에만 집중하게 하고, 실수로 나가는 것을 막기 위해서입니다 |
| 그 밖의 로그인 화면 (`/`, `/explore`, `/review`, `/stats`) | 보임 |

- `/study/session` 은 탭이 아닙니다. 탭 4개는 위 표가 전부이며, 세션은 홈·복습함의 시작 버튼으로만 들어갑니다.
- 활성 탭은 `aria-current="page"` 와 알약형 인디케이터로 표시합니다. 탭 하나의 터치 영역은 최소 44×44px 입니다.

## 3. 화면 정의

### 3.1 로그인 · 회원가입 (REQ-001, REQ-121)

**목적**: 계정을 만들고 세션을 시작합니다.

**로그인 화면 요소**
- 닉네임 입력 (`autocomplete="username"`, v1.1: 이메일 없음)
- 비밀번호 입력 (`type="password"`, `autocomplete="current-password"`, 표시 전환 아이콘)
- "로그인" 기본 버튼 (전체 너비, 높이 48px)
- "회원가입" 텍스트 링크

**회원가입 화면 요소**
- 닉네임(2~30자, 다른 사람과 겹치지 않는 이름 안내), 비밀번호(8자 이상, 72바이트 이하 안내). 이메일 입력은 없다 (v1.1)
- 가입 성공 시 로그인 화면으로 이동하고 "가입이 완료되었습니다. 로그인해 주세요." 토스트

**동작**
- 로그인 성공 → `next` 경로 또는 홈(`#/`)
- 401 → 비밀번호 칸 아래에 "닉네임 또는 비밀번호가 올바르지 않습니다." (입력 값은 유지, 비밀번호만 지움)
- 429 → 버튼을 비활성화하고 카운트다운을 표시합니다. 규격은 §5.2 참조.
- 409 (가입) → 닉네임 칸 아래에 "이미 사용 중인 닉네임입니다."

**상태**: Idle, Submitting(버튼 스피너), Blocked(429 카운트다운), Error(401·409·422·네트워크)

### 3.2 홈 (REQ-012, REQ-131, REQ-142)

가장 먼저 보이는 화면이며 **세션 시작까지 한 번의 탭**이 목표입니다.

| 영역 | 내용 |
| :--- | :--- |
| 활성 단어장 요약 카드 | "학습 중인 단어장" 라벨 + 단어장 제목(`h1`) + 진행률 바(`progress-bar.js`) + "N / M 학습" 문구. 활성 단어장이 없으면 "단어장을 골라 주세요"와 안내 문구 |
| 단어장 이동 버튼 | 활성이 있으면 "단어장 바꾸기", 없으면 "단어장 고르기" — 탐색(`#/explore`)으로 이동 |
| 오늘의 목표 카드 | 일일 목표 **15단어** (`DAILY_GOAL = 15`, 서버에 목표 설정이 없어 상수). 문구 "N문항 남았어요", 목표 바(`min(100, 오늘 학습 단어 수 / 15 × 100)`), "오늘 N개 학습". **오늘 학습 수는 고유 단어 기준** 입니다 (`GET /api/study/stats` 의 오늘 `count`, 같은 단어를 여러 번 풀어도 1). 달성하면 "오늘 목표를 채웠어요 🎉". 연속 학습일이 있으면 "N일 연속" 배지 |
| 학습 방식 토글 | 퀴즈 / 플래시카드 2칸 (`mode-toggle.js`). 마지막 선택을 `localStorage` 키 `voda.study.mode` 에 기억하며, 저장소를 못 써도 동작하고 알 수 없는 값은 퀴즈로 되돌립니다 |
| 세션 시작 CTA | 큰 주요 버튼 "15문항 …" (최소 높이 56px). 활성 단어장이 없으면 비활성. 누르면 `#/study/session?mode=<선택>` 로 이동 (활성 단어장 `source=all`) |

**상태**: Loading(스켈레톤), Success, Error(통계를 못 받아도 단어장 요약과 CTA 는 보이고 목표 영역만 "오늘 기록을 불러오지 못했어요.")

### 3.3 탐색 (REQ-140, REQ-141, REQ-142, REQ-133)

표준 단어장 카탈로그를 훑고 학습할 단어장을 고르는 화면입니다 (`views/explore-view.js`, `core/explore-model.js`).

- **필터 칩**: 카테고리 칩(전체 + 카탈로그에 실제 있는 카테고리, 처음 나온 순서)과 레벨 선택(전체 + `Lv.N`). 둘은 AND 입니다. 카테고리 표시 이름은 `ELEMENTARY`=초등, `SECONDARY`=중고등, `CSAT`=수능이며, 목록에 없는 새 카테고리는 코드를 그대로 보입니다 (서버가 자유 문자열을 허용). 칩은 `aria-pressed` 로 선택 상태를 알립니다.
- **카드 그리드**: 단어장 한 장 = 카드 한 장. 제목, "카테고리 · Lv.N · N단어", 설명(있을 때만), 진행률 바, "N / M 학습 · N 숙련" 문구, 학습 중이면 강조 표시.
- **카드 동작**: [미리보기] → 단어 프리뷰 바텀시트, [이 단어장으로 학습] → `POST /api/users/me/active-vocabulary` (멱등). 이미 활성인 카드는 "홈에서 학습" 으로 홈에 보냅니다. 성공하면 목록의 활성 표시를 갱신합니다.
- **단어 프리뷰 바텀시트** (`views/components/word-sheet.js`): 단어장의 단어를 **읽기 전용**으로 30개씩 보여 줍니다 (`GET /api/vocabularies/{id}/words`, "더 보기"로 다음 페이지). 행에는 표제어, 뜻, 예문(있을 때만), 예문 뜻(있을 때만)이 있습니다. `Esc`, 바깥 탭, 닫기 버튼으로 닫히고, 닫으면 열었던 버튼으로 포커스를 돌려 줍니다.
- **빈 결과**: 조건에 맞는 단어장이 없으면 "조건에 맞는 단어장이 없습니다."

### 3.4 복습함 (REQ-017, REQ-018, REQ-019, REQ-129)

틀린 단어와 북마크한 단어로 복습 세션을 시작하는 화면입니다 (`views/review-view.js`, `core/review-model.js`).

- **탭 2개**: **북마크**(`GET /api/bookmarks`) / **틀린 단어**(`GET /api/study/wrong-words`). 각각 20건씩 "더 보기"로 이어 받습니다.
- **행**: 표제어, 뜻, 소속 단어장 제목, 예문(있을 때만), 예문 뜻(있을 때만).
- **최소 진입 제약 (4문항 미만 방어)**: 복습 세션은 해당 출처의 단어가 **4개 이상**이어야 시작할 수 있습니다 (`REVIEW_MIN_WORDS = 4`, 서버의 퀴즈 최소 단어 수와 같음).
  | 개수 | 시작 버튼 | 안내 문구 |
  | :--- | :---: | :--- |
  | 아직 모름 | 비활성 | "불러오는 중이에요." (숫자를 지어내지 않음) |
  | 4개 미만 | 비활성 | "{북마크/틀린 단어}가 4개 이상이어야 복습할 수 있어요 (현재 N개)." |
  | 4개 이상 | 활성 | "{북마크한 단어/틀린 단어} N개로 복습합니다." |
- **복습 세션 CTA**: 활성이면 `#/study/session?mode=<선택>&source=bookmarks|wrong` 로 이동합니다. 복습 세션은 활성 단어장을 바꾸지 않습니다.
- **빈 상태**: 북마크 없음 / 틀린 단어 없음 각각 한 문장 + 홈으로 가는 버튼.
- 서버의 "틀린 단어" 규칙은 단어별 마지막 결과가 오답인 단어이며 맞히면 목록에서 빠집니다 (REQ-129).

### 3.5 통계 (REQ-131, REQ-132, REQ-133)

`GET /api/study/stats` 한 번으로 그립니다 (`views/stats-view.js`, `core/stats-page-model.js`). 전체 이력 기준이며 최근 100건 제한이 없습니다.

- **요약 카드 2개**: 누적 정답률(기록이 없으면 "—"), 연속 학습일(0이면 "오늘 학습하면 시작돼요"). 연속 학습일은 한국 날짜 기준입니다.
- **주간 학습 바 차트**: 최근 7일(오늘 포함)의 날짜별 학습 단어 수를 인라인 SVG 막대로 보여 줍니다 (`core/weekly-chart.js`). 같은 날 같은 단어는 한 번. 오늘 막대는 강조하고 "오늘" 뱃지, 막대를 누르거나 포커스하면 그 날의 개수를 표시합니다. 헤더에 7일 합계 "N개". 외부 차트 라이브러리는 쓰지 않습니다.
- **단어장별 숙련도 프로그레스**: 표준 단어장마다 한 줄 — 제목(학습 중이면 "학습 중" 표시), 퍼센트, 진행률 바, 보조 문구. 진행률은 서버 `vocabulary_progress[].percent`(한 번이라도 맞힌 단어 비율)입니다.
- **빈 상태**: 기록이 없으면 "첫 세션을 마치면 정답률과 진행률이 여기에 쌓여요."

### 3.6 학습 세션 러너 (REQ-012, REQ-014, REQ-015, REQ-016, REQ-124, REQ-125, REQ-127, REQ-137)

`#/study/session` 한 화면에서 퀴즈와 플래시카드를 모두 진행합니다. 탭바는 숨겨지고, **한 번에 한 문항**만 보입니다. 세션은 시작 시 `POST /api/study/sessions` 로 15문항(기본)을 받고, 문항마다 `POST .../answer` 로 즉시 채점·기록합니다.

**상태 머신** (`core/session-runner.js`, 구동은 `core/session-driver.js`)

```text
IDLE ─START─▶ LOADING ─SESSION_LOADED─▶ QUESTION_ACTIVE ─ANSWER_RECEIVED─▶ FEEDBACK_SHOWING
                │                            ▲   │                              │
                └─실패─▶ ERROR               │   ├─마감 초과─▶ EXPIRED           ├─ NEXT ─▶ QUESTION_ACTIVE
                                             │   └─검증·인증 실패─▶ ERROR         └─ 마지막 문항 ─▶ SESSION_COMPLETE
                                             └──────── NEXT ────────────────────────┘
```

**화면 구성 (1문항 집중 뷰)**
- 상단 진행 헤더(`progress-header.js`): 왼쪽 ✕ **학습 중단** 버튼(`Esc` 와 같은 동작, 중단 확인 모달), 가운데 진행 바(`role="progressbar"`), "N/M" 문구, 오른쪽 **단어 읽어 주기**(TTS) 버튼.
- 본문 — **퀴즈**: 표제어(크게) + 문맥 예문(있을 때만) + 4지선다 버튼. 보기를 고르면 즉시 잠기고 서버 채점 응답을 기다립니다. 한 문항은 한 번 답하면 잠깁니다.
- 본문 — **플래시카드**: 카드 **앞면(단어만 표시)** 을 탭하거나 `Space`·`Enter` 로 뒤집어 **뒷면(뜻, 영문 예문, 예문 해석)** 을 본 뒤, **알아요 / 헷갈려요** 로 응답합니다. 카드 뒤집기는 3D 플립이며 `prefers-reduced-motion` 에서는 끕니다. 스와이프 제스처는 없습니다.
- **피드백 시트** (`views/components/feedback-sheet.js`): 응답을 받으면 화면 맨 아래에서 **200ms 슬라이드업** 으로 올라옵니다. 정오 제목(정답 초록 / 오답 빨강, 아이콘+텍스트 병기), 표제어와 발음 듣기, 뜻, 예문과 예문 뜻(있을 때만), 숙련 달성 배지·연속 정답 칩, **[다음 문항 (Enter)]** 버튼(자동 포커스). 정답 응답을 받을 때만 효과음이 납니다(REQ-137, 오답에는 무음, 음소거 설정 존중).
- **완료 화면** (`views/components/session-result.js`): 트로피 아이콘, 요약 제목·부제, 통계 칸(정답 수·정답률 등), "다시 볼 단어" 목록(틀린 단어와 뜻), 다음 행동 버튼(한 번 더 / 홈으로).
- **EXPIRED**: 서버가 `QUIZ_EXPIRED` 를 돌려주면 "마지막 답 이후 30분이 지났어요. 푼 문항은 이미 저장되어 있어요." 를 보여 주고 새 세션을 시작할 수 있게 합니다.
- **ERROR**: 서버 `X-Error-Code` 로 분기합니다 (API 규격서 §6.3). 출제할 단어가 없으면(`NO_WORDS_TO_STUDY`) 숙련 포함을 제안하거나 안내합니다.

**단축키 체계** (REQ-127, `core/session-view-model.js` 의 `sessionKeyAction`)
| 상황 | 키 | 동작 |
| :--- | :--- | :--- |
| 퀴즈, 문항 활성 | `1`~`4` | 해당 보기 선택 |
| 플래시카드, 앞면 | `Space`, `Enter` | 카드 뒤집기 |
| 플래시카드, 뒷면 | `→` / `←` | 알아요 / 헷갈려요 |
| 해설 시트가 열린 상태 | `Enter`, `Space` | 다음 문항 |
| 문항 활성 또는 해설 상태 | **`Esc`** | **세션 중단 확인 모달** |
| 입력 칸·열린 모달에 포커스 | (모두) | 단축키 무시 (`shortcutsBlocked`) |
- 버튼에 포커스가 있을 때 `Enter`/`Space` 는 브라우저가 그 버튼을 누르게 두고 단축키로 가로채지 않습니다.
- **Esc 세션 중단 모달** (SweetAlert2 확인): 제목 "학습을 중단할까요?", 본문 "푼 문항은 이미 저장되어 있어요.", 확인 버튼 "중단". 중단하면 홈으로 이동합니다. 답은 문항마다 서버에 저장되므로 잃는 것이 없습니다.

### 3.7 회원 탈퇴 (계정 메뉴) — REQ-122

- 진입: 상단바의 닉네임 칩을 누르면 계정 메뉴가 열립니다. 메뉴에는 **로그아웃**과 **회원 탈퇴**가 있습니다.
- 1단계 확인: "회원 탈퇴를 진행할까요?" 모달. 계정과 북마크, 학습 기록, 학습 진행도가 영구 삭제되고 되돌릴 수 없다고 안내합니다 (표준 단어장은 공용이라 영향이 없음). 확인 버튼은 "계속".
- 2단계 확인: 닉네임을 **정확히 입력**해야 "탈퇴하기" 가 동작합니다. 입력이 다르면 "닉네임이 일치하지 않습니다." (앞뒤 공백만 무시, 대소문자 구분)
- 성공: 세션 저장소를 비우고 로그인 화면으로 이동하며 "회원 탈퇴가 완료되었습니다." 토스트. 실패: 오류 토스트, 계정 유지.

### 3.7.1 계정 드롭다운 (REQ-134)

- 닉네임 칩 아래 오른쪽 정렬 팝오버(폭 16rem, 화면 밖으로 나가지 않게 최소 여백 8px). 칩은 `aria-haspopup="menu"`, `aria-expanded`.
- 구성: 프로필 헤더(원형 이니셜 아바타, 닉네임, "학습자" 배지) → 구분선 → **로그아웃**(`log-out`, 확인 없이 즉시 처리: 서버 세션 종료 → 로컬 사용자 상태 삭제 → "로그아웃되었습니다." 토스트 → `#/login` 이동) → 구분선 → 위험 구역의 **회원 탈퇴**(`user-x`, 빨간 글씨). v2.0 의 "내 단어장 백업" 항목은 폐기되었습니다.
- 바깥 탭(투명 백드롭)과 `Esc` 로 닫힙니다.

## 4. 상태 머신 공통 규격 (데이터 영역)

모든 데이터 영역(홈·탐색·복습함·통계의 목록과 카드)은 아래 상태 중 하나입니다. 학습 세션 러너의 상태는 §3.6 의 별도 상태 머신을 씁니다.

```text
           요청 시작
   Idle ──────────────▶ Loading ──성공(데이터 0건)──▶ Empty
                          │
                          ├──성공(데이터 있음)──▶ Success
                          │
                          └──실패──▶ Error ──재시도──▶ Loading
```

| 상태 | 화면 표시 | 전이 조건 |
| :--- | :--- | :--- |
| Idle | 아무것도 그리지 않음 | 화면 진입 전 |
| Loading | 스켈레톤(같은 모양의 회색 블록 3~5개). 텍스트 "불러오는 중"은 스크린리더 전용 | 요청 시작 |
| Empty | 아이콘 + 한 문장 + 행동 버튼 1개 | 성공이고 항목 0개 |
| Success | 실제 목록 또는 내용 | 성공이고 항목 1개 이상 |
| Error | 메시지 + "다시 시도" 버튼 | 실패(0, 5xx, 404 제외) |
| NotFound | "찾을 수 없습니다." + 상위 화면 이동 버튼 | 404 |
| Unauthorized | 화면 전환 (로그인으로) | 401 (API 규격서 §5.2) |

**Error 메시지 규칙**
- 네트워크 오류(0): "인터넷 연결을 확인해 주세요."
- 5xx·503: "서버에 문제가 있습니다. 잠시 후 다시 시도해 주세요."
- 그 밖의 실패: 서버 `detail`을 쓰되 기술 용어가 있으면 쉬운 말로 바꿉니다.

**규칙**
- 스켈레톤은 실제 목록과 같은 높이를 가져 화면이 튀지 않게 합니다 (CLS 방지).
- 재시도 버튼은 중복 요청을 막기 위해 요청 중에는 비활성입니다.
- Empty와 Error를 같은 문구로 쓰지 않습니다.

## 6. 모바일 우선 반응형 규격

### 6.1 뷰포트 기준
| 구분 | 폭 | 레이아웃 |
| :--- | :--- | :--- |
| 최소 기준 | 360px | 단일 열, 좌우 여백 16px |
| 기준 | 390px | 단일 열 |
| 큰 모바일 | 430px | 단일 열, 여백 16px 유지 (카드 너비만 늘어남) |
| 태블릿 | 768px 이상 | 최대 너비 720px 가운데 정렬, 모달은 가운데 팝업 |
| 데스크톱 | 1024px 이상 | 최대 너비 960px 가운데 정렬. 탐색 화면의 단어장 카드는 2열 격자 |

- 뷰포트 메타: `<meta name="viewport" content="width=device-width, initial-scale=1">` (REQ-021)
- 360px, 390px, 430px 세 폭에서 주요 화면을 캡처해 가로 스크롤이 없는지 확인합니다 (REQ-119). 검증 절차는 테스트 정의서에 씁니다.

### 6.2 Tailwind 브레이크포인트 사용 규칙
- 기본 클래스는 모바일 값을 씁니다. `sm:`(640px)과 `md:`(768px)에서 넓힙니다.
- 고정 폭(`w-[360px]`)은 쓰지 않습니다. `w-full`과 `max-w-*`를 씁니다.
- 가로 스크롤 방지: 긴 표제어는 `break-words` 또는 `truncate`로 처리합니다.

### 6.3 터치 타깃 (REQ-114)
- 모든 버튼과 링크는 **최소 44×44px**입니다. 아이콘만 있는 버튼도 같습니다 (아이콘이 24px여도 패딩으로 영역을 넓힘).
- 인접한 타깃 사이 간격은 최소 8px입니다.
- 목록 행 전체를 탭 영역으로 씁니다. 행 안의 별 아이콘은 별도의 44px 영역을 가집니다.

### 6.4 글자 크기 (REQ-115)
- 본문 기본 16px (`text-base`). 입력 칸도 16px 이상이어야 iOS가 확대하지 않습니다.
- 표제어는 플래시카드에서 36px 이상, 목록에서는 18px.
- 행간은 1.5 이상.

## 10. 접근성

- 아이콘 버튼에는 `aria-label`을 붙입니다 (예: 이전 카드 "이전 카드").
- 색만으로 정답·오답을 구분하지 않습니다. 아이콘과 텍스트를 함께 씁니다.
- 대비: 본문 텍스트는 WCAG AA (4.5:1) 이상.
- 로딩 상태는 `aria-busy="true"`와 스크린리더 전용 텍스트로 알립니다.
- 모달을 열면 포커스를 모달 안으로 옮기고, 닫으면 열었던 버튼으로 돌려보냅니다.
- 동작 줄이기 설정(`prefers-reduced-motion`)을 따르면 카드 뒤집기와 해설 시트 애니메이션을 끕니다.
- 해설 시트는 `role="status"`, `aria-live="assertive"` 로 정오를 알립니다.

| 9 | 디자인 시스템 | Zinc 뉴트럴, Indigo 포인트, 다크 모드 100% (§12) | 확정 (v1.1~v2.1) |
| 10 | 빈 상태 일러스트 | Lucide 아이콘만 사용 | 확정 |
| 11 | 단어 검색 | 제공하지 않음 (표준 단어는 탐색의 프리뷰 시트에서 훑어봄) | 확정 (v2.1) |
| 12 | 퀴즈 타이머 / 결과 `sessionStorage` 캐싱 | **폐기** — 세션 전체 카운트다운 없음. 답은 문항마다 서버에 저장 | 폐기 (v2.1) |

## 12. 디자인 시스템 (v2.1)

| 항목 | 규격 |
| :--- | :--- |
| 뉴트럴 | Zinc (배경 zinc-50, 보더 zinc-200, 본문 zinc-900, 보조 글자 zinc-500) |
| 포인트 | Indigo (주요 버튼, 활성 탭, 링크 indigo-600, 호버 indigo-700) |
| 위험 | Red (삭제, 탈퇴, 오답 표시) |
| 표면 | 흰 배경, 1px 보더(zinc-200), 반경 16px, 얇은 그림자 2단계 |
| 버튼 | 반경 12px, 최소 44px 높이, 누르면 0.97배로 줄어듦, 키보드 포커스는 인디고 외곽선 |
| 아이콘 | Lucide 0.460.0 (CDN 고정). 화면과 모달을 그릴 때마다 SVG 로 바꾼다 (`refreshIcons`) |
| 헤더와 탭바 | 블러 배경, 얇은 보더, 탭바는 활성 항목에 알약형 인디케이터. 로그인 상태이고 인증 화면·학습 세션이 아닐 때만 보인다 (§2.2) |
| 동작 줄이기 | 사용자가 설정하면 모든 애니메이션과 전환을 끈다 |
| 다크 모드 (v1.2) | `html.dark` 클래스로 전환하며 Zinc 계열만 쓴다 (Slate 미사용). 배경 치환: `bg-white`→#18181b, `bg-zinc-50`→#09090b, `bg-zinc-100`→#27272a, `bg-zinc-200`→#3f3f46 (`css/app.css`의 `html.dark` 재정의). 초기값은 저장된 선택(`voda.theme`), 없으면 시스템 설정 |
| 테마 전환 버튼 (v1.2) | 헤더 우측, 44px 정사각 버튼, 아이콘 `moon`, `aria-label="다크 모드 전환"`. 누르면 즉시 바꾸고 선택을 저장한다 |
| 해설 시트 (v2.1) | 화면 맨 아래에 고정, `translateY(100%)`→0 을 **200ms** 로 올라온다. `prefers-reduced-motion` 이면 즉시 나타난다. 정답은 초록(ok), 오답은 빨강 톤 |
| 헤더 소리 토글 (v2.0) | 다크 모드 버튼 왼쪽, 44px 정사각 버튼, 아이콘 `volume-2`(켬) / `volume-x`(끔). 상태는 `aria-pressed`로 알린다 |
| 오늘 뱃지 (v2.0) | 연한 강조 배경(`accent-soft`)의 알약형 뱃지에 강조색 글자 "오늘". 9px 굵은 글자 |
| 차트 막대 (v2.0) | 강조색, 지난 날 투명도 0.35, 오늘과 선택한 막대는 1.0 (SVG `fill`). 라벨은 보조 글자색 |
| 진행률 게이지 (v2.0) | 높이 6px(h-1.5), 둥근 모서리, 트랙은 보더 색, 채움은 강조색. 너비 변화는 420ms 전환, `prefers-reduced-motion`에서는 전환 없음 |
| 드롭다운 팝오버 (v2.0) | 표면 색, 16px 반경, 그림자는 `shadow-raised`, 160ms 나타남 애니메이션. 항목 최소 높이 44px |
