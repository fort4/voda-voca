## 1. 목적 및 범위

### 1.1 목적
모바일 기기에서도 편하게 사용할 수 있는 웹 단어장 서비스를 제공한다. 사용자는 단어장을 만들고 단어를 관리하며, 플래시카드와 퀴즈로 학습하고, 중요한 단어를 북마크할 수 있다.

### 1.2 범위 (In Scope)
- 다중 사용자 접속 및 사용자별 데이터 분리
- 단어장 및 단어의 CRUD
- 플래시카드 학습 / 객관식 퀴즈 학습
- 단어 북마크 및 북마크 기반 학습
- 모바일 뷰포트 우선 반응형 UI

### 1.3 범위 외 (Out of Scope, 1차 릴리스)
- 단어장 공유 및 협업 편집 (기본값: 1차 제외, Q2)
- 소셜 로그인, 이메일 인증 메일 발송 (기본값: 1차 제외)
- 네이티브 앱(iOS/Android) 배포
- 외부 사전 API 연동을 통한 뜻 자동 완성

### 1.4 기술 제약 (CLAUDE.md 기준)
| 계층 | 기술 |
| :--- | :--- |
| Backend | Python FastAPI, SQLAlchemy 2.0 (asyncmy), Alembic |
| Frontend | HTML5, Vanilla JavaScript (ES6+), JSDoc, 빌드 파이프라인 없음 |
| UI | Tailwind CSS (Play CDN), SweetAlert2, Lucide Icons |
| DB | MySQL 8.x (Docker 컨테이너, utf8mb4, Asia/Seoul) |
| 운영 | WSL2 Ubuntu 24.04, Docker Compose, pytest |

| 역할 | 설명 | 주요 관심사 |
| :--- | :--- | :--- |

| 운영자/개발자 (Operator) | Docker 환경을 구성하고 서비스를 운영 | 컨테이너 기동, 마이그레이션, 로그 확인 |

## 3. 사용자 시나리오 (핵심)

- **S-01 신규 학습자 시작**: 회원 가입 → 로그인 → 첫 단어장 생성 → 단어 5개 추가
- **S-02 이동 중 학습**: 모바일에서 로그인 → 단어장 선택 → 플래시카드로 한 단어씩 넘기며 암기
- **S-03 실력 점검**: 단어장 선택 → 객관식 퀴즈 10문항 → 결과 확인 → 틀린 단어 북마크
- **S-04 중점 복습**: 북마크 목록 → 북마크 단어만 플래시카드 또는 퀴즈 진행

## 4. 기능 요구사항 (Functional Requirements)

우선순위: **M** = 필수(Must), **S** = 권장(Should)

### 4.1 계정 (Account)

| ID | 요구사항 | 우선순위 | 상세 기준 (Acceptance Criteria) |
| :--- | :--- | :---: | :--- |
| REQ-001 | 회원 가입 | M | 계정은 **닉네임(2~30자, 중복 불가)과 비밀번호**만으로 만든다. 이메일은 받지 않는다. 닉네임은 로그인 식별자이며 대소문자와 무관하게 유일하다. 비밀번호는 8자 이상, UTF-8 기준 **72바이트 이하**만 허용한다 (bcrypt 입력 한계, ADR-002). 가입이 끝나면 기본 단어장 3종을 자동으로 만든다 (REQ-123). 인증은 **HttpOnly, SameSite=Lax 세션 쿠키** 방식을 사용한다 (Q1 확정). |
| REQ-002 | 로그인 / 로그아웃 | M | 올바른 자격 증명 시 세션을 `sessions` 테이블에 생성하고 세션 쿠키를 발급한다. 세션 수명은 로그인 후 **14일**(절대 만료)이다 `[기본값]`. 로그아웃 시 해당 세션 행을 삭제하여 즉시 무효화한다. 실패 시 어떤 항목이 틀렸는지 노출하지 않는다. (ADR-001) |
| REQ-003 | 사용자별 데이터 격리 | M | 로그인한 사용자는 본인 소유 단어장/단어/북마크만 조회·수정·삭제할 수 있다. 타 사용자 리소스 접근 시 403 또는 404를 반환한다. |
| REQ-122 | 회원 탈퇴 | M | 로그인한 사용자는 계정을 탈퇴할 수 있다 (`DELETE /api/auth/me`). 탈퇴하면 계정, 세션, 단어장, 단어, 북마크, 학습 이력, 퀴즈 세션을 **모두 영구 삭제**하고 세션 쿠키를 만료시킨다 (204). 탈퇴 전에 경고 확인과 닉네임 직접 입력 확인을 거친다. 탈퇴한 닉네임은 다시 사용할 수 있다. |

### 4.2 단어장 (Wordbook)

| ID | 요구사항 | 우선순위 | 상세 기준 (Acceptance Criteria) |
| :--- | :--- | :---: | :--- |
| REQ-004 | 단어장 생성 | M | 단어장 이름(1~50자, 필수)과 설명(0~200자, 선택)을 입력받아 생성한다. 동일 사용자 내 단어장 이름 중복은 거부한다 (D1 확정). |
| REQ-005 | 단어장 목록 조회 | M | 본인 단어장 목록을 최근 수정순으로 페이지 단위 조회한다. 기본 페이지 크기는 20건이다 (Q 확정). |
| REQ-006 | 단어장 수정 | M | 이름과 설명을 수정한다. 이름 변경 시에도 사용자 내 중복을 거부한다. 수정 시각을 갱신한다. |
| REQ-007 | 단어장 삭제 | M | 삭제 시 소속 단어와 북마크, 학습 이력도 함께 삭제한다 (하드 삭제, Q3 확정). 삭제 전 확인 모달(SweetAlert2)을 띄운다. |
| REQ-123 | 기본 단어장 자동 제공 | M | 모든 가입자에게 **초급 필수 영단어 200, 중급 핵심 영단어 200, 고급 심화 영단어 200** 3개 단어장을 가입 직후 자동으로 만들어 준다. 각 단어장은 표제어, 뜻, 예문이 있는 단어 200개를 가지며, 사용자 소유이므로 수정과 삭제가 가능하다. 계정 생성과 단어장·단어 삽입은 한 트랜잭션으로 처리하며, 실패하면 아무것도 남지 않는다. |
| REQ-128 | 단어장 단어 수 노출 | S | 단어장 목록과 단어장 상세 응답에 `word_count`(단어 수)를 포함한다. 목록은 한 번의 집계 쿼리로 모든 단어장의 개수를 구하며, 단어가 없는 단어장은 0이다. 카드에는 "N개 단어" 배지로 보여 준다 (천 단위 구분 기호 사용). |
| REQ-130 | 중급 1,000제 추천 프리셋 | S | 단어장 화면의 "추천 1,000제 추가" 버튼을 누르고 확인하면 "중급 필수 영단어 1,000" 단어장을 내 계정에 만든다. 단어 1,000건은 단어장 생성과 한 트랜잭션으로 저장하며, 실패하면 아무것도 남지 않는다. 같은 이름의 단어장이 이미 있으면 409, 프리셋 데이터 파일이 없으면 503으로 안내한다. 데이터는 저장소의 `intermediate_1000.csv`(헤더 `term,meaning,example`)이다. |

| :--- | :--- | :---: | :--- |
| REQ-008 | 단어 추가 | M | 표제어(영문/원어, 1~100자, 필수), 뜻(1~200자, 필수), 예문(0~500자, 선택)을 입력받아 단어장에 추가한다. 동일 단어장 내 표제어 중복은 거부한다 (대소문자 무시). |

| REQ-010 | 단어 수정 | M | 표제어, 뜻, 예문을 수정한다. 수정 후 표제어 중복 규칙을 다시 검증한다. |
| REQ-011 | 단어 삭제 | M | 단어를 삭제하면 해당 단어의 북마크와 학습 이력도 함께 삭제한다. |
| REQ-125 | 발음 청취 (TTS) | S | 단어 목록, 플래시카드, 퀴즈 화면에 스피커 버튼을 두고, 브라우저 음성 합성(Web Speech API, 영어 en-US, 속도 0.9, 음높이 1.0)으로 표제어를 읽어 준다. 연속으로 누르면 이전 발음을 끊고 새로 읽는다. 음성을 지원하지 않는 브라우저에서는 예외를 던지지 않고 실패를 무시한다. 외부 음성 서비스와 API 키는 쓰지 않는다. |

### 4.4 학습 (Study)

| ID | 요구사항 | 우선순위 | 상세 기준 (Acceptance Criteria) |
| :--- | :--- | :---: | :--- |
| REQ-012 | 플래시카드 학습 | M | 카드 앞면(표제어)을 보여주고, 탭하면 뒷면(뜻·예문)을 뒤집어 보여준다. 좌우 스와이프 또는 버튼으로 이전/다음 카드로 이동한다. |
| REQ-013 | 플래시카드 셔플 | S | 셔플 버튼으로 카드 순서를 무작위로 섞는다. 셔플 해제 시 원래 순서로 복원한다. |
| REQ-014 | 객관식 퀴즈 | M | 표제어를 보여주고 뜻 4지선다 중 하나를 고르게 한다. 오답 3개는 같은 단어장의 다른 단어 뜻에서 무작위로 추출한다. 단어장이 4개 미만이면 퀴즈를 시작할 수 없다는 안내를 띄운다. |
| REQ-015 | 퀴즈 결과 | M | 보기를 고르면 **즉시** 정오를 보여 준다 (정답 초록, 오답 빨강). 마지막 문항 뒤에는 정답 수, 정답률, 오답 노트(틀린 단어, 정답 뜻, 내가 고른 뜻)를 보여 준다. 결과는 새로고침 후에도 같은 탭에서 복구된다 (결과 캐싱). |
| REQ-016 | 학습 이력 기록 | S | 퀴즈 제출 시 **문항별 정답 여부와 제출 시각**을 저장한다. 사용자의 최근 학습 이력 **100건을 최신순**으로 조회할 수 있다 (Q5 확정: 1차 포함). 한 퀴즈의 기록은 단일 트랜잭션으로 저장한다. |
| REQ-124 | 퀴즈 즉각 피드백과 해설 | M | 문항마다 보기를 고르는 즉시 정답 뜻과 **해설 예문**을 보여 주는 카드가 나타나고, 그 카드의 [다음 문항] 버튼으로 넘어간다. 한 문항은 한 번 답하면 잠긴다. 예문이 없는 단어는 "해설 예문이 없습니다"를 보여 준다. 출제 응답에 정답 인덱스와 예문이 포함된다 (정답 비노출 원칙은 이 요구로 폐지되었다). |
| REQ-129 | 오답 복습 퀴즈 | S | 학습 이력 화면에서 최근 100건의 틀린 고유 단어로 퀴즈를 시작한다. 같은 단어를 여러 번 틀려도 문항은 한 번만 나온다. 고유 오답 단어가 4개 미만이면 시작 버튼을 비활성화하고 현재 개수를 안내하며, 서버도 400으로 거부한다 (`복습 가능한 오답 단어가 4개 미만입니다 (현재 N개)`). 보기는 사용자 전체 단어 풀에서 뽑는다. 출처(단어장, 북마크, 오답 복습)는 정확히 하나만 지정할 수 있다 (422). |
