## 1. 개요

모바일 기기에서도 편하게 쓸 수 있는 웹 영어 단어 학습 서비스를 만든다. 사용자는 서비스가 제공하는 표준 단어장을 골라 플래시카드와 퀴즈로 학습하고, 틀린 단어를 다시 보며, 학습 진도와 성적을 확인한다. AI기반프로그래밍 2026-2 기말과제 「단어장 앱」의 제출물이다.

## 2. 배경과 해결하려는 문제

| 문제 | 해결 방향 |
| :--- | :--- |
| 단어를 직접 모으고 입력하는 준비가 학습을 시작하기 어렵게 한다 | 표준 단어장(5종, 1,000단어)을 제공해 가입 직후 바로 학습한다 |
| 외운 단어를 잊고, 무엇을 다시 봐야 할지 알기 어렵다 | 오답 복습, 간격 반복 복습, 북마크를 제공한다 |
| 학습이 쌓이는 것이 보이지 않으면 꾸준히 하기 어렵다 | 일차 진도, 오늘의 목표, 학습 통계와 성적 추이를 보여 준다 |
| 짧은 이동 시간에 휴대전화로 학습한다 | 모바일 뷰포트를 우선해 설계한다 |

## 3. 목표와 성공 기준

| 목표 | 성공 기준 | 확인 방법 |
| :--- | :--- | :--- |
| 과제 기본 요건 충족 | 요구사항 명세 §11 의 기본 항목을 구현하고, 차이가 있으면 기록한다 | 명세 §11 상태 표시 |
| 모바일 사용성 | 360px 폭에서 화면이 깨지지 않고 터치 영역이 44px 이상이다 | 소스 검사 테스트, 실기기 수동 점검 |
| 재현 가능한 배포 | 루트 `Dockerfile` 빌드와 서버 규격 점검이 통과한다 | `docker-check` 워크플로 |
| 응답 성능 | 동시 사용자 50명, p95 300ms 이하 (REQ-102) | **검증 수단이 아직 없다** |
| 추적 가능성 | 요구사항 ID 로 문서·코드·테스트를 잇는다 | 명세 §7 추적 매트릭스 |

## 4. 대상 사용자

| 사용자 | 설명 | 주요 관심사 |
| :--- | :--- | :--- |
| 일반 학습자 | 표준 단어장으로 학습하는 주 사용자 | 모바일에서 빠른 학습, 틀린 단어 복습, 진행 상황 확인 |
| 관리자 | 고정 `admin` 계정 | 단어장과 단어 등록·수정, CSV 일괄 등록 |
| 운영자·개발자 | Docker 환경에서 서비스를 운영 | 컨테이너 기동, 마이그레이션, 로그 확인 |

## 5. 범위

### 5.1 포함
- 닉네임·비밀번호 계정과 사용자별 데이터 분리
- 표준 단어장 조회·선택, 단어 검색
- 플래시카드·퀴즈(4지선다·OX, 출제 방향 선택), 발음 듣기
- 오답·간격 반복 복습, 북마크, 일차 진도, 학습 통계
- 관리자의 단어장·단어 관리와 CSV 일괄 등록
- 모바일 우선 반응형 UI, 다크 모드

### 5.2 제외
- 단어장 공유와 협업 편집
- 일반 사용자의 개인 단어장·단어 생성
- 이메일 가입·인증, 소셜 로그인, 비밀번호 찾기
- 다른 계정의 통계 조회 (과제 도전 항목 중 선택하지 않음)
- 네이티브 앱, 외부 사전 API 연동, CSV 내보내기

## 6. 핵심 사용자 시나리오

| ID | 시나리오 |
| :--- | :--- |
| S-01 | 가입하면 초급 단어장이 학습 단어장이 되고 홈에서 바로 학습을 시작한다 |
| S-02 | 모바일에서 플래시카드를 뒤집으며 "알아요 / 헷갈려요"로 응답한다 |
| S-03 | 퀴즈를 풀며 정오와 해설을 바로 확인하고, 끝나면 정답 수와 오답을 본다 |
| S-04 | 탐색 화면에서 다른 표준 단어장을 골라 학습 단어장을 바꾼다 |
| S-05 | 복습함에서 북마크나 틀린 단어로 복습한다 |

## 7. 제약 조건

| 구분 | 내용 |
| :--- | :--- |
| 기술 | FastAPI, SQLAlchemy(aiosqlite), Alembic / 빌드 없는 Vanilla JavaScript / SQLite |
| 배포 | 루트 `Dockerfile`, `0.0.0.0:8080`, UID 10001, 쓰기는 `/data`·`/tmp` 만 |
| 네트워크 | 실행 중 인터넷을 쓰지 않는다. 외부 자원은 저장소에 포함한다 |
| 보안 | 비밀값은 환경 변수로 받는다 (예외: 관리자 초기 비밀번호, ADR-011) |
| 개발 환경 | Windows 11 + WSL2 (Ubuntu 24.04), Docker |

## 8. 추진 체계와 산출물

- 사용자가 요구사항과 범위를 결정·승인하고, AI 에이전트(Claude Code)가 분석·설계·구현·문서화를 수행한다 (`CLAUDE.md`, `개발방법론.md` §3).
- 작업 흐름: 요구사항 명세 → 설계 문서 → 실패하는 테스트 → 구현 → 검증.
- 산출물(`docs/`): 개발 방법론, 프로젝트 기획서, 요구사항 명세서, 시스템 아키텍처 설계서, 데이터 설계서, API 연동 규격서, UI/UX 설계서, 결정 기록, 테스트 정의서.
