## 1. 목적과 범위

보다보카의 **실행 구조**(어떤 프로세스·컨테이너가 어디서 돌고 서로 어떻게 통신하는가)와 **소스 구조**(계층과 의존 방향)를 정의한다. 테이블 규격은 데이터 설계서, 엔드포인트 규격은 인터페이스 정의서, 화면 규격은 UI/UX 설계서가 정하며 이 문서는 되풀이하지 않는다.

## 2. 설계 원칙

| # | 원칙 | 근거 |
| :-: | :--- | :--- |
| P1 | **빌드 없는 프론트엔드**: HTML, ES 모듈, `vendor/` 에 둔 라이브러리만 쓴다 (CDN 요청 없음). 번들러·npm 런타임 의존성이 없다 | CLAUDE.md §1 |
| P2 | **단일 출처(same-origin)**: API 와 정적 프론트를 한 FastAPI 프로세스가 서빙한다 | ADR-001 (쿠키 인증, CORS·CSRF 면적 최소화) |
| P3 | **DB 와 앱을 모두 컨테이너로 실행할 수 있다**: DB 는 항상 컨테이너, 앱은 컨테이너(권장) 또는 호스트 `.venv` 로 실행한다. 개발 중 호스트 직접 실행도 허용한다 | REQ-116, 117, 152, ADR-009, CLAUDE.md §4-7 |
| P4 | **비동기 I/O**: 라우터부터 DB 드라이버까지 async | REQ-101 |
| P5 | **스키마는 Alembic 으로만 변경** | REQ-107 |
| P6 | **서버가 판정, 클라이언트는 표시**: 정답 채점·통계·숙련·SRS 일정은 서버에서 계산한다 | Data Design D16, D17, D15 |
| P7 | **콘텐츠와 학습 상태 분리**: 표준 단어장은 읽기 전용 공용 데이터, 사용자는 진행 상태만 소유 | Data Design D10 |

## 3. 시스템 컨텍스트

```text
 [사용자 브라우저 (모바일 우선, Chrome/Edge 최신)]
        │  HTTP (same-origin, 세션 쿠키 voda_session)
        │  ├─ GET /, /css/*, /js/*     정적 프론트엔드
        │  ├─ /api/*                   REST API (JSON)
        │  └─ GET /health              프로세스·DB 헬스체크
        ▼
 [Docker 호스트 (개발: WSL2 + Docker Desktop / 배포: 학교 서버)]  호스트 포트 ${APP_PORT:-8080}
   └─ [컨테이너 voda-voca-app] (단일 컨테이너, UID 10001, 쓰기는 /data 와 /tmp 만)
         ├─ docker-entrypoint.sh: alembic upgrade head → exec uvicorn :8080
         ├─ FastAPI (단일 프로세스) + 정적 프론트엔드
         │     aiosqlite (같은 프로세스 안, 네트워크 없음)
         │     ▼
         └─ SQLite 파일 /data/voca.db (WAL) ← 볼륨 voda-voca-data

 학교 서버에서는 앞단 nginx 가 /2026/voca-<학번>/ 아래로 앱을 옮긴다 (§4.2).
 호스트에서 앱을 직접 실행하는 개발 방식(.venv, DB_PATH=./data/voca.db)도 지원한다.

 ※ 화면 자원(Tailwind, SweetAlert2, Lucide, 서체)도 /vendor/* 로 같은 출처에서 받는다 (외부 CDN 없음, 2026-11-24)
```

- **행위자**: 일반 사용자 한 종류. 관리자 역할은 1차에서 제외했다 (요구사항 Q8).
- **외부 시스템**: 서버가 호출하는 외부 서비스는 없다. 외부 의존도 없다. 화면 자원은 `vendor/` 에서 제공한다 (2026-11-24, A4 해소).
- 발음 듣기는 브라우저의 Web Speech API, 효과음은 Web Audio 합성이라 서버나 음원 파일이 필요 없다.

## 4. 배포(실행) 토폴로지

| 구성요소 | 실행 위치 | 정의 파일 | 포트 | 비고 |
| :--- | :--- | :--- | :-: | :--- |
| FastAPI 앱 | Docker 컨테이너 `voda-voca-app` (권장) 또는 호스트 `.venv` | `Dockerfile`(prod 가 마지막 스테이지), `docker-entrypoint.sh`, `src/backend/main.py` | `${APP_PORT:-8080}` → 8080 | UID 10001, `--cap-drop ALL` 에서도 동작, 이미지 `HEALTHCHECK` 로 `/health` 확인, `restart: unless-stopped` |
| SQLite DB | 앱과 같은 컨테이너의 `/data/voca.db` | `src/backend/db/session.py`, `docker/docker-compose.yml` | - | 볼륨 `voda-voca-data` 에 보관. WAL 이라 `-wal`, `-shm` 파일이 함께 생긴다 |
| 정적 프론트엔드 | 위 FastAPI 프로세스 | `src/frontend/` | 8080 | `StaticFiles(html=True)` 를 `/` 에 마운트 |

기동 순서(컨테이너): `docker compose up -d --build` 한 번이면 entrypoint 가 마이그레이션을 적용한 뒤(빈 DB 에서도 시작) 서버를 띄우고, 앱 시작(lifespan) 시 표준 단어장 시드를 DB 에 반영하고, 이어서 관리자 계정이 없으면 만든다 (REQ-159, ADR-011). 호스트 직접 실행: `alembic upgrade head` → `uvicorn`. 시작부터 `/health` 200 까지 약 4초(시드 1,000단어 포함)다.

**설정 주입**: 모든 값은 루트 `.env` 또는 OS 환경 변수 → `core/config.py` 의 `Settings`(pydantic-settings). 저장소에는 `.env.example` 만 둔다 (REQ-112).

| 변수 | 사용처 |
| :--- | :--- |
| `DB_PATH` | SQLite 파일 경로 (기본 `/data/voca.db`). 상위 디렉터리가 없으면 만든다 |
| `SECRET_KEY` | 비밀값 주입 자리. 세션은 DB 토큰 방식이라 지금은 사용처가 없고, 컨테이너 compose 가 필수로 요구한다(`${SECRET_KEY:?…}`) |
| `TZ` | 컨테이너 시간대 (저장은 항상 UTC) |
| `APP_PORT` | 앱 컨테이너가 호스트에 여는 포트 (기본 8080) |
| `COOKIE_SECURE` | 세션 쿠키 Secure 속성 (HTTPS 배포 시 true) |
| `SESSION_TTL_DAYS`(기본 14), `BCRYPT_ROUNDS`(기본 12) | 코드 기본값, 필요 시 환경 변수로 덮어씀 |

### 4.2 서버 접두사 대응 (REQ-153)

학교 서버는 앞단 nginx 가 앱을 `/2026/voca-<학번>/` 아래로 옮기고(경로의 접두사를 떼어 `app:8080/` 로 프록시), 응답의 `href="/…"`, `src="/…"`, `url(/…`, `fetch("/…` **리터럴 문자열만** 접두사로 치환하며 쿠키 `Path` 도 접두사로 바꾼다. 앱은 다음으로 대응한다.

| 대상 | 방식 |
| :--- | :--- |
| 정적 자원 | `vendor/…`, `css/…`, `js/…` 상대경로 |
| 화면 이동 | 해시 라우팅(`#/…`)이라 서버 경로와 무관 |
| API 호출 | `js/core/api.js` 의 `resolveApiBase(import.meta.url)` 가 **모듈 파일 위치에서 두 단계 위**를 앱 루트로 삼아 `/api` 또는 `/2026/voca-<학번>/api` 를 계산한다. 상대경로 `api` 는 주소창이 슬래시 없이 열리면 `/2026/api` 로 어긋나므로 쓰지 않았다. 호스트는 붙이지 않는다 |
| 쿠키 | nginx 가 `Path` 를 접두사로 바꿔도 API 경로가 그 아래라 인증이 유지된다 |

로컬에서 점검 워크플로의 `run` 블록을 그대로 재현해 가입·로그인·쿠키 인증이 접두사 아래에서 동작함을 확인했다. 실제 GitHub Actions 는 커밋 `d027de4` 에서 전 단계 성공했다.

### 4.1 이미지와 개발용 override

리포 루트에 `Dockerfile`, `docker-entrypoint.sh` 가 있고 `docker/` 에는 `docker-compose.yml`(app 단일 서비스), `docker-compose.dev.yml`(개발용 override)이 있다. 빌드 컨텍스트는 프로젝트 루트이고 `.dockerignore` 가 비밀·로컬 자산을 걸러 낸다.

| 단계 | 내용 |
| :--- | :--- |
| `base` | `python:3.12-slim`, `requirements.txt` 만 먼저 설치해 소스가 바뀌어도 의존성 레이어를 재사용한다. 시간대 `Asia/Seoul`, `PYTHONPATH=/app/src`, `DB_PATH=/data/voca.db` |
| `dev` | `base` + `requirements-dev.txt`. 사용자 `app`(uid 1000, WSL 기본 사용자와 같아 마운트 권한이 맞는다). 소스는 복사하지 않고 마운트해 `uvicorn --reload` 로 실행. 헬스체크 없음 |
| `prod` (마지막 스테이지 = 기본 빌드 대상) | `base` + `src/` 복사, 사용자 `app`(**uid 10001**), `/data` 소유권 지정, 8080, 마이그레이션 entrypoint, `--proxy-headers`. 8080 `/health` 헬스체크. 테스트 코드·`.env`·DB 파일은 이미지에 없다. 이미지 약 296MB |

- `.dockerignore`: `.env`, `.env.*`, `.venv`, `.git`, `ai-agent`, `docs`, 테스트 코드 등을 제외한다.
- **dev override 의 마운트 정책**: `./src` 는 쓰기 가능, `pytest.ini`·`.coveragerc`·`docker/`·`Dockerfile`·`docker-entrypoint.sh`·`.dockerignore`·`.gitattributes`·`.gitignore` 는 읽기 전용. 저장소 전체와 `.env` 는 마운트하지 않아 루트 비밀번호가 컨테이너에 노출되지 않는다. 컨테이너 안에서 `pytest`, `alembic check` 를 실행한다.
- 정적 서빙(`FrontendStaticFiles`): `vendor/` 응답에만 `Cache-Control: public, max-age=31536000, immutable` 을 붙이고(경로에 버전이 있어 안전), woff2 MIME 을 `font/woff2` 로 등록한다 (ADR-007 결정 6).

## 5. 소프트웨어 구조

### 5.1 백엔드 계층

```text
HTTP 요청
  → routers/      얇은 계층: 경로, 인증 의존성, 입력/출력 스키마 연결, 상태 코드 변환
  → services/     비즈니스 규칙: 출제·채점·SRS·통계·북마크·인증. 트랜잭션 경계
  → models/       SQLAlchemy 2.x ORM (비동기)
  → db/session.py 엔진·세션 팩토리, 요청당 1세션 (get_db_session). 연결 PRAGMA 와 BEGIN IMMEDIATE 설정, db/errors.py 무결성 오류 판별
  → SQLite (aiosqlite)
schemas/          Pydantic 요청·응답 모델 (REQ-111). 라우터와 서비스가 공유
core/             config, deps(get_current_user, get_admin_user), rate_limit, admin, terms(표제어 중복 판정)
```

의존 방향은 위에서 아래 한 방향이다. `services/` 는 FastAPI 에 의존하지 않는다 (오류는 `services/errors.py` 의 도메인 예외로 던지고 라우터가 HTTP 로 바꾼다). 이 덕에 `session_picker.py`, `srs.py`, `progress.py` 같은 순수 함수는 DB 없이 단위 테스트한다.

| 라우터 (prefix) | 책임 | 핵심 서비스 |
| :--- | :--- | :--- |
| `/api/auth` | 가입, 로그인, 로그아웃, 내 정보, 탈퇴 | `auth`, `password`, `session` |
| `/api/vocabularies`, `/api/users/me` | 표준 단어장 목록, 단어 목록, 활성 단어장 지정 | `system_vocab` |
| `/api/admin` | 관리자 단어장·단어 생성·수정·삭제, CSV 일괄 등록 (라우터 전체에 관리자 검사) | `admin_content`, `csv_import`(DB 없는 파싱·검증, ADR-013) |
| `/api/study/sessions` | 학습 세션 생성, 문항별 답 기록 | `learning_session`, `session_picker`, `progress`, `srs` |
| `/api/study` | 오답 단어, 통계, 학습 이력 | `stats`, `study_log`, `study` |
| `/api/bookmarks` | 북마크 추가·삭제·목록 | `bookmark` |
| `/api/users/me/settings` | 학습 개수·목표 설정 | 서비스 없이 라우터가 `users` 컬럼을 직접 읽고 갱신 (단순 CRUD 예외) |
| `/health` | 프로세스와 DB 연결 확인 | 라우터 직접 (`SELECT 1`) |

라우터 등록 후 **마지막에** 정적 프론트를 `/` 에 마운트한다. 라우트가 먼저 매칭되므로 `/api`, `/health` 는 정적 마운트에 가려지지 않는다.

### 5.2 프론트엔드 구조

```text
index.html ─ <script type="module" src="js/app.js">
js/app.js        부트스트랩, 상단바·하단 탭바·계정 메뉴, 401 처리 등록
js/routes.js     해시 라우트 표 (#/home, #/explore, #/review, #/stats, #/study/session …)
js/core/         DOM 이 없는 순수 로직: api, router, 세션 러너·드라이버, 콤보, 뷰모델, 저장소, 사운드, TTS
js/views/        화면 (core 의 모델을 받아 textContent 로 렌더링)
js/views/components/  북마크 버튼, 해설 시트, 단어 시트, 품사 태그 등
css/app.css      디자인 토큰, 컴포넌트, 다크 모드 (Tailwind Play 스크립트와 병용)
vendor/          자체 호스팅 외부 자원 (출처·버전·라이선스: vendor/README.md)
tests/           node --test (순수 로직 + 소스 수준 정적 검사)
```

- **규칙**: `core/` 는 DOM 을 건드리지 않는다. 그래서 외부 패키지 없이 `node --test` 로 검증한다 (P1).
- **API 접근**: 모든 호출이 `core/api.js` 하나를 거친다 (쿠키 전송, 오류 본문 정규화, 401/429 처리, 15초 시간 초과).
- **렌더링 보안**: `innerHTML` 을 쓰지 않고 `textContent` 만 쓴다.
- **클라이언트 저장**: 효과음·테마(`voda.sound_muted`, `voda.theme`)만 브라우저 `localStorage` 에 둔다. 학습 설정은 서버에 저장한다.

### 5.3 시드(콘텐츠) 파이프라인

```text
src/backend/data/seeds/vocabularies.json + words/*.json (5종, 1,000단어)
   → 서버 시작 시 services/system_seed.py 가 검증·적재 (멱등)
       단어장은 slug, 단어는 (vocabulary_id, term) 으로 식별
       content_hash 가 같으면 건너뛰고, 다르면 UPDATE (word_id 불변 → 학습 기록 유지)
   → system_vocabularies, system_words (source='seed'. 관리자 등록분 source='admin' 은 보존하고,
     같은 표제어가 시드에 들어오면 시드가 우선한다, ADR-012)
```

시드 파일을 바꾸면 서버 재시작 때 운영 DB 에 반영된다. 파일 추가·수정 전에 DB 백업이 필요하다 (README §3.6).

## 6. 핵심 런타임 흐름

### 6.1 인증 (ADR-001)

```text
로그인 → services/auth: 닉네임 조회, bcrypt 검증 (계정 없어도 해시 비교를 수행)
       → services/session: secrets.token_urlsafe(32) 발급, SHA-256 다이제스트만 sessions.id 에 저장
       → Set-Cookie voda_session (HttpOnly, SameSite=Lax, Secure=COOKIE_SECURE), 절대 만료 14일
이후 요청 → core/deps.get_current_user: 쿠키 → 해시 → sessions 조회(만료 조건) → User
          쿠키 없음·만료·삭제는 모두 같은 401
```

로그인 무차별 대입 방어(REQ-121)는 `core/rate_limit.py` 의 **프로세스 메모리** 슬라이딩 윈도우다 (IP 또는 닉네임 기준 1분 5회). 외부 저장소를 쓰지 않는다.

### 6.2 학습 세션 (출제와 채점)

```text
POST /api/study/sessions {mode, source}
  → learning_session.create_session
      활성 단어장 확인 → session_picker.select_session_words (순수 함수)
        워터폴: 오답 ≤30%, 복습 10% 선확보, 나머지 미학습, 부족 시 복습 충원. 복습 슬롯은 SRS 복습 기한이 지난 단어를 오래 밀린 순으로 먼저 쓴다 (REQ-150)
      → 문항 스냅샷을 quiz_sessions.questions(JSON) 에 저장
      → 응답에는 정답·해설을 싣지 않는다 (D16)
POST /api/study/sessions/{id}/answer
  → record_session_answer (한 트랜잭션, REQ-106)
      채점(서버) → study_logs 추가 → progress.apply_result (연속 정답, 숙련 판정)
                 → srs.schedule_next (복습 단계·다음 복습 시각)
      → 응답에서 처음으로 정답·해설 공개
```

- 문항은 출제 시점에 스냅샷으로 저장하므로, 이후 시드가 바뀌어도 진행 중인 세션이 흔들리지 않는다.
- 한 번 낸 답은 바뀌지 않는다 (멱등 기록은 `quiz_sessions.answers` 로 보장).
- 복습 세션(북마크, 오답, 오늘 복습)은 같은 엔드포인트의 `source` 값(`bookmarks`, `wrong`, `due`)으로 구분하며 활성 단어장을 바꾸지 않는다.

### 6.3 통계

`services/stats.py` 가 전체 이력에서 서버 집계한다 (누적 정답률, 연속 학습일, 최근 7일, 단어장별 숙련도). 날짜 경계는 KST, 저장은 UTC (REQ-109).

일차 진도(REQ-165, ADR-014)는 `services/study_day.py` 가 정한다. 답을 기록하는 `study_log.record_result` 와 통계 화면이 같은 함수 `current_day` 를 써서 저장한 일차와 보이는 일차가 어긋나지 않는다.
