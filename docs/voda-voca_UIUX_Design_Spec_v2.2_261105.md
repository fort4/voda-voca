## 1. 설계 원칙

1. **모바일이 기준입니다.** 360px 폭을 최소 기준으로 그리고, 430px와 데스크톱으로 넓힙니다. 가로 스크롤은 어떤 폭에서도 생기지 않습니다 (REQ-020).
2. **한 화면에 한 가지 작업**을 둡니다. 홈에서 **한 번 탭하면** 학습이 시작되어야 합니다 (S-02). 학습 세션은 한 문항에만 집중하게 하고 탭바를 숨깁니다.
3. **서버가 정답을 알고 있습니다.** 출제 응답에는 정답이 없고(REQ-014), 보기를 고르면 서버가 채점해 정오와 해설을 돌려줍니다(REQ-124). 화면은 정답을 미리 알지 못한 채 그립니다.
4. **오류는 가까운 곳에 보입니다.** 입력 오류는 입력 칸 아래, 화면 오류는 화면 안, 확인이 필요한 행위는 SweetAlert2 모달에 둡니다 (REQ-022).
5. **브라우저 기본 `alert`, `confirm`, `prompt`는 쓰지 않습니다** (REQ-022).
6. **없는 값은 그리지 않습니다.** 예문, 예문 뜻 등 값이 없으면 그 줄을 렌더링하지 않습니다.

**탭바 노출/숨김 규칙** (`isTabbarVisible`)
| 조건 | 탭바 |
| :--- | :--- |
| 로그인하지 않음 | 숨김 |
| `/login`, `/signup` | 숨김 |

- 활성 탭은 `aria-current="page"` 와 알약형 인디케이터로 표시합니다. 탭 하나의 터치 영역은 최소 44×44px 입니다.

## 3. 화면 정의

### 3.1 로그인 · 회원가입 (REQ-001, REQ-121)

**목적**: 계정을 만들고 세션을 시작합니다.

**로그인 화면 요소**
- 닉네임 입력 (`autocomplete="username"`, v1.1: 이메일 없음)
- 비밀번호 입력 (`type="password"`, `autocomplete="current-password"`, 표시 전환 아이콘)
- "로그인" 기본 버튼 (전체 너비, 높이 48px)
- "회원가입" 텍스트 링크

**회원가입 화면 요소**
- 닉네임(2~30자, 다른 사람과 겹치지 않는 이름 안내), 비밀번호(8자 이상, 72바이트 이하 안내). 이메일 입력은 없다 (v1.1)
- 가입 성공 시 로그인 화면으로 이동하고 "가입이 완료되었습니다. 로그인해 주세요." 토스트

**동작**
- 로그인 성공 → `next` 경로 또는 홈(`#/`)
- 401 → 비밀번호 칸 아래에 "닉네임 또는 비밀번호가 올바르지 않습니다." (입력 값은 유지, 비밀번호만 지움)
- 429 → 버튼을 비활성화하고 카운트다운을 표시합니다. 규격은 §5.2 참조.
- 409 (가입) → 닉네임 칸 아래에 "이미 사용 중인 닉네임입니다."

**상태**: Idle, Submitting(버튼 스피너), Blocked(429 카운트다운), Error(401·409·422·네트워크)

### 3.2 홈 (REQ-012, REQ-131, REQ-142)

가장 먼저 보이는 화면이며 **세션 시작까지 한 번의 탭**이 목표입니다.

| 영역 | 내용 |
| :--- | :--- |
| 활성 단어장 요약 카드 | "학습 중인 단어장" 라벨 + 단어장 제목(`h1`) + 진행률 바(`progress-bar.js`) + "N / M 학습" 문구. 활성 단어장이 없으면 "단어장을 골라 주세요"와 안내 문구 |
| 단어장 이동 버튼 | 활성이 있으면 "단어장 바꾸기", 없으면 "단어장 고르기" — 탐색(`#/explore`)으로 이동 |
| 오늘의 목표 카드 | 일일 목표 **15단어** (`DAILY_GOAL = 15`, 서버에 목표 설정이 없어 상수). 문구 "N문항 남았어요", 목표 바(`min(100, 오늘 학습 단어 수 / 15 × 100)`), "오늘 N개 학습". **오늘 학습 수는 고유 단어 기준** 입니다 (`GET /api/study/stats` 의 오늘 `count`, 같은 단어를 여러 번 풀어도 1). 달성하면 "오늘 목표를 채웠어요 🎉". 연속 학습일이 있으면 "N일 연속" 배지 |
| 학습 방식 토글 | 퀴즈 / 플래시카드 2칸 (`mode-toggle.js`). 마지막 선택을 `localStorage` 키 `voda.study.mode` 에 기억하며, 저장소를 못 써도 동작하고 알 수 없는 값은 퀴즈로 되돌립니다 |
| 세션 시작 CTA | 큰 주요 버튼 "15문항 …" (최소 높이 56px). 활성 단어장이 없으면 비활성. 누르면 `#/study/session?mode=<선택>` 로 이동 (활성 단어장 `source=all`) |

**상태**: Loading(스켈레톤), Success, Error(통계를 못 받아도 단어장 요약과 CTA 는 보이고 목표 영역만 "오늘 기록을 불러오지 못했어요.")

### 3.3 탐색 (REQ-140, REQ-141, REQ-142, REQ-133, REQ-144, REQ-145)

표준 단어장 카탈로그를 훑고 학습할 단어장을 고르는 화면입니다 (`views/explore-view.js`, `core/explore-model.js`).

- **필터 칩**: 카테고리 칩(전체 + 카탈로그에 실제 있는 카테고리, 처음 나온 순서)과 레벨 선택(전체 + `Lv.N`). 둘은 AND 입니다. 카테고리 표시 이름은 `ELEMENTARY`=초등, `SECONDARY`=중고등, `CSAT`=수능, `EXAM`=시험, `BUSINESS`=비즈니스(v2.2, REQ-145)이며, 목록에 없는 새 카테고리는 코드를 그대로 보입니다 (서버가 자유 문자열을 허용). 칩은 `aria-pressed` 로 선택 상태를 알립니다.
- **카테고리 칩 순서 (v2.2)**: 서버 정렬(`sort_order`)에서 처음 나온 순서이므로 `전체 · 초등 · 중고등 · 수능 · 시험 · 비즈니스` 6개입니다. 칩 행은 가로 스크롤이라 360px 에서도 넘치지 않아야 하며(수동 점검), 새 색 클래스를 쓰지 않아 다크 모드 규칙은 그대로입니다. 단어장 카드는 5장이 되며 `시험 · Lv.3 · 200단어`처럼 배지에 라벨이 표시됩니다.
- **카드 그리드**: 단어장 한 장 = 카드 한 장. 제목, "카테고리 · Lv.N · N단어", 설명(있을 때만), 진행률 바, "N / M 학습 · N 숙련" 문구, 학습 중이면 강조 표시.
- **카드 동작**: [미리보기] → 단어 프리뷰 바텀시트, [이 단어장으로 학습] → `POST /api/users/me/active-vocabulary` (멱등). 이미 활성인 카드는 "홈에서 학습" 으로 홈에 보냅니다. 성공하면 목록의 활성 표시를 갱신합니다.
- **단어 프리뷰 바텀시트** (`views/components/word-sheet.js`): 단어장의 단어를 **읽기 전용**으로 30개씩 보여 줍니다 (`GET /api/vocabularies/{id}/words`, "더 보기"로 다음 페이지). 행에는 표제어(오른쪽에 인접해 **품사**와 `/발음기호/` — 값이 있을 때만, §12.8·§12.9), 뜻, 예문(있을 때만), 예문 뜻(있을 때만)이 있습니다. `Esc`, 바깥 탭, 닫기 버튼으로 닫히고, 닫으면 열었던 버튼으로 포커스를 돌려 줍니다.
- **빈 결과**: 조건에 맞는 단어장이 없으면 "조건에 맞는 단어장이 없습니다."

### 3.4 복습함 (REQ-017, REQ-018, REQ-019, REQ-129)

틀린 단어와 북마크한 단어로 복습 세션을 시작하는 화면입니다 (`views/review-view.js`, `core/review-model.js`).

- **탭 2개**: **북마크**(`GET /api/bookmarks`) / **틀린 단어**(`GET /api/study/wrong-words`). 각각 20건씩 "더 보기"로 이어 받습니다.
- **행**: 표제어, 뜻, 소속 단어장 제목, 예문(있을 때만), 예문 뜻(있을 때만).
- **최소 진입 제약 (4문항 미만 방어)**: 복습 세션은 해당 출처의 단어가 **4개 이상**이어야 시작할 수 있습니다 (`REVIEW_MIN_WORDS = 4`, 서버의 퀴즈 최소 단어 수와 같음).
  | 개수 | 시작 버튼 | 안내 문구 |
  | :--- | :---: | :--- |
  | 아직 모름 | 비활성 | "불러오는 중이에요." (숫자를 지어내지 않음) |
  | 4개 미만 | 비활성 | "{북마크/틀린 단어}가 4개 이상이어야 복습할 수 있어요 (현재 N개)." |
  | 4개 이상 | 활성 | "{북마크한 단어/틀린 단어} N개로 복습합니다." |
- **복습 세션 CTA**: 활성이면 `#/study/session?mode=<선택>&source=bookmarks|wrong` 로 이동합니다. 복습 세션은 활성 단어장을 바꾸지 않습니다.
- **빈 상태**: 북마크 없음 / 틀린 단어 없음 각각 한 문장 + 홈으로 가는 버튼.
- 서버의 "틀린 단어" 규칙은 단어별 마지막 결과가 오답인 단어이며 맞히면 목록에서 빠집니다 (REQ-129).

### 3.5 통계 (REQ-131, REQ-132, REQ-133)

`GET /api/study/stats` 한 번으로 그립니다 (`views/stats-view.js`, `core/stats-page-model.js`). 전체 이력 기준이며 최근 100건 제한이 없습니다.

- **요약 카드 2개**: 누적 정답률(기록이 없으면 "—"), 연속 학습일(0이면 "오늘 학습하면 시작돼요"). 연속 학습일은 한국 날짜 기준입니다.
- **주간 학습 바 차트**: 최근 7일(오늘 포함)의 날짜별 학습 단어 수를 인라인 SVG 막대로 보여 줍니다 (`core/weekly-chart.js`). 같은 날 같은 단어는 한 번. 오늘 막대는 강조하고 "오늘" 뱃지, 막대를 누르거나 포커스하면 그 날의 개수를 표시합니다. 헤더에 7일 합계 "N개". 외부 차트 라이브러리는 쓰지 않습니다.
- **단어장별 숙련도 프로그레스**: 표준 단어장마다 한 줄 — 제목(학습 중이면 "학습 중" 표시), 퍼센트, 진행률 바, 보조 문구. 진행률은 서버 `vocabulary_progress[].percent`(한 번이라도 맞힌 단어 비율)입니다.
- **빈 상태**: 기록이 없으면 "첫 세션을 마치면 정답률과 진행률이 여기에 쌓여요."

### 3.6 학습 세션 러너 (REQ-012, REQ-014, REQ-015, REQ-016, REQ-124, REQ-125, REQ-127, REQ-137, REQ-144)

`#/study/session` 한 화면에서 퀴즈와 플래시카드를 모두 진행합니다. 탭바는 숨겨지고, **한 번에 한 문항**만 보입니다. 세션은 시작 시 `POST /api/study/sessions` 로 15문항(기본)을 받고, 문항마다 `POST .../answer` 로 즉시 채점·기록합니다.

**상태 머신** (`core/session-runner.js`, 구동은 `core/session-driver.js`)

```text
IDLE ─START─▶ LOADING ─SESSION_LOADED─▶ QUESTION_ACTIVE ─ANSWER_RECEIVED─▶ FEEDBACK_SHOWING
                │                            ▲   │                              │
                └─실패─▶ ERROR               │   ├─마감 초과─▶ EXPIRED           ├─ NEXT ─▶ QUESTION_ACTIVE
                                             │   └─검증·인증 실패─▶ ERROR         └─ 마지막 문항 ─▶ SESSION_COMPLETE
                                             └──────── NEXT ────────────────────────┘
```

**화면 구성 (1문항 집중 뷰)**
- 상단 진행 헤더(`progress-header.js`): 왼쪽 ✕ **학습 중단** 버튼(`Esc` 와 같은 동작, 중단 확인 모달), 가운데 진행 바(`role="progressbar"`), "N/M" 문구, 오른쪽 **단어 읽어 주기**(TTS, `speakButton`, 44px) 버튼. 재생 중에는 강조된다 (§12.6).
- 본문 — **퀴즈**: 표제어(크게) + 품사 태그(있을 때만, §12.9) + 문맥 예문(있을 때만) + 4지선다 버튼. 보기를 고르면 즉시 잠기고 서버 채점 응답을 기다립니다. 한 문항은 한 번 답하면 잠깁니다.
- 본문 — **플래시카드**: 카드 **앞면(표제어 + 그 아래 보조 줄 `품사 /발음기호/`)** 을 탭하거나 `Space`·`Enter` 로 뒤집어 **뒷면(뜻·영문 예문·예문 해석만 — 표제어와 발음기호는 앞면에서 이미 봤으므로 다시 보이지 않는다)** 을 본 뒤, **알아요 / 헷갈려요** 로 응답합니다. 카드 뒤집기는 3D 플립이며 `prefers-reduced-motion` 에서는 끕니다. 스와이프 제스처는 없습니다. 뒷면의 영문 예문 옆에는 **예문 발음 듣기** 버튼이 있고(누르면 카드가 뒤집히지 않는다), 앞면일 때 뒷면은 `inert` 라 포커스 순서에 끼지 않는다.
- **피드백 시트** (`views/components/feedback-sheet.js`, 예문과 예문 해석은 한 열 `.sheet-example-text` 에 묶고 44px 발음 버튼은 그 옆에 둔다 — 버튼 줄 아래에 해석을 따로 두면 줄 높이만큼 틈이 벌어진다): 응답을 받으면 화면 맨 아래에서 **200ms 슬라이드업** 으로 올라옵니다. 정오 제목(정답 초록 / 오답 빨강, 아이콘+텍스트 병기), 표제어와 그 오른쪽의 품사·`/발음기호/`(값이 있을 때만, §12.8·§12.9), 발음 듣기(`speakButton`), 뜻, 예문과 **예문 발음 듣기**(있을 때만)·예문 뜻, 숙련 달성 배지·**콤보 칩**(2콤보부터 "N콤보!"), **[다음 문항 (Enter)]** 버튼(자동 포커스). 답을 채점받을 때 효과음이 납니다(REQ-137: 정답 `correct`, 콤보 5·10·15 는 `milestone`, 퀴즈 오답은 `wrong`, 플래시카드 "헷갈려요"는 무음. 음소거 설정을 따릅니다. §12.7).
- **완료 화면** (`views/components/session-result.js`): 트로피 아이콘, 요약 제목·부제, 통계 칸(정답 수·정답률 등), "다시 볼 단어" 목록(틀린 단어와 뜻), 다음 행동 버튼(한 번 더 / 홈으로).
- **콤보 뱃지 줄** (`views/components/combo-badge.js`): 진행 헤더 바로 아래의 **28px 고정 높이** 줄(위아래 -6px 마진으로 간격 보정). 콤보가 **2 이상**일 때만 `flame` 아이콘 + "N콤보" 뱃지를 보이고, 줄 자체는 항상 있어 뱃지가 나타나도 카드가 밀리지 않습니다. 시각 전용(`aria-hidden`)이며 낭독은 해설 시트의 "N콤보!" 가 맡습니다. 완료 카드의 통계 칸에는 **최대 콤보**("N콤보")가 표시됩니다. 화면 규격은 §12.7.
- **효과음 토글**: 세션 진행 헤더에는 두지 않고 앱 헤더의 단일 토글(`#sound-toggle`, 아이콘 `bell-ring` 켬 / `bell-off` 끔, 라벨 "효과음 끄기/켜기")을 씁니다. 세션 중에도 앱 헤더가 그대로 보입니다. 발음(TTS) 버튼은 `volume-2` 로 아이콘이 다릅니다.
- **EXPIRED**: 서버가 `QUIZ_EXPIRED` 를 돌려주면 "마지막 답 이후 30분이 지났어요. 푼 문항은 이미 저장되어 있어요." 를 보여 주고 새 세션을 시작할 수 있게 합니다.
- **ERROR**: 서버 `X-Error-Code` 로 분기합니다 (API 규격서 §6.3). 출제할 단어가 없으면(`NO_WORDS_TO_STUDY`) 숙련 포함을 제안하거나 안내합니다.

**단축키 체계** (REQ-127, `core/session-view-model.js` 의 `sessionKeyAction`)
| 상황 | 키 | 동작 |
| :--- | :--- | :--- |
| 퀴즈, 문항 활성 | `1`~`4` | 해당 보기 선택 |
| 플래시카드, 앞면 | `Space`, `Enter` | 카드 뒤집기 |

- 버튼에 포커스가 있을 때 `Enter`/`Space` 는 브라우저가 그 버튼을 누르게 두고 단축키로 가로채지 않습니다.
- **Esc 세션 중단 모달** (SweetAlert2 확인): 제목 "학습을 중단할까요?", 본문 "푼 문항은 이미 저장되어 있어요.", 확인 버튼 "중단". 중단하면 홈으로 이동합니다. 답은 문항마다 서버에 저장되므로 잃는 것이 없습니다.

### 3.7 회원 탈퇴 (계정 메뉴) — REQ-122

- 진입: 상단바의 닉네임 칩을 누르면 계정 메뉴가 열립니다. 메뉴에는 **로그아웃**과 **회원 탈퇴**가 있습니다.
- 1단계 확인: "회원 탈퇴를 진행할까요?" 모달. 계정과 북마크, 학습 기록, 학습 진행도가 영구 삭제되고 되돌릴 수 없다고 안내합니다 (표준 단어장은 공용이라 영향이 없음). 확인 버튼은 "계속".
- 2단계 확인: 닉네임을 **정확히 입력**해야 "탈퇴하기" 가 동작합니다. 입력이 다르면 "닉네임이 일치하지 않습니다." (앞뒤 공백만 무시, 대소문자 구분)
- 성공: 세션 저장소를 비우고 로그인 화면으로 이동하며 "회원 탈퇴가 완료되었습니다." 토스트. 실패: 오류 토스트, 계정 유지.

### 3.7.1 계정 드롭다운 (REQ-134)

- 닉네임 칩 아래 오른쪽 정렬 팝오버(폭 16rem, 화면 밖으로 나가지 않게 최소 여백 8px). 칩은 `aria-haspopup="menu"`, `aria-expanded`.

- 바깥 탭(투명 백드롭)과 `Esc` 로 닫힙니다.

## 4. 상태 머신 공통 규격 (데이터 영역)

모든 데이터 영역(홈·탐색·복습함·통계의 목록과 카드)은 아래 상태 중 하나입니다. 학습 세션 러너의 상태는 §3.6 의 별도 상태 머신을 씁니다.

```text
           요청 시작
   Idle ──────────────▶ Loading ──성공(데이터 0건)──▶ Empty
                          │
                          ├──성공(데이터 있음)──▶ Success
                          │
                          └──실패──▶ Error ──재시도──▶ Loading
```

| 상태 | 화면 표시 | 전이 조건 |
| :--- | :--- | :--- |
| Idle | 아무것도 그리지 않음 | 화면 진입 전 |
| Loading | 스켈레톤(같은 모양의 회색 블록 3~5개). 텍스트 "불러오는 중"은 스크린리더 전용 | 요청 시작 |
| Empty | 아이콘 + 한 문장 + 행동 버튼 1개 | 성공이고 항목 0개 |
| Success | 실제 목록 또는 내용 | 성공이고 항목 1개 이상 |
| Error | 메시지 + "다시 시도" 버튼 | 실패(0, 5xx, 404 제외) |
| NotFound | "찾을 수 없습니다." + 상위 화면 이동 버튼 | 404 |
| Unauthorized | 화면 전환 (로그인으로) | 401 (API 규격서 §5.2) |

**Error 메시지 규칙**
- 네트워크 오류(0): "인터넷 연결을 확인해 주세요."
- 5xx·503: "서버에 문제가 있습니다. 잠시 후 다시 시도해 주세요."
- 그 밖의 실패: 서버 `detail`을 쓰되 기술 용어가 있으면 쉬운 말로 바꿉니다.

**규칙**
- 스켈레톤은 실제 목록과 같은 높이를 가져 화면이 튀지 않게 합니다 (CLS 방지).
- 재시도 버튼은 중복 요청을 막기 위해 요청 중에는 비활성입니다.
- Empty와 Error를 같은 문구로 쓰지 않습니다.

- 360px, 390px, 430px 세 폭에서 주요 화면을 캡처해 가로 스크롤이 없는지 확인합니다 (REQ-119). 검증 절차는 테스트 정의서에 씁니다.

### 6.2 Tailwind 브레이크포인트 사용 규칙
- 기본 클래스는 모바일 값을 씁니다. `sm:`(640px)과 `md:`(768px)에서 넓힙니다.
- 고정 폭(`w-[360px]`)은 쓰지 않습니다. `w-full`과 `max-w-*`를 씁니다.
- 가로 스크롤 방지: 긴 표제어는 `break-words` 또는 `truncate`로 처리합니다.
- 반응형으로 바뀌는 값(페이지 여백, 세로 간격, 카드 여백, 학습 단어 크기)은 Tailwind `sm:` 클래스를 화면마다 흩뿌리지 않고 `css/app.css` 의 토큰을 `@media (min-width: 640px)` 에서 한 번만 바꿔 적용합니다 (v2.2).

### 6.3 터치 타깃 (REQ-114)
- 모든 버튼과 링크는 **최소 44×44px**입니다. 아이콘만 있는 버튼도 같습니다 (아이콘이 24px여도 패딩으로 영역을 넓힘).
- 인접한 타깃 사이 간격은 최소 8px입니다.
- 목록 행 전체를 탭 영역으로 씁니다. 행 안의 별 아이콘은 별도의 44px 영역을 가집니다.

### 6.4 글자 크기 (REQ-115)
- 글자 크기는 §12.1 의 타입 스케일 토큰을 씁니다. `text-[15px]` 같은 임의값은 쓰지 않습니다 (`tests/design-tokens.test.js` 가 검사).
- 본문은 `text-body`(15px, 행간 1.65). **입력 칸은 16px 이상**이어야 iOS가 확대하지 않으므로 별도로 16px 를 유지합니다 (REQ-115).
- 학습 단어(`--fs-display`)는 모바일 32px, 640px 이상 40px. 목록에서는 `text-heading`(20px) 이하.
- 한글은 `word-break: keep-all` 로 어절 단위로 줄바꿈하고, 긴 영단어·URL 은 `overflow-wrap: anywhere` 로만 넘침을 막습니다. `word-break: break-word` 는 한글을 글자 단위로 쪼개므로 쓰지 않습니다.
- 행간은 1.2(제목)~1.65(본문).

## 10. 접근성

- 아이콘 버튼에는 `aria-label`을 붙입니다 (예: 이전 카드 "이전 카드").
- 색만으로 정답·오답을 구분하지 않습니다. 아이콘과 텍스트를 함께 씁니다.
- 대비: 본문 텍스트는 WCAG AA (4.5:1) 이상.
- 로딩 상태는 `aria-busy="true"`와 스크린리더 전용 텍스트로 알립니다.
- 모달을 열면 포커스를 모달 안으로 옮기고, 닫으면 열었던 버튼으로 돌려보냅니다.
- 동작 줄이기 설정(`prefers-reduced-motion`)을 따르면 카드 뒤집기와 해설 시트 애니메이션을 끕니다.
- 해설 시트는 `role="status"`, `aria-live="assertive"` 로 정오를 알립니다.

### 12.4 컴포넌트: `.btn` / `.card` / `.chip` (v2.2)

색은 모두 `var(--토큰)` 만 씁니다. 다크 모드는 `html.dark` 에서 토큰을 바꾸는 것으로 따라오며, 리터럴 색(`#hex`, `rgb()`)을 쓰면 `tests/dark-theme.test.js` 가 다크 규칙 누락으로 잡아냅니다.

**버튼 `.btn`** — `dom.js` 의 `button({variant, size, full, ...})` 가 클래스를 만듭니다(`buttonClass`). 알 수 없는 variant 는 primary.

| variant | 용도 | 비고 |
| :--- | :--- | :--- |
| `primary` | 화면의 주 행동 | 채움 `--btn-primary-bg`, 3D 가장자리 `--btn-primary-edge` |
| `secondary` | 보조 행동 | 표면 + 보더, 가장자리 `--btn-secondary-edge` (라이트 zinc-300, **다크 `#050506`**). 다크에서 가장자리는 표면보다 **어두워야** 한다 — 밝은 가장자리(`--border-strong`)는 버튼이 움푹 들어가 보였다 (`ui-polish.test.js` 가 검사) |
| `danger` | 파괴적 행동 | 빨강 채움 |
| `danger-soft` | 연한 위험 행동 | `--bad-soft` 배경 |
| `ghost` | 가장 약한 행동 | 투명 배경, 글자만 |

- 크기: 기본 44px, `size: "lg"` 는 56px(`.btn-lg`, 글자 `--fs-lead`). `full` 은 전체 너비.
- **3D 눌림**: 채움 계열은 `box-shadow: 0 3px 0 var(--btn-edge)` 로 아래 가장자리를 그리고, `:active` 에서 `translateY(2px)` + 그림자 1px 로 가라앉습니다(90ms). 그림자는 레이아웃 공간을 차지하지 않으므로 세로로 붙는 버튼 사이는 8px 이상 띄웁니다.
- **키보드 안내**: 버튼 안의 `(Enter)`, `(←)`, `(→)` 는 `kbdHint()` 가 만드는 `.kbd-hint` 입니다. 터치 기기(`@media (hover: none)`)에서는 숨기고 `aria-hidden` 으로 스크린리더에도 읽히지 않게 합니다.

**카드 `.card`** — 표면, 1px 보더, 반경 16px, 그림자 `--shadow-card`, 안쪽 여백 `--card-pad`. 변형: `.card-raised`(떠 있는 그림자), `.card-flat`(그림자 없음), `.card-interactive`(호버 시 1px 상승, 누르면 0.99배). 기존 `.surface` 는 여백 없는 표면용으로 남깁니다.

**칩 `.chip` / `.chip-sm`** — `.chip` 은 누르는 알약(필터). 높이 40px, 선택은 `aria-pressed="true"` 로 표시하며 인디고 채움 + 흰 글자. `.chip-sm` 은 보여 주기만 하는 작은 라벨(예: "학습자")로 `accent-soft` 배경 + 강조색 글자.

**명도 대비 (WCAG AA 4.5:1, `design-tokens.test.js` 가 계산·검사)**

| 조합 | 라이트 | 다크 |
| :--- | :--- | :--- |
| primary 버튼 (흰 글자) | `#4f46e5` 6.29:1 | `#5b5ff0` ≥ 4.5:1 (이전 `#6366f1` 은 4.47:1 로 미달) |
| danger 버튼 (흰 글자) | `#dc2626` 4.83:1 | `#dc2626` 4.83:1 |

| 복습함 | 선택한 출처의 복습 시작 | "더 보기" secondary |
| 통계 | 기록이 없을 때만 "학습 시작하기" | — |
| 학습 세션 | 퀴즈: 해설 시트의 "다음" / 플래시카드: "알아요" | "헷갈려요" secondary |
| 결과 | "한 번 더 하기" | "홈으로" secondary |

- 글자 위계는 화면 제목 `text-title` → 카드 제목 `text-heading` → 본문 `text-body` → 보조 `text-caption`/`text-micro`(`--muted`) 순으로 3단계 이상 건너뛰지 않습니다.
- 목록처럼 항목이 반복되는 곳의 항목별 행동은 primary 로 올리지 않습니다.

### 12.6 발음 듣기: `.btn-icon` / `.speak-btn` (v2.2)

REQ-125 의 화면 규격입니다. 재생 로직은 `core/tts.js`, 표시 계산은 `core/speak-model.js`, 버튼은 `views/components/speak-button.js` 가 맡습니다.

- **`.btn-icon`**: 아이콘만 있는 `.btn` 변형. **44×44px 정사각**, 안쪽 여백 0 (REQ-114). 36px 이던 해설 시트 발음 버튼도 이 규격으로 통일했습니다.
- **`.speak-btn`**: `btn btn-ghost btn-icon speak-btn` 조합. 아이콘은 Lucide `volume-2`. 평소에는 보조 글자색(`--muted`).
- **`.speak-btn.is-playing`** (재생 중): 글자색 `--accent`, 배경 `--accent-soft`, 아이콘이 900ms 주기로 1.0↔1.2배 맥동(`speak-pulse`). `prefers-reduced-motion: reduce` 에서는 맥동 없이 색만 바뀝니다. 색은 모두 토큰이라 다크 모드에서 자동으로 따라오며, `tests/dark-theme.test.js` 가 `.speak*` 규칙의 리터럴 색 누락을 검사합니다.
- **접근성**: 버튼은 `aria-pressed`(재생 중이면 `true`)와 이름을 가집니다. 표제어는 "<단어> 발음 듣기", 예문은 "예문 듣기", 세션 헤더는 "단어 읽어 주기".
- **같은 단어의 버튼은 함께 켜진다**: 재생 식별자(`key`)가 같은 버튼만 강조됩니다(`word:<단어>`, `sentence:<단어>`). 세션 헤더와 해설 시트의 표제어 버튼은 같은 key 라 동시에 표시됩니다.

| 위치 | 버튼 | key |
| :--- | :--- | :--- |
| 세션 헤더 | 표제어 | `word:<단어>` |
| 해설 시트 | 표제어 + 예문(있을 때) | `word:<단어>` / `sentence:<단어>` |
| 플래시카드 뒷면 | 예문(있을 때) | `sentence:<단어>` |
| 단어 미리보기 시트 | 행마다 **표제어만** (예문 듣기 없음 — 훑어보는 용도, 2026-11-10) | `word:<단어>` |

- **재생 규칙**: 소리는 버튼 클릭 핸들러 안에서만 냅니다(자동 재생 없음). 표제어 0.9배속, 예문 0.85배속. 연타하면 이전 발음을 끊고 새로 읽으며, 이때 버튼이 꺼졌다 켜지는 깜박임은 없습니다.
- **정지 시점**: 문항 전환, 해설 시트 닫힘(다음), 세션 중단·종료·화면 정리, 단어 시트 닫힘, 라우트 이동(`hashchange`), 탭 숨김(`visibilitychange`)·페이지 이탈(`pagehide`).
- **보이스**: 선택 UI 없음. en-US → en-GB → 그 밖의 en-* 순으로 자동 선택하고, 같은 언어에서는 기기 내장 보이스를 먼저 씁니다.
- **실패 안내**: 브라우저가 재생을 막은 경우, 영어 보이스가 없는 경우, 음성 합성 미지원 브라우저는 토스트로 알립니다. 학습 세션당 최초 1회만, 취소·중단은 알리지 않습니다.

| 사유 | 토스트 문구 |
| :--- | :--- |
| 재생 차단 (`not-allowed`) | 브라우저가 소리 재생을 막았어요. 버튼을 다시 눌러 보세요. |
| 영어 보이스 없음 | 이 기기에는 영어 음성이 없어 발음이 정확하지 않을 수 있어요. |
| 미지원 브라우저 | 이 브라우저는 발음 듣기를 지원하지 않아요. |

### 12.7 세션 효과음과 콤보 뱃지 (v2.2)

REQ-137, REQ-138 의 화면·음향 규격입니다. 합성은 `core/sound.js`, 콤보 계산과 효과음 정책은 `core/combo-model.js`, 뱃지는 `views/components/combo-badge.js` 가 맡습니다.

**효과음 큐 (Web Audio 합성, 외부 파일 없음)**

| 큐 | 언제 | 소리 |
| :--- | :--- | :--- |
| `correct` | 정답 (마일스톤이 아닐 때) | C5(523.25) → E5(659.25) → G5(783.99) 상승 아르페지오. 사인파, 간격 0.07초, 각 0.18초, 음량 0.2 |
| `milestone` | 콤보 5·10·15 에 닿는 정답 | C5 → E5 → G5 → C6(1046.5) 4음 상승. 간격 0.08초, 마지막 C6 은 0.4초에 삼각파를 살짝(음량 0.06) 겹침. **정답음을 대체**하며 둘이 겹치지 않음 |
| `wrong` | **4지선다 퀴즈**의 오답 | 196Hz → 130.8Hz 로 0.25초 동안 지수 하강하는 낮은 사인파 한 음. 최대 음량 0.12, 어택 30ms 로 부드럽게 |
| `complete` | 정상 완주 + 정답 1개 이상 | G4 → C5 → E5 → G5 로 오른 뒤(삼각파, 각 0.14초) C5+E5+G5 화음을 0.6초 유지(음량 각 0.1) |

- **무음인 경우**: 플래시카드 "헷갈려요", 세션 중단, 푼 문항 없음, 전부 틀린 완주, 건너뜀, 음소거 상태. 정책은 `soundCueFor` 한 곳에서 정합니다.
- **마스터 게인 0.6**: 모든 음이 컨텍스트당 하나의 마스터 게인을 거쳐 출력됩니다. 같은 순간 울리는 음량의 합 × 0.6 이 0.9 를 넘지 않도록 테스트가 검사합니다(클리핑 방지). 음의 시작·끝은 0 이 아닌 0.0001 에서 지수로 올라 팝 노이즈를 막고, 음이 끝나면 노드를 해제합니다.
- **자동재생 제한**: 효과음은 사용자가 답을 누르거나 결과를 보는 흐름 안에서만 납니다. 컨텍스트가 정지 상태면 재개하고 첫 제스처에서 다시 깨웁니다. 미지원·생성 실패는 예외 없이 무음입니다.
- **음소거**: 앱 헤더의 `#sound-toggle` 하나가 모든 효과음을 제어합니다(세션 헤더에 중복 배치하지 않음). 아이콘은 `bell-ring`(켬) / `bell-off`(끔)이고, `volume-2` 는 발음(TTS) 전용입니다. 설정은 `voda.sound_muted` 에 저장되며 엔진의 구독으로 어디서 바꿔도 아이콘이 따라옵니다. 발음은 효과음 음소거와 별개입니다.

**콤보 뱃지**

| 항목 | 규격 |
| :--- | :--- |
| 노출 | 콤보 2 이상 (`COMBO_MIN_VISIBLE`). 1 이하이거나 오답·건너뜀으로 끊기면 뱃지만 사라짐 |
| 줄 | `.combo-row` **높이 28px 고정**, 위아래 마진 -6px. 뱃지가 없어도 높이를 차지해 카드가 밀리지 않음 (레이아웃 시프트 없음) |
| 뱃지 | `.combo-badge`: `flame` 아이콘 + "N콤보", 알약형, 배경 `--accent-soft`, 글자 `--accent`, 굵기 700, 글자 크기 `--fs-caption` |
| 마일스톤 | `.combo-badge--milestone` (5·10·15 콤보): 배경 `--btn-primary-bg`, 글자 `--on-accent` 로 주 버튼과 같은 채움 |
| 바운스 | 직전에 그린 콤보보다 **늘어난 렌더에서만** `.is-bounce`. `combo-pop` 320ms, 스케일 0.85 → 1.25 → 1. 세션 화면은 상태가 바뀔 때마다 다시 그려지므로 값 비교 없이는 관련 없는 재렌더에도 튐 |

| 접근성 | 시각 전용(`aria-hidden`). 해설 시트의 `aria-live` "N콤보!" 와 중복 낭독을 막음 |

### 12.8 발음기호 `.phonetic` (v2.2, REQ-144)

DB 에는 슬래시 없는 미국식 IPA 가 저장되고(예: `ˈæpəl`), 화면이 `/ˈæpəl/` 서식을 입힙니다 (`core/phonetic.js` 의 `formatPhonetic`, 요소는 `views/components/phonetic-line.js` 의 `phoneticLine`).

| 항목 | 규격 |
| :--- | :--- |
| 클래스 | `.phonetic` (`css/app.css`) |
| 글자 크기 | `--fs-caption` (13px) |
| 색 | `--muted` — 토큰만 쓰므로 다크 모드가 자동으로 따라온다 (리터럴 색 금지, `dark-theme.test.js`·`phonetic.test.js` 가 검사) |

| 줄바꿈 | `white-space: nowrap` (발음기호 한 덩어리는 쪼개지 않는다) |
| 서체 | `--font-ipa: var(--font-sans), 'Lucida Sans Unicode', sans-serif`. Pretendard 에 없는 IPA 글리프(ˈ ˌ ː ə ɪ ʊ ʃ θ ð ŋ 등)는 Lucida Sans Unicode, 그다음 시스템 sans-serif 로 대체된다 |
| 접근성 | `aria-hidden="true"` 시각 전용. 스크린리더가 IPA 를 어색하게 읽거나 🔊 버튼과 이중 낭독하지 않도록, 발음은 발음 듣기 버튼(REQ-125)이 맡는다. `lang="en-fonipa"` 는 지원이 불균일해 부여하지 않는다 |
