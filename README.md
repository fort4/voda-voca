# 보다보카 (voda-voca)

모바일에 맞춘 웹 기반 영어 단어 학습 서비스입니다. 서비스가 준비한 **표준 단어장**(5종, 1,000단어)을 골라 학습 세션 하나에서 4지선다 퀴즈와 플래시카드로 외우고, 북마크와 틀린 단어를 복습함에서 다시 봅니다.

- **버전**: v2.2 개발 중 (최근 릴리즈 태그 `v2.1.0`), 2026-11-25 DB 를 SQLite 로 전환
- **설계 문서**: [`docs/`](docs/) (개발 방법론 v1.0, 프로젝트 기획서 v0.1, 요구사항 명세 v2.3, 데이터 설계서 v3.0, API 연동 규격서 v2.2, UI/UX 설계서 v2.2, 아키텍처 설계서 v1.1, 결정 기록 v1.1, 테스트 정의서 v1.2)
- **선택한 DB**: **SQLite** (단일 파일, 기본 `/data/voca.db`). PostgreSQL 은 쓰지 않는다
- **작업 환경**: Windows 11 + WSL2 (Ubuntu 24.04), Docker

## 1. 기술 스택

| 계층 | 기술 | 비고 |
| :--- | :--- | :--- |
| 백엔드 | Python 3.12, FastAPI 0.162, SQLAlchemy 2.1 (aiosqlite), Pydantic 2 | 비동기 REST API |
| 마이그레이션 | Alembic 1.20 | 스키마 변경은 마이그레이션으로만 한다 |
| 데이터베이스 | **SQLite** (단일 파일) | WAL, 외래키 강제, 트랜잭션 `BEGIN IMMEDIATE`, 시각은 UTC 저장, 닉네임·표제어는 `NOCASE` |
| 인증 | 세션 쿠키 (HttpOnly, SameSite=Lax), bcrypt | 세션은 DB `sessions` 테이블에 저장 |
| 프론트엔드 | HTML5, Vanilla JavaScript (ES 모듈, JSDoc), **빌드 없음** | 해시 라우팅, `textContent` 기반 렌더링 |
| UI | Tailwind CSS (Play 스크립트, vendor/ 자체 호스팅), SweetAlert2 11.10.5, Lucide 0.460.0, Chart.js 4.6.2 | Zinc 뉴트럴 + Indigo 포인트, 다크 모드 |
| 서체 | Pretendard Variable (본문), Paperlogy Bold (제목·학습 단어) | vendor/ 자체 호스팅, `font-display: swap`, 실패 시 시스템 폰트 |
| 테스트 | pytest 9 (백엔드), `node --test` (프론트엔드) | 외부 프론트 의존성 없음 |

프론트엔드에는 npm 의존성이 없습니다. `package.json`은 테스트 실행 스크립트만 가집니다.

### 2.1 아키텍처와 화면 흐름

- **백엔드**: FastAPI가 `/api` 아래 REST API를 제공하고, 같은 출처로 정적 프론트엔드를 서빙합니다. 인증은 세션 쿠키이며 세션은 DB에 저장합니다. 서버가 시작될 때 표준 단어장 시드를 DB에 반영합니다.
- **단어장**: 서비스가 제공하는 표준 단어장은 일반 사용자에게 **읽기 전용 공용 콘텐츠**입니다. 관리자는 단어장과 단어를 추가하고, 자신이 등록한 것을 수정·삭제합니다. 사용자별로는 활성 단어장, 북마크, 학습 기록, 단어 진행도, 학습 설정만 저장합니다.
- **프론트엔드**: 빌드 없는 ES 모듈입니다. 해시 라우팅(`#/…`)으로 화면을 바꾸고, 화면은 `views/`, DOM 없는 순수 로직은 `core/`에 둡니다.
- **하단 탭 4개**: 홈 · 탐색 · 복습함 · 통계. 학습 세션(`#/study/session`)은 탭이 아니며 세션 중에는 탭바가 숨겨집니다.
- **화면 흐름**: 로그인·가입 → 탐색에서 단어장을 고름 → 홈에서 "N문항 학습 시작" → 학습 세션(퀴즈 또는 플래시카드) → 결과. 복습함에서 북마크·틀린 단어로 같은 세션을 시작합니다.
- **상단바**: 브랜드와 계정 칩이 있습니다. 계정 메뉴에 **마이페이지**, **학습 설정**, **환경 설정**, **로그아웃**이 있습니다. 회원 탈퇴는 마이페이지에 있습니다.

## 3. 실행 방법

### 3.1 준비물
- **컨테이너로 실행**: Docker 와 Git 만 있으면 된다.
- **호스트에서 개발·테스트**: Python 3.12, Node.js (프론트엔드 단위 테스트용, 검증 환경: v26). DB 서버는 필요 없다.
- 브라우저 (Chrome, Edge 등 최신 버전)

### 3.2 환경 변수 설정
```bash
cp .env.example .env
```
`.env` 는 저장소에 커밋하지 않는다 (`.env.example` 만 커밋).

| 변수 | 설명 |
| :--- | :--- |
| `DB_PATH` | SQLite 파일 경로. 로컬 개발 기본 예시는 `./data/voca.db`, 컨테이너는 `/data/voca.db` (상위 폴더가 없으면 만든다) |
| `SECRET_KEY` | 비밀값. 코드에 쓰지 않고 환경 변수로만 넣는다. 컨테이너 compose 는 없으면 시작하지 않는다 |
| `APP_PORT` | 앱 컨테이너가 호스트에 여는 포트 (기본 `8080`) |
| `TZ` | 시간대 (기본 `Asia/Seoul`) |
| `COOKIE_SECURE` | HTTP(로컬·사내망)는 `false`, HTTPS 배포는 `true` |

### 3.3 컨테이너로 실행 (권장)
```bash
# 이미지 빌드 (마지막 스테이지 = 배포용이 기본 대상)
docker build -t voca-app .

# 실행: DB 파일은 이름 있는 볼륨 /data 에 보관된다. 시작할 때 마이그레이션이 자동 적용된다.
docker run -d --name voca -p 8080:8080 -e SECRET_KEY=change-me -v voca-data:/data voca-app
curl http://localhost:8080/health      # {"status":"ok","db":"connected"}
```
또는 compose 로 (프로젝트 루트에서, `.env` 에 `SECRET_KEY` 필요):
```bash
docker compose --project-directory . -f docker/docker-compose.yml up -d --build   # http://localhost:8080
```
- 시작할 때 표준 단어장 시드(1,000단어)를 멱등으로 적재한다. 시작부터 `/health` 200 까지 약 4초다.
- 과제 서버와 같은 조건(UID 10001, 읽기 전용 파일시스템, 권한 제거, 메모리 1GB)에서도 동작한다.

### 3.4 호스트에서 직접 실행 (개발)
```bash
python3 -m venv .venv
```

## 5. 주요 기능

### 5.1 계정 (REQ-001, REQ-002, REQ-121, REQ-122, REQ-159, REQ-164)
- **닉네임과 비밀번호로 가입**합니다. 이메일은 받지 않습니다. 비밀번호를 한 번 더 입력해 확인하고, 닉네임은 "중복 확인" 버튼으로 가입 전에 확인합니다 (REQ-158). 닉네임은 2~30자이며 대소문자와 무관하게 유일합니다. 비밀번호는 8자 이상, UTF-8 기준 72바이트 이하입니다.
- 로그인 실패가 IP 또는 닉네임 기준 1분에 5회 쌓이면 429로 잠시 막습니다 (무차별 대입 방어). 대기 시간은 카운트다운으로 보여 줍니다.
- 로그아웃은 확인 없이 바로 처리합니다. **회원 탈퇴**는 마이페이지에서 시작하며 경고를 확인한 뒤 닉네임을 직접 입력해야 진행되며, 계정과 북마크, 학습 기록, 진행도가 영구 삭제됩니다 (표준 단어장은 공용이라 영향이 없습니다).
- **비밀번호 변경**: 계정 메뉴의 **마이페이지**에서 현재 비밀번호를 확인하고 바꿉니다. 바꾸면 다른 기기의 로그인은 해제됩니다 (REQ-164).
- **관리자 계정**: 닉네임 `admin`, 초기 비밀번호 `admin1234` 입니다. 서버가 처음 시작할 때 만들며, **배포한 뒤에는 바로 로그인해 비밀번호를 바꾸세요.** 바꾼 비밀번호는 재시작해도 유지됩니다. `admin` 닉네임은 가입에 쓸 수 없고 관리자 계정은 탈퇴할 수 없습니다 (REQ-159).
- **관리자의 단어 관리** (REQ-160·161): 탐색에서 "새 단어장"을 만들고, 카드의 "단어 관리"에서 "단어 추가"로 단어를 넣습니다(표준 단어장에도 가능). 관리자가 등록한 단어장·단어만 수정·삭제할 수 있고, 삭제하면 모든 사용자의 관련 학습 이력·북마크도 지워집니다. 같은 단어장의 표제어는 대소문자·악센트를 무시하고 중복될 수 없습니다.
- **CSV 일괄 등록** (REQ-162): "단어 관리"의 "CSV 등록"에서 파일을 고릅니다.
  - 첫 줄은 열 이름입니다. `term`, `meaning` 필수, `example`, `example_meaning` 선택. 쉼표가 들어간 값은 큰따옴표로 감쌉니다.
  - UTF-8(엑셀의 "CSV UTF-8"), 한 번에 500행·512KB 까지입니다. 더 많으면 파일을 나눠 올립니다(2,000개는 4개 이상).
  - 형식 오류가 하나라도 있으면 파일 전체를 등록하지 않고 오류 행 번호를 알려 줍니다.
  - **중복 정책**: 같은 단어장에 이미 있거나 파일 안에서 겹치는 표제어(대소문자·악센트 무시)는 건너뛰고 건수를 알려 줍니다. 기존 단어는 바꾸지 않습니다.
  - 표준 단어장에 올린 단어는 하나씩만 지울 수 있습니다. 시험할 때는 새 단어장을 만들어 올리세요(단어장 삭제로 한 번에 정리).

### 5.2 표준 단어장과 탐색 (REQ-140~142, REQ-145)
- 서비스가 제공하는 단어장 5개, 단어 1,000개입니다. 각 단어에는 표제어, 뜻, 예문, 예문 해석, 발음기호, 품사가 있습니다.

| 단어장 | 카테고리 | 대상 |
| :--- | :--- | :--- |
| 초급 필수 영단어 200 | 초등 | 일상에서 자주 쓰는 기초 어휘 |
| 중급 핵심 영단어 200 | 중고등 | 중학교 수준 핵심 어휘 |
| 고급 심화 영단어 200 | 수능 | 고등학교 이상 심화 어휘 |
| 시험 대비 핵심 200 | 시험 | 시험 대비 핵심 어휘 |
| 실무 비즈니스 영단어 200 | 비즈니스 | 직장 영어 어휘 |

- **탐색** 탭에서 카테고리·레벨 칩으로 거르고, 카드의 [미리보기]로 단어를 훑습니다 (30개씩 "더 보기"). 미리보기의 검색 칸에서 표제어나 뜻의 일부로 단어를 찾고 (REQ-163), 행 오른쪽의 북마크 버튼으로 복습함에 담습니다. [이 단어장으로 학습]을 누르면 그 단어장이 **활성 단어장**이 됩니다.
- 원본은 `src/backend/data/seeds/`의 JSON 파일입니다. 값이 바뀌면 서버가 다시 뜰 때 DB에 반영됩니다.

### 5.3 홈과 학습 세션 (REQ-012, REQ-014~016, REQ-124, REQ-142, REQ-147)
- **홈**은 세션 시작까지 한 번의 탭이 목표입니다. 활성 단어장과 진행률, 오늘의 목표, 퀴즈/플래시카드 토글, "N문항 학습 시작" 버튼이 있습니다. 오늘 학습 수는 고유 단어 기준입니다.
- **일차 진도** (REQ-165): 단어장마다 1일차부터 셉니다. 설정의 오늘의 목표만큼 서로 다른 단어를 풀고(정답·오답 모두), 한국 날짜가 바뀌면 다음 일차가 됩니다. 못 채우면 같은 일차를 이어 갑니다. 홈에 현재 일차, 그 일차의 진행, 암기한 단어 수(연속 3회 정답) / 전체가 보입니다. 업데이트 전에 쌓인 기록에는 일차가 없습니다.
- 한 번에 푸는 문항 수와 오늘의 목표는 **학습 설정**(10·20·30, 기본 10)을 따릅니다.
- **세션 하나에서 퀴즈와 플래시카드를 모두 진행**합니다. 문항마다 서버가 즉시 채점·기록하며, 한 번 고른 답은 바뀌지 않습니다.
- **퀴즈**: 홈에서 **출제 방향**(영→한·한→영·섞기)과 **문제 형식**(4지선다·OX)을 고릅니다 (REQ-157). 영→한은 단어를 보고 뜻을, 한→영은 뜻을 보고 단어를 고릅니다. 답을 고르면 해설 시트가 올라와 정오, 뜻, 예문, 품사와 발음기호를 보여 줍니다. 단어 4개 미만이면 출제할 수 없습니다. 출제 단어는 오답·복습·미학습 배분을 지키면서, 많이 틀렸고 오래 안 본 단어일수록 자주 뽑히는 **가중 무작위**로 고릅니다 (REQ-168).
- **플래시카드**: 앞면에 표제어·품사·발음기호, 뒷면에 뜻·예문을 보여 줍니다. 카드를 눌러 뒤집고 "헷갈려요"/"알아요"로 평가합니다.
- **숙련**: 한 단어를 연속 3번 맞히면 숙련으로 표시하고 기본 출제에서 뺍니다. 한 번 틀리면 숙련이 풀립니다.
- **콤보와 효과음**: 연속 정답이 2 이상이면 콤보 뱃지가 보이고 5·10·15에서 마일스톤 소리가 납니다. 효과음은 Web Audio로 합성하므로 음원 파일이 없습니다.
- **발음 듣기**: 스피커 버튼이 브라우저 음성 합성(Web Speech API)으로 읽습니다. 퀴즈는 답을 고르면 영단어를 자동으로 읽어 줍니다. 지원하지 않으면 한 번만 안내하고 조용히 넘어갑니다.
- **키보드 단축키**: 플래시카드는 Space·Enter 뒤집기, ←/→ 평가. 퀴즈는 숫자 키로 고르고 Enter·Space로 다음 문항. Esc는 세션 중단 확인 모달을 엽니다.
- **세션 중 북마크**: 카드 오른쪽 위 별 버튼으로 북마크합니다. 응답을 기다리지 않고 바로 바뀌고, 실패하면 되돌리고 토스트로 알립니다.

### 5.4 복습함 (REQ-017~019, REQ-129)
- **북마크**와 **틀린 단어** 두 탭이 있고, 각각 20건씩 "더 보기"로 이어 받습니다. 행에는 표제어, 품사, 발음기호, 단어장 이름, 뜻이 보입니다 (예문은 보이지 않습니다).
- **틀린 단어**는 단어별 **마지막 결과가 오답**인 단어입니다. 다시 맞히면 목록에서 빠집니다.
- 해당 목록의 단어가 **4개 이상**이면 [복습 시작]이 켜지고, 그 단어들로 같은 학습 세션(퀴즈 또는 플래시카드)을 시작합니다. 복습은 활성 단어장을 바꾸지 않습니다.

### 5.5 통계 (REQ-131~133, REQ-154, REQ-155)
- 누적 정답률, 연속 학습일(한국 날짜 기준), 전체 단어, 복습할 오답, 최근 7일 학습 단어 수 막대 차트(오늘 강조), 단어장별 숙련도 진행률을 보여 줍니다. 전체 이력 기준이며 서버가 집계합니다.

### 5.6 계정 메뉴, 학습 설정, 환경 설정 (REQ-134, REQ-147, REQ-149)
- 닉네임 칩을 누르면 칩 아래에 메뉴가 뜹니다. 바깥을 누르거나 Esc로 닫습니다.
- **학습 설정**(책 아이콘): 퀴즈 문항 수, 플래시카드 문항 수, 오늘의 목표를 칩으로 고릅니다. 고르는 즉시 서버(`/api/users/me/settings`)에 저장하고 실패하면 되돌립니다.
- **환경 설정**(톱니바퀴 아이콘): 스위치로 **효과음**과 **다크 모드**를 켜고 끕니다. 두 값은 이 브라우저에 저장합니다 (`voda.sound_muted`, `voda.theme`). 다크 모드는 저장값이 없으면 시스템 설정을 따릅니다. 효과음을 끄면 퀴즈 자동 발음도 꺼집니다. 발음 듣기 버튼은 별개입니다.
- 로그인 전에는 계정 메뉴가 없으므로 상단바의 **로그인 링크 왼쪽 달/해 버튼**으로 다크 모드를 켜고 끕니다. 아이콘은 누르면 바뀔 모드를 보여 줍니다(라이트면 달, 다크면 해). 선택은 이 브라우저에 저장되고 로그인 후에도 이어집니다.

### 5.7 추천 학습 흐름
1. 가입하고 **탐색**에서 학습할 단어장을 고릅니다 (미리보기로 단어를 먼저 볼 수 있습니다).
2. **홈**에서 모드(퀴즈 또는 플래시카드)를 고르고 "N문항 학습 시작"을 누릅니다.
3. 퀴즈 해설과 플래시카드 뒷면에서 뜻과 예문, 발음기호를 확인합니다. 스피커 버튼으로 발음을 듣습니다.
4. 기억이 흐린 단어는 카드의 별 버튼으로 **북마크**합니다.
5. **복습함**에서 북마크나 틀린 단어가 4개 이상이면 [복습 시작]으로 다시 풉니다.
6. **통계**에서 정답률, 연속 학습일, 단어장 진행률을 확인합니다.

## 6. API 개요

아래 경로는 모두 `/api` 아래입니다(헬스체크 `GET /health` 만 밖에 있습니다). 자세한 요청·응답은 `docs/설계_261119_API연동규격서 v2.2.md`와 `/docs`(자동 생성)를 봅니다.

| 영역 | 엔드포인트 |
| :--- | :--- |
| 인증 | `POST /auth/signup`, `POST /auth/login`, `POST /auth/logout`, `GET·DELETE /auth/me`, `PUT /auth/me/password`, `GET /auth/check-nickname` |
| 표준 단어장 | `GET /vocabularies`, `GET /vocabularies/{id}/words` (검색 `?q=`), `POST /users/me/active-vocabulary` |

## 7. 보안과 운영 메모
- 세션 쿠키는 JavaScript 에서 읽을 수 없습니다 (HttpOnly). 토큰 원문은 저장하지 않고 SHA-256 값만 DB 에 둡니다.
- 비밀번호는 bcrypt 로 해시합니다. 평문은 저장하지 않습니다.
- 관리자 초기 비밀번호는 공개 저장소에 있는 값입니다 (ADR-011). 바꾸기 전에는 누구나 관리자로 로그인할 수 있습니다.
- 모든 SQL 은 파라미터 바인딩을 씁니다. 외래키 강제(`foreign_keys=ON`)와 쓰기 직렬화(`BEGIN IMMEDIATE`)는 연결 단계에서 설정합니다.
- 북마크, 학습 기록, 진행도, 설정은 사용자별로 격리됩니다.
- 로그인 무차별 대입 방어는 프로세스 메모리에서 동작합니다. 워커를 여러 개 띄우면 한도가 워커마다 따로 적용되므로, 그 경우 공유 저장소가 필요합니다.
- 프론트엔드는 `innerHTML`을 쓰지 않고 `textContent`로만 텍스트를 넣습니다.
- 퀴즈 출제 응답에는 정답과 해설이 없고, 답을 제출한 뒤 채점 응답에서만 공개됩니다 (데이터 설계서 D16). 플래시카드는 정답 개념이 없어 뒷면 정보(뜻·예문)가 출제 응답에 함께 실립니다. 퀴즈의 발음기호는 출제 응답에서 서버가 비웁니다.

## 8. 알려진 제한
- 진행 중인 세션을 다시 조회하는 API 가 없어 새로고침하면 이어갈 수 없습니다. 이미 푼 문항은 문항마다 서버에 기록되어 통계에 남습니다.
- 효과음 설정과 다크 모드 선택은 **브라우저별**로 저장되어 다른 기기와 공유되지 않습니다. 학습 설정(문항 수·목표)은 서버에 저장됩니다.
- 효과음은 브라우저 정책에 따라 첫 사용자 동작 뒤부터 날 수 있습니다. 발음 듣기는 브라우저에 영어 음성이 없으면 동작하지 않습니다.
- 모바일 실제 기기에서의 시각 점검(360px 레이아웃, 다크 모드의 북마크 색, 발음기호 글리프)은 자동 테스트로 확인할 수 없어 수동 점검 대상입니다.
- HTTPS 배포와 워커 다중화 설정은 아직 문서화된 운영 절차가 없습니다. §3.6 의 배포 절차는 **HTTP 로 쓰는 사내망·LAN 전용**입니다. SQLite 는 단일 프로세스·단일 컨테이너를 전제로 하며 워커를 늘리면 쓰기 경합이 생깁니다.
